Obol/libbrlobol Backend Capabilities
====================================

Purpose
-------

This file is the current status and remaining-work guide for retiring both
libbsg and libdm from the GED/qtcad drawing path.  Detailed migration history
and completed bridge-retirement notes live in `backend_worklog.txt`.

The target architecture is:

* Public and cross-library contracts remain neutral: `ged/draw.h`,
  `rt/view.h`, qtcad Obol APIs, and libbrlobol APIs.
* Obol/libbrlobol owns concrete scene, view, source, feature, polygon,
  render/export, framebuffer, and display backend implementation.
* libbsg is removed from the primary GED/qtcad drawing path.
* libdm is removed from the primary qged/qtcad drawing path.  Any remaining
  libdm use is isolated legacy compatibility, not a design input for new
  backend behavior.

Working environment notes:  development frequently happens on FreeBSD - in
those cases we're using clang and lldb.  If you need python on those systems
its currently python3.11

We usually build in a build/ direcotory in the source tree using the ninja
build tool.

Guiding Constraints
-------------------

* Do not expose BSG types, BSG enum names, or BSG ownership rules from new
  public APIs.
* Do not expose Coin/Inventor implementation details through GED or RT public
  APIs unless the API is explicitly libbrlobol-facing.
* Preserve current GED/qtcad behavior first.  Defer broad performance work
  until the migration is structurally complete unless a test exceeds the
  agreed 180 second limit or an obvious catastrophic slowdown is introduced.
* Keep new contracts narrow enough to replace remaining bridge-owned behavior,
  not broad enough to become a second generic scene graph.
* Keep guard coverage aligned with each retired BSG/libdm boundary.
* Any libdm-facing adapter must be disposable glue around a permanent
  Obol/libbrlobol capability.
* Work should focus on the highest priority capability, but need not shy away
  from changes that impact other categories solely to keep work "pure" to one
  category.  The priority is making good progress towards our desired final
  end state.


Implementation Order
--------------------

1. Obol scene/source ownership.
2. View feature and polygon store.
3. Obol render/export record query.
4. Obol display backend draw stream, with temporary libdm compatibility.
5. qtcad/qged final display ownership and dependency-row removal.

The process should not strictly block on category boundaries when a step
naturally crosses them, but the high-level retained scene/source semantics
need to be stable before removing lower-level dependency rows.


Current Status
--------------

Capability 1, scene/source ownership, is the active migration phase.

Current state:

* Obol/qtcad has staged scene, group, source, placement, display-state,
  revision, summary, and draw-sync coverage.
* GED public records and transaction paths increasingly use neutral summaries,
  source-state records, draw-state summaries, source snapshots, and facade
  operations instead of direct BSG field access.
* The current BSG-backed source adapter still owns the transitional retained
  scene implementation, geometry publication, source realization, LoD
  realization, child/source attachment, and remaining scene-ref mutation.
* `src/libged/bsg_ged_draw_private.h` still exposes transitional
  `bsg_scene_ref` handles because live GED internals still need a retained
  scene token while the Obol scene/source owner is incomplete.
* The pivot guard is enforcing staged boundary movement and should be updated
  when a bridge is intentionally retired.
* The focused scene regression and the Obol/qtcad guard group are the main
  fast checks for this phase.

Recent cleanup state:

* Transaction clear/teardown accounting now uses neutral scene-context tree
  summary data instead of a private `rt_view_scene_ref` child-count bridge.
* Scene-context child lookup uses the scene-ref child iterator facade instead
  of a private direct child-index-to-context bridge.
* Scene-context parent lookup remains behind the source-adapter
  parent-context facade; moving raw parent traversal into the refs layer is
  intentionally guarded against.


Capability 1 Remaining Work: Scene And Source Ownership
-------------------------------------------------------

Goal:

Replace retained `bsg_scene_ref` ownership with an Obol/libbrlobol-owned
scene/source model that backs the existing neutral GED draw APIs.

Required behavior:

* Scene root creation, attachment, reattachment, lifecycle, active view scope,
  and independent view scope ownership.
* Group creation, lookup, rename, erase, clear, nested subpath erase,
  child append/remove, traversal, and subtree bounds.
* Shape references with stable identity, parent/group ownership, full path,
  leaf directory, source state, source ref, shape state, and draw context.
* Database source nodes with source revision, input revision, realized
  revision, realization identity, stale flag, stale reason, material policy,
  and source-owned realization status.
* Draw intent ownership: semantic path, draw mode, fallback mode, overlay
  flag, appearance, revalidation, and copy.
* Display attributes: visible, highlighted, selected, transparency, color,
  material revision/color, line style, line width, draw matrix, transform,
  draw center, draw size, bounds, and draw tree depth.
* Structural revision and frame revision accounting.
* Neutral summary exports for GED records:
  `ged_draw_scene_display_summary`,
  `ged_draw_database_source_summary`,
  `ged_draw_scene_tree_summary`,
  `ged_draw_shape_record_summary`,
  `ged_draw_group_record_summary`,
  `ged_draw_scene_draw_state_summary`, and
  `ged_draw_shape_material_summary`.

Near-term work:

* Continue shrinking cross-file `bsg_scene_ref` bridge exposure where callers
  can use summaries, records, source snapshots, child iterators, or
  transaction/source-specific facade operations.
* Keep source ownership, source-state mutation, database-source record
  synchronization, and source realization transitions local to the current
  source adapter until Obol/libbrlobol can own them directly.
* Avoid moving raw retained parent/child traversal into higher-level wrappers;
  use source-adapter facades or neutral summaries instead.
* Keep draw transactions, redraw, material refresh, highlight, erase, bounds,
  source-update, and database-update behavior passing while the backend owner
  is swapped.
* When a bridge is retired, update `misc/CMake/brlobol_pivot_guard.cmake` so
  the guard tracks the new intended boundary instead of stale transitional
  tokens.

Capability 1 acceptance criteria:

* GED root, group, shape, source, and draw-intent code can operate without
  calling BSG scene/source APIs outside the backend adapter boundary.
* Public GED records keep their current fields and semantics.
* Existing draw transaction, redraw, material refresh, highlight, erase,
  bounds, source summary, and database-update tests pass.


Capability 2 Remaining Work: View Feature And Polygon Store
-----------------------------------------------------------

Goal:

Replace the BSG-backed implementation behind neutral `rt_view_*` and
`ged_draw_view_*` feature/polygon APIs.

Required feature behavior:

* Named feature lookup, creation, removal, visibility, color, line width, and
  style.
* Overlay feature ownership and command-result owner callbacks.
* Line, indexed line, point, label, arrow, axes, line-layer, and edit-preview
  feature publication.
* Feature summaries: point/command counts, geometry kind, visible state,
  realized state, local/shared scope, and owner metadata.
* Selection store: selected path add/set/clear/contains/count and pick-result
  application.
* Edit-preview callbacks and pick/update lifecycle.

Required polygon behavior:

* Polygon create, select, find, duplicate, update, update screen point, move,
  rename, remove, and user-data association.
* Neutral polygon record visit/readback.
* Current/open/closed contour state, selected point state, visual style, edge
  color, fill state, fill color, fill slope, CSG, sketch import/export,
  snap count, snap exclusion, and point-selection clear.

Acceptance criteria:

* `src/librt/view_legacy_bsg.c` feature/polygon implementation is replaced or
  reduced to a compatibility adapter.
* `src/libged/bsg_ged_draw_view.c` no longer owns the primary feature/polygon
  backend.
* qtcad and qged polygon/edit/selection paths continue using neutral RT/GED
  APIs without reintroducing qtcad public legacy-view helpers.


Capability 3 Remaining Work: Render And Export Record Query
-----------------------------------------------------------

Goal:

Replace BSG export and backend-scene record queries with Obol/libbrlobol
queries that emit neutral records GED already exposes.

Current state:

* Obol export action can emit staged object records with stable ordering,
  identity, filtering, geometry detail summaries, and source-backed
  full-detail request metadata.
* GED view-record wrappers call a neutral backend-adapter producer.
* The temporary BSG export producer still exists in the BSG-backed source
  adapter pending Obol query hookup.

Remaining work:

* Connect GED record APIs to the Obol query path.
* Add any missing annotation, segment, line, point, and surface iterator
  parity.
* Replace the temporary BSG-backed export producer in
  `src/libged/bsg_ged_draw_source.c`.
* Preserve render/export consistency summaries, LoD/full-detail request
  reporting, and deterministic guard-test ordering.

Acceptance criteria:

* `src/libged/bsg_ged_draw_records.c` no longer needs BSG export/render or
  backend-scene APIs.
* GED draw-scene, view-command, qged swrast, export, pick, snap, measure, and
  qtcad Obol workflow tests preserve current behavior.


Capability 4 Remaining Work: Obol Display Backend Draw Stream
-------------------------------------------------------------

Goal:

Implement the permanent Obol/libbrlobol display draw stream.  During migration,
this stream may feed temporary libdm compatibility paths so libdm can first
drop its direct BSG dependency, then leave the primary qged/qtcad display path.

Required behavior:

* Ordered draw items for scene, HUD, overlay, annotation, framebuffer, and
  geometry passes.
* Geometry item kinds for lines, indexed lines, points, indexed face sets,
  meshes, labels/text, annotations, images, overlays, HUD widgets, CSG/BREP
  proxies, and edit previews.
* Per-item visibility, role, source scope, material/color, alpha, line
  width/style, transform, coordinate space, draw center, bounds,
  selected/highlighted state, and owner/cache identity.
* Batch lifecycle: request creation, collection, dispatch, payload preparation,
  payload freeing, invalidation, begin/end request, sorted-alpha pass,
  visible-only pass, and HUD pass.
* HUD/faceplate support for axes, grid, ADC, center dot, scale overlay,
  params, labels, interactive rectangle, and other RT view records.
* Framebuffer/image items with viewport, cursor, layer, and image-source
  synchronization.

Acceptance criteria:

* `src/libdm/view.c` no longer includes BSG headers or calls BSG render APIs.
* `libdm` can drop its direct `libbsg` dependency row.
* The same draw stream is usable directly by Obol/qtcad without routing
  through libdm.
* DM backend draw-item tests and qged swrast smoke tests continue to pass.


Capability 5 Remaining Work: qtcad And WindowHost Display Ownership
-------------------------------------------------------------------

Goal:

Make qtcad/qged display ownership primarily Obol/libbrlobol-owned instead of
retained DM/BSG-owned.

Required behavior:

* `BRLObolViewController` owns visible scene root, camera/view state, viewport
  size, render requests, LoD service integration, and result consumption.
* `BRLObolWindowHost` owns framebuffer attachment, image source, viewport
  image nodes, flush/reset/viewport/cursor operations, and render requests.
* qtcad draw synchronization updates Obol scene/source state directly from
  neutral GED draw notifications and transactions.
* qtcad selection, overlay, database-source sync, edit-preview publication,
  snap, pick, measure, export, and real-model workflows use Obol/libbrlobol
  data as the primary display path.
* qged can launch and render its normal Obol/qtcad display path without a
  direct `dm_plugins` build dependency.

Acceptance criteria:

* qtcad visible Obol rendering reaches parity for guarded real-model and qged
  swrast workflows.
* qtcad no longer needs retained DM/framebuffer ownership for its normal Obol
  display path.
* `qged` direct `dm_plugins` dependency can be retired safely.


Dependency Retirement Gates
---------------------------

`libged` direct `libbsg` dependency can be removed after:

* GED retained scene/source/root/scope operations are backed by Obol or a
  neutral owner.
* GED feature/polygon and export/render record queries no longer require BSG.
* Public BSG-shaped GED snap/scene-ref shims are removed or reduced to
  non-linking compatibility wrappers.

`libdm` direct `libbsg` dependency can be removed after:

* DM draw dispatch, while it still exists, uses the neutral Obol/libbrlobol
  draw stream instead of BSG render-item APIs.
* HUD, overlay, annotation, framebuffer, and scene draw tests pass without BSG
  render-item APIs.

`libdm` can be removed from the primary drawing path after:

* qtcad/qged visible rendering uses Obol/libbrlobol directly.
* Remaining compatibility renderers are explicitly isolated as legacy
  consumers.
* No primary qged/qtcad runtime path depends on libdm backend plugins.

`qged` direct `dm_plugins` dependency can be removed after:

* qtcad/Obol owns normal display backend selection and runtime rendering.
* qged no longer depends on build-time DM plugin availability for its primary
  Obol display path.


Guard And Test Gates
--------------------

Fast guard set for current scene/source work:

* `ninja -C build libged ged_test_ged_draw_scene`
* `ctest --test-dir build -R '^ged_test_ged_draw_scene$' --timeout 180 --output-on-failure`
* `ctest --test-dir build -R '^(brlobol_pivot_guard|ged_test_ged_draw_scene|test_qtcad_obol_draw_sync|libbrlobol_lod_update_action|test_qtcad_obol_export|test_qtcad_obol_overlay_sync)$' --timeout 180 --output-on-failure`

Broader coverage should scale with the touched capability:

* Scene/source: shape/group/source records, draw transactions, erase/redraw,
  material refresh, stale state, source summaries, and database-update tests.
* Feature/polygon: qged polygon create/modify, selection, edit-preview,
  feature summaries, and snap exclusion.
* Render/export records: GED draw-scene, view-command, visible DB-object
  records, annotation/line/surface iterators, and qged swrast.
* Display stream: DM backend draw-item tests, faceplate/HUD tests, qged
  swrast, and selected real-model qtcad workflows.
* qtcad ownership: qtcad Obol draw, pick, snap, measure, export, real-model
  havoc/stress tests, and qged smoke tests.


Non-Goals
---------

* Do not build a one-for-one public BSG compatibility layer in Obol.
* Do not build permanent libdm-only features.
* Do not make GED public APIs depend on Coin/Inventor node classes.
* Do not retire dependency rows before the corresponding backend capability
  exists and is tested.
* Do not optimize broad performance behavior before the replacement path is
  structurally complete, except for clear regressions or tests exceeding the
  agreed 180 second limit.
