Target Architecture
-------------------

Obol/libbrlobol is the canonical scene, view, interaction, display, and
framebuffer presentation stack for migrated interactive workflows.  Legacy BSG
and libdm code may remain compiled during transition, but they should not mask
missing Obol behavior or define new semantics.

libbv owns common non-scene view mechanics: camera state, matrices, autoview
bounds math, screen/model transforms, input/knob state, and view-set
bookkeeping.  It must not own scene objects, display lists, polygon stores,
snap/selection state, LoD caches, or retained scene graph behavior.

libbrlobol owns the retained Obol scene graph: database sources, source-local
geometry, per-instance placement and identity, view-aware LoD payloads,
metadata/material/color-table resolution, draw proxy/cache ownership, mesh POP
LoD, command visuals, and framebuffer stream scene presentation.

librt supplies geometry evaluation/query services such as evaluated wireframe
generation.  It should not own interactive draw-cache policy or application
scene state.

Core Invariants
---------------

* Database source geometry is source-local.  Placement comes from explicit
  instance transforms, not baked point coordinates.
* Reused geometry must stay reusable.  Multiple comb instances may point to
  the same source geometry while preserving per-instance identity.
* Visible leaf/source instances own path identity, material/region state,
  selection, visibility, highlight, edit intent, and export metadata.
* View LoD is view-specific.  Multiple views may show different LoD for the
  same shared source while database edits, selection, picking, and erasure
  remain semantically identical.
* Active display LoD is bound through the traversing view state, not by
  mutating shared source nodes.
* Persistent draw cache data lives under `BU_DIR_CACHE/.DbDrawCache`.
* Legacy BSG mesh LoD is quarantined under `.BsgMeshLodCache` until deleted.
* AABB/OBB proxies are leaf-solid geometry only.  Comb bounds are bottom-up
  aggregates of transformed leaf facts.
* Command-generated visuals are Obol scene objects.  They are shared by
  default unless the command explicitly requests view-local scope.
* Effective BRL-CAD material and color-table lookup belongs in libbrlobol.
  GED owns revision bookkeeping and requests refreshes.
* Draw-facing `rt_db_internal` interpretation belongs in libbrlobol database
  sources.  GED may load/select objects, but primitive publication is a
  libbrlobol responsibility.
* No-owned-scene or missing-feature-store cases should return explicit
  no-op/empty results, not recreate retained BSG fallback state.

Current Baseline
----------------

* Normal database draw/erase/redraw flows use Obol/libbrlobol providers rather
  than `_ged_drawtrees` retained BSG ownership.
* Draw transactions no longer keep parallel retained BSG scene ownership.
* View features, annotations, polygons, database-source records, material
  refresh, and primitive wireframe publication have Obol/libbrlobol paths.
* Command-scene coverage includes rtcheck, NIRT/qray, check overlap, GQA,
  BREP/NMG diagnostics, overlay uplot import, `vdraw send`, preview eye paths,
  and simple visualizations.
* qtcad ordinary painting is Obol-only.  qged framebuffer service traffic uses
  a libbrlobol image stream bridge.  GSH and MGED have Obol attach/screengrab,
  progressive-LoD, and ERT smoke coverage.
* `dm-obol` is the headless Obol display plugin.  Immediate-mode callbacks are
  no-ops; high-level GED draw transactions are expected.
* Progressive LoD tests cover qtcad startup, explicit expand, automatic
  expand, Generic_Twin startup/expand, wire LoD, shaded BoT LoD, and
  GSH/MGED attached-view image progression.
* Compact CAD source-local assembly and view-LoD CAD payloads exist.  Root
  aggregation was not kept because current benchmarks did not justify the
  added complexity.
* Evaluated wireframe defaults to the boolweave-backed librt path.  The old
  BigE-style method remains only as a comparison option.

Known Risks
-----------

* Some neutral RT view wrappers still live in `src/librt/view_legacy_bsg.c`
  and need to move to a non-legacy source file.
* Display stream and fbserv wire-protocol ownership is still transitional in
  libdm.  The long-term home should be a small image/framebuffer protocol
  layer beside libimgstream/libicv.
* MGED/TclCAD and older application hosts still need more Obol-native view,
  input, faceplate, readback, and refresh cleanup.
* Compact CAD records still need tighter promote/demote and off-scene handle
  APIs before they are a fully stable extension point.
* Progressive large-root behavior still needs stronger handling for
  duplicate-occurrence proxy/frontier expansion, non-union CSG children,
  pending-autoview scheduling/cancellation, and avoiding whole-root
  synchronous full-detail promotion.
* Evaluated wireframe still has open performance/candidate-generation work for
  very thin shell models such as `havoc.g`.
* Slow ERT streaming still needs a deterministic intermediate-frame image
  gate.

Next Steps
----------

1. Split neutral RT view-context wrappers out of
   `src/librt/view_legacy_bsg.c`.  Keep explicit `_bsg` APIs quarantined in
   the legacy file and isolate remaining test-only BSG context use.
2. Retire remaining application-host legacy dependencies: MGED/TclCAD/GSH raw
   dm refresh, faceplate/input/readback, fbserv hookup, and `dm_plugins`
   assumptions.  Obol/libbrlobol/libbv should own the modern behavior.
3. Move fbserv protocol ownership out of libdm after qged/GSH/MGED ERT paths
   are stable.  Preserve Auth/TLS and make the destination an image/framebuffer
   stream protocol layer, not libbrlobol scene code.
4. Finish residual command/import/readback/no-owned-scene/no-feature-store
   edge cases and tests.  Command-scene and overlay routing are mostly
   migrated; the remaining work is coverage and cleanup, not a second drawing
   path.
5. Complete progressive large-root policy gaps: duplicate-occurrence
   proxy/frontier identity, CSG-aware non-union children, automatic
   pending-autoview settlement/cancellation, and no whole-root synchronous
   full-detail promotion on startup refinement.
6. Harden compact CAD records, explicit promote/demote APIs, publication
   batching, and tree-walk/path-state cost.  Do not reintroduce root/group
   CAD aggregation without fresh benchmark evidence.
7. Continue evaluated-wire follow-up: redesign thin-shell/havoc candidate
   generation, add deterministic parallel ray/classification work with
   per-thread resources, and keep boolweave as the default evaluator.
8. Convert GED basic/LoD image baselines to verified Obol outputs and reduce
   remaining DM/swrast baseline assumptions.
9. Remove libbsg mesh payload/LoD internals and remaining libbsg tests once
   retained BSG rendering no longer needs them.
10. Add deterministic slow-stream ERT tests that verify intermediate
    framebuffer updates as well as final output.
