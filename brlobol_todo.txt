BRL-CAD Obol Drawing: Remaining Work
====================================

Purpose
-------

This is the active backlog for completing the Obol/libbrlobol drawing
migration.  It records only unresolved BRL-CAD feature-parity work, important
scalability or lifecycle limitations, and release gates.  Completed work
belongs in source history and tests; detailed coverage inventories belong in
`doc/notes/`; performance captures belong in `.build_perf/`.

Scope
-----

Feature parity means preserving the drawing, interaction, editing, capture,
framebuffer, and application workflows that supported BRL-CAD programs expose
today.  It does not require adding rendering features that current BRL-CAD
does not expose.

The following are deliberately not migration blockers:

* translating librt/liboptical material shaders or textures into OpenGL scene
  materials;
* stereo rendering until a supported application and native host request and
  validate a stereo-capable surface;
* replacing correct VList fallbacks with native Obol curve, point, text, or
  surface nodes solely for representational purity;
* adding shaded tessellation for primitives whose current librt tessellator is
  itself unimplemented, provided existing wire behavior and diagnostics remain
  available; and
* restoring the historical rtwizard GUI unless it again becomes a supported
  application.  The current `rtwizard` command and Archer-hosted view remain in
  scope.

Architecture Invariants
-----------------------

* Obol is the only graphical scene and rendering path.  Do not add a libdm,
  libbsg, OGL/WGL, or application-local scene fallback.
* Each hosted GED view has one GED view context, display endpoint, Obol
  controller, and factory-owned native host.  Applications own windows and
  event loops, not parallel renderers or scene lifetimes.
* libbrlobol owns BRL-CAD realization, retained drawing, picking, selection,
  edit previews, compact occurrences, view-local LoD, and retained interactive
  rendering.  libbv remains passive view state.
* Qt and Tk hosts own native widgets, contexts, and presentation only.  The
  endpoint/host contract owns lifecycle, resize/DPI propagation, engine policy,
  capture, framebuffer composition, progressive presentation, and shutdown.
* The endpoint property registry is the sole production renderer-policy
  surface.  Explicit engine or property requests fail when unsupported rather
  than silently selecting another behavior.
* Application-specific input action tokens remain application-owned.  The
  endpoint normalizes and routes events but does not acquire MGED/QGED policy.
* Remove a compatibility adapter when its final caller moves, updating the
  caller inventory and regression in the same change.

Verified Baseline
-----------------

* QGED, MGED, TclCAD/Archer, GSH, standalone `rt`, and `fbserv` use the shared
  endpoint/host-factory and Obol/imgstream model.  The locally testable hosted
  ownership matrix has no unclassified graphical owner.
* Normal wireframe and shaded drawing, hidden-line and evaluated draw modes,
  faceplates, work grids, ADC, annotations, selection, picking, snapping,
  measurement, export, and edit previews have Obol representations and focused
  regression coverage.  Known primitive/mode exceptions and their current
  librt support status are recorded in
  `doc/notes/obol_realization_coverage.txt`.
* Common QGED selection and MGED view/edit/ADC/constraint gestures use typed
  endpoint routing with application-owned policy and cancellation.  Native
  bindings for migrated gestures are suppressed to prevent duplicate actions.
* Deferred realization is bounded and cancellable in local stress tests.
  Camera-only changes avoid source realization, stale generations do not
  publish, and ready final data may replace a proxy before first draw.
* `auto`, `hw`, `sw`, `rt`, `none`, and `diagnostic` have explicit capability
  and fallback rules.  FAST and QUALITY are software-wire policies, not
  renderer names.
* Framebuffer storage and protocol state are owned by imgstream.  Endpoint
  rehosting, composition rollback, RT/framebuffer ordering, capture, local
  TCP/IPC operation, and authenticated TLS remote access have local coverage.
* The retained RT engine separates geometry from presentation revisions,
  renders on workers, supports cancellation and progressive rows, and presents
  depth/source identity through the same endpoint composition model.
* BRL-CAD pins published BEXT upstream commit
  `374a5d4b72ba7d20c8a63d76a545d4c41afc09ed`; dependency synchronization is
  enabled and the refreshed staged dependency build supports the Obol targets.

Priority 0: Existing Feature Parity
-----------------------------------

1. Complete the native application and host matrix.

   Run supported QGED, MGED, TclCAD/Archer, GSH, the current `rtwizard`
   command, `rt`, and `fbserv` workflows on native X11, Windows, and macOS
   hosts.  Cover every toolkit/engine combination actually shipped on that
   platform, including simultaneous views, resize/DPI, active-view changes,
   host replacement, system-GL context ownership, OSMesa presentation,
   capture, ERT, framebuffer detach/reattach, database replacement, and close
   while rendering or delivering callbacks.  Run the TCP/IPC/TLS lifecycle
   and pinned-handshake cases on each platform that ships those transports.

   The known gaps are native Windows Tk/WGL worker delivery and defining and
   validating a supported macOS Tk host.  Xvfb is useful Linux coverage but is
   not evidence for either native platform.

   Exit condition: the supported-platform matrix is recorded with runnable
   tests; close drains callbacks before endpoint and stream release; failed
   replacement is transactional; and endpoints cannot exchange native host,
   input, framebuffer, or capture state.

2. Complete command-result and diagnostic interaction semantics.

   Finish command-specific feature and per-primitive metadata schemas for
   rtcheck/check overlap results, NIRT segments and hits, and GQA severities.
   Route application detail panels through neutral GED readback APIs rather
   than libbrlobol-private records.  Preserve owner/generation replacement,
   pick identity, primitive selection/highlighting, and declared snap/measure/
   export behavior.

   Audit remaining old-style drawing callbacks and move supported interactive
   producers to command-scene features.  Newly asynchronous producers require
   generation tokens so stale output cannot replace a newer command run.

   Exit condition: supported diagnostic results are retained scene objects
   with stable lifecycle and identity, not display-only lines or a parallel
   legacy overlay; QGED and Tcl consumers obtain the same neutral metadata.

3. Finish live edit and feature-identity parity.

   Exercise complete primitive and object edit lifecycles in supported MGED,
   QGED, and Archer workflows: begin, motion, snapping, preview replacement,
   accept/reject, selection changes, database mutation, cancellation on
   modifier release/focus loss, and teardown during an active edit.

   Define stable face/edge/vertex identities for tessellated curved primitives
   wherever an existing tool exposes sub-object interaction.  Identity must
   survive realization reuse and LoD transitions or explicitly force the exact
   full-detail representation while editing.

   Exit condition: each supported edit gesture executes once through the
   endpoint/application contract, publishes one authoritative preview, and
   returns stable typed pick/snap identity without a legacy scene query.

4. Close the final graphical producer inventory edge.

   Runtime-validate ART tile publication in an Appleseed-enabled build.  Re-run
   the production inventory for ART/ADRT, remrt/rtsrv, RT-family tools,
   framebuffer utilities, and image commands after any related change.

   Exit condition: each supported graphical producer publishes through Obol or
   imgstream, or fails explicitly when no provider exists; none opens a legacy
   graphical backend, private scene, or application-owned framebuffer.

Priority 1: Key Scalability and Robustness Limits
-------------------------------------------------

5. Stress deferred realization and LoD on production-scale scenes.

   Extend the current cancellation/queue tests to substantially larger models
   and native hosted view replacement.  Stress camera churn, edits, erase,
   source revision changes, database replacement/close, endpoint teardown, and
   repeated proxy-to-final transitions while measuring queue depth, owner-thread
   work, cache growth, peak memory, and time to useful pixels.

   Workers must not touch attached Coin, GED, or toolkit state.  Stale results
   and cancelled cache writes must never publish.  Autoview may follow dynamic
   bounds only until they stabilize or the user changes the camera.

   Exit condition: useful pixels precede outstanding full detail, camera-only
   frames avoid source work, queues and memory remain bounded, and final scene
   identity is correct after sustained churn and teardown.

6. Make evaluated-wire drawing practical for thin-shell large models.

   Preserve the symbolic boolweave semantics and deterministic region order of
   draw mode 3 while redesigning candidate generation and ray/classification
   work for thin-shell cases such as `havoc.g havoc`.  Parallelize queued ray
   jobs with per-thread librt resources and deterministic merge rather than
   changing visible region ordering or restoring historical Big-E as the
   default.

   Compare representative subtraction-heavy results against current BRL-CAD
   behavior and retain the diagnostic comparison harness until correctness and
   scalability are both established.

   Exit condition: evaluated wire is correct and interactively usable on
   Generic Twin, Havoc, and a larger production model without unbounded
   candidate memory or nondeterministic output.

7. Improve normal wireframe and shaded whole-path performance.

   Measure cold draw, first useful pixels, settled rotation/zoom, selection,
   lighting, source updates, traversal, submission, raster/readback,
   presentation, and peak memory for Havoc, Generic Twin, and a larger model.
   Compare native system GL with FAST and QUALITY OSMesa wire policies.

   Prioritize retained buffers, batching/instancing, source deltas, frustum and
   subpixel work, and measured realization/import overhead.  Do not restore
   per-occurrence Coin carriers, synchronous per-part LoD, mutable shared scene
   state, or GED redraw layers for a benchmark-only gain.

   Exit condition: whole-workflow gains preserve deterministic output, colors,
   transparency, lighting, interaction correctness, small-model latency, and
   bounded memory.

8. Validate retained RT as an interactive production engine.

   Exercise live QGED and native hosted MGED camera interaction, cancellation,
   preview/final cadence, source edits, clipping, output planes, capture, and
   framebuffer/background/faceplate composition.  Unchanged geometry must stay
   retained across camera and presentation changes, and stale frames must never
   be presented after a view change.

   Do not expand this item into OpenGL material-shader preview or broad
   liboptical shader emulation.  Raytrace shader/texture behavior remains owned
   by the raytrace stack.

   Exit condition: supported applications can use the time-budgeted RT engine
   interactively with bounded cancellation latency, deterministic final output,
   stable geometry retention, and the same endpoint lifecycle as HW and SW.

Release Gates
-------------

* Reconfigure and build a clean tree using a freshly cloned copy of the pinned
  BEXT commit.  No dependency may require a developer-local source path or a
  stale staged package.
* Build a clean headless configuration.  `rt` and `fbserv` must not acquire UI
  library linkage; `/dev/null` must render without presentation; visible
  targets must explicitly reject missing providers.
* Re-run the hosted ownership matrix, realization coverage table, legacy
  producer inventory, and pivot guard after compatibility deletions.  Remove
  stale transitional labels once no corresponding compatibility mode exists.
* A skipped native display, network, TLS, or large-model test is not a product
  pass.  Record the missing environment and run it on the release platform.

Verification Gates
------------------

Run focused checks before the broad application matrix:

* `ninja -C .build test_brlobol_prototype test_brlobol_window_host`
* `ctest --test-dir .build --output-on-failure -R '^libbrlobol_'`
* `ctest --test-dir .build --output-on-failure -R '^imgstream_fbserv_'`
* `ctest --test-dir .build --output-on-failure -R '^(rt_null_sink|(rt|fbserv)_display_)'`
* `ctest --test-dir .build --output-on-failure -R '^(ged_test_obol_draw_sync|ged_test_mged_view_state|ged_test_mged_shaded_mode|ged_test_drawing_basic)$'`
* `ctest --test-dir .build --output-on-failure -R '^(tclcad_test_(tkobol_widget_smoke|archer_obol_smoke)|test_qged_obol_fbserv|regress-qged-ert|gsh_obol_(smoke|ert_smoke|progressive_lod)|mged_obol_(smoke|ert_smoke|progressive_lod))$'`
* `ctest --test-dir .build --output-on-failure -R '^test_qtcad_obol_'`

Run TCP/IPC/TLS tests outside a network-restricted sandbox.  Slow LoD and
large-model tests are opt-in or resource-gated; record their hardware and
memory requirements.  Store performance captures in `.build_perf/` rather
than treating them as routine correctness artifacts.

Completion Standard
-------------------

The migration is complete when every supported hosted view uses one Obol
scene/endpoint model; current BRL-CAD drawing modes, interaction, editing,
diagnostic results, capture, ERT, and framebuffer streaming require neither a
legacy scene nor graphical backend; explicit HW, SW, and RT engines share one
lifecycle and policy model; production-scale interaction remains bounded; and
the supported native application/platform matrix passes without hidden
fallbacks.
