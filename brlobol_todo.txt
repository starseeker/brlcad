BRL-CAD Obol Drawing TODO
=========================

Last verified: 2026-07-11
Branch: brlobol

Purpose
-------

This is the top-level work list for completing the Obol/libbrlobol drawing
migration.  Durable design contracts and detailed investigations belong in
`doc/notes/`; this file records current architecture, remaining work, exit
conditions, and verification gates.

The status below was checked against the current sources, dependency rows,
and registered tests.  libbsg and the parallel BSG drawing implementation are
retired; neutral GED handles route supported drawing to Obol or report missing
ownership explicitly.

Target Architecture
-------------------

* libbv owns scene-independent view mechanics only: passive camera/view
  state, matrices, transforms, autoview math, input/knob bookkeeping,
  passive faceplate/snap records, view sets, and generic view-quality policy.
* libbrlobol owns the retained interactive scene: database sources,
  source-local geometry, instances, materials, per-view realized LoD,
  command/view features, selection/pick/snap/measure realization, edit
  previews, and framebuffer image presentation.
* librt supplies geometry evaluation and queries.  It must not own
  interactive scene state, draw-cache policy, or application display state.
* libimgstream owns image streams and the framebuffer protocol contract.
  Toolkit-specific event-loop adapters may live in their application hosts,
  but packet semantics and backend dispatch must not remain owned by libdm.
* GED owns command policy, database revision bookkeeping, neutral scene/view
  handles, and transactions.  Supported migrated drawing must use Obol or
  fail explicitly; missing ownership must not silently recreate a BSG scene.
* libdm is a transitional compatibility layer.  libbsg is retired and must
  not be reintroduced.

Non-Negotiable Invariants
-------------------------

* Geometry is source-local; instance transforms provide placement.
* Reused source geometry retains per-instance path identity, material,
  visibility, selection, highlight, edit intent, and export metadata.
* Realized LoD is view-local.  Shared sources must not be mutated to change
  one view's LoD.
* Leaf proxies represent leaf solids.  Combination bounds are bottom-up
  aggregates of transformed leaf facts.
* The active persistent cache is `BU_DIR_CACHE/.DbDrawCache`, owned by
  libbrlobol.  The former `.BsgMeshLodCache` path is deleted.
* Command visuals and faceplate/grid content are Obol scene objects.  Grid
  snap remains semantic model-space state even when grid lines are hidden.
* Effective material/color-table resolution and draw-facing
  `rt_db_internal` interpretation belong in libbrlobol database sources.
* No-owned-scene and missing-feature-store behavior is explicit error,
  empty, or no-op behavior as appropriate, never an implicit BSG fallback.

Verified Current State
----------------------

Working Obol paths:

* Database draw/erase/redraw, view features, annotations, polygons,
  materials, source publication, selection, pick, snap, measure, faceplate,
  grid, and command visuals have Obol/libbrlobol implementations.
* qtcad painting and qged's visible canvas use Obol.  qged does not depend on
  the `dm_plugins` build target.
* `dm-obol` provides headless attachment.  libtclcad owns and registers the
  built-in vendored-Togl `tkobol` Tk widget; it is not a DM plugin.
  The widget owns its Obol controller, uses a real Obol context manager,
  renders directly in Togl's current context, and supports both standalone
  top-level and explicit `-t 0` embedded operation.
* MGED and GSH have Obol attach, screengrab, ERT, and progressive-LoD smoke
  tests.  qged has an embedded framebuffer/ERT regression test.
* Obol viewport readback is centralized through the view controller and GED
  bridge.  TclCAD exporters prefer it for Obol-backed views.
* The active mesh POP LoD and draw cache are libbrlobol-owned.  Evaluated
  wireframe defaults to the boolweave-backed librt implementation.
* Edit previews from qged and classic MGED publish transient Obol features.
* Drawing baselines capture Obol output and use SSIM-based approximate image
  comparison.  Basic, faceplate, LoD, selection, and quad coverage is active.
* libbv is free of direct scene, libbsg, libdm, and database ownership.
* Shared qged/qtcad views render the authoritative GED Obol scene through a
  view-local attachment.  They do not duplicate database sources into a
  second Qt-owned scene; only independent views own scoped local geometry.
* Progressive LoD substitutions take precedence over retained compiled CAD
  assemblies.  Compact source-level payloads preserve aggregate batching for
  unaffected sources, while multi-instance deferred roots retain per-mesh
  scheduling granularity.

Important retained dependencies:

* libged, libqtcad, qged, and GSH are directly libdm-free.  Display-manager
  commands are isolated in GED plugins.  libtclcad still links libdm for its
  generic Tcl DM and legacy framebuffer-object compatibility surface, not for
  Tk drawing or widget ownership.
* libimgstream owns the complete fbserv protocol core: authentication, TLS,
  state, message handling, client lifecycle, bounded processing, backend
  dispatch, and cleanup.  Qt and Tcl retain only toolkit event-loop adapters.
  libdm retains a narrow `struct fb` backend adapter.
* Retained BSG rendering and the OGL/WGL/X/QtGL/swrast/tkswrast graphical
  display and framebuffer paths are deleted.
* librt primitive callbacks use `bv_view_info` and libbv LoD policy directly;
  the former `rt_view_info`/`rt_view_lod_policy` aliases and wrappers are gone.
* The pivot guard has one canonical scan scope.  It rejects libbsg, retired
  graphical DMs, duplicated fbserv protocol ownership, qged/GSH libdm
  dependencies, external Tk widget ownership, and DM-backed native drawing
  tests.

Priority 1: Complete Progressive Large-Model Behavior
-----------------------------------------------------

7. Completed: close progressive LoD policy gaps.

   * Occurrence-aware source keys, parent/child records, occurrence ordinals,
     Boolean operations, and leaf transforms preserve duplicate and non-union
     CSG identity through exact proxy publication and frontier expansion.
   * Deferred startup publishes root/cache metadata without synchronously
     realizing the whole tree.  A prioritized, bounded frontier expands in
     stages while independent asynchronous proxy refinement proceeds.
   * Deferred autoview is revision-owned: refinement can settle it, while
     camera changes, database invalidation, view replacement, and teardown
     cancel stale work.
   * LoD requests and results have generation cancellation, queue and result
     limits, cache-write limits, and reservation-based backpressure.
   * Shared-view endpoint reaffirmation repairs stale shared-root bindings
     without rebuilding already-correct render roots.  Qt draw and selection
     synchronization enumerate the actual rendered scene rather than assuming
     controller-local source ownership.
   * Compiled per-source CAD assemblies and the aggregate CAD render batch
     honor active view-local LoD payloads.  Compact CAD proxy/mesh payloads
     participate in the same active-payload counts as explicit mesh records.
   * Unlimited visible-frontier expansion now continues until no pass makes
     progress.  The former inverted stop condition expanded only the first
     combination level and could never publish leaf proxies.
   * Compact, single-instance sources retain source-level asynchronous LoD.
     View-dependent compact sources containing multiple instances demote after
     realization so current scheduling still exposes independent mesh
     candidates instead of one oversized root task.

   Exit condition: focused tests cover duplicate instances, subtraction and
   intersection trees, cancellation, multi-view independent LoD, startup
   without whole-root synchronous promotion, real AABB/OBB/mesh image
   transitions, compact payload accounting, and proxy-first frontier
   expansion through leaf depth.

   Linux verification: `libbrlobol_lod_realization`,
   `libbrlobol_lod_service`, `libbrlobol_lod_update_action`,
   `ged_test_obol_draw_sync`, and the qtcad progressive-LoD matrix, including
   startup-only, refine, explicit and automatic expansion, wire, shaded,
   backpressure, repeated Moss, and Generic Twin cases.

8. Completed: harden compact CAD source records.

   * Compact records expose stable handles derived from source lifetime and
     Obol instance identity, with query, summary, validation, promotion, and
     demotion APIs that remain valid while records are off-scene.
   * Bulk source publication and placement-only synchronization avoid full
     display rebuilds and repeated path-state walks for instance edits.
   * Retained explicit shapes, semantic paths, materials, selection, and
     placement survive promotion, demotion, re-promotion, and cache-backed
     realization.  Erase and clear explicitly invalidate stale handles.
   * The retained CAD render batch aggregates eligible source assemblies while
     preserving per-source semantic ownership.  During compact LoD it omits
     only sources with active CAD substitutions; unaffected sources remain in
     the aggregate instead of dropping the whole scene to individual draws.

   Exit condition: compact and full records can replace each other without
   identity changes, stale handles, full-scene rebuilds, or leaked nodes.

   Linux verification: `libbrlobol_prototype`, `libbrlobol_view_store`, and
   the controlled Obol CAD instance-record tests.

Priority 1: Finish Editing and Interaction
------------------------------------------

9. Completed: complete Obol-native edit realization.

   * A toolkit-neutral GED edit transaction owns begin/update/replace,
     commit/cancel/discard, intent, revision, color, point, and transformed
     `rt_db_internal` feedback.  It realizes per-view Obol transient features
     across every hosted view.
   * MGED primitive editing and qged plugins share that transaction.  The
     qtcad widget-private preview and callback ownership paths are deleted.
   * Typed Obol pick details preserve primitive, face, material, nearest
     vertex, and model-point data.  The qged BoT editor implements face,
     edge, and vertex selection, view-plane drag feedback, apply, and reset.
   * Database writes emit semantic added/modified events inside event batches,
     advancing GED scene revisions and updating all hosted views.

   Exit condition: interactive qged and MGED edits use the same neutral edit
   transaction and Obol realization path with no direct widget preview path.

   Linux verification: `test_qtcad_obol_edit_preview`,
   `ged_test_state_services`, `ged_test_obol_draw_sync`, the qged edit-plugin
   builds, and the complete MGED/qged application build.

Priority 2: Performance, Cleanup, and Deletion
----------------------------------------------

10. In progress: characterize evaluated-wire and large-model performance, then
    retain only benchmark-supported optimizations.

    * `ged_draw_perf` now owns a headless GED/Obol endpoint without libdm and
      reports stage counters and deterministic rendered-image hashes.  The
      quick/full corpus driver isolates caches and keeps expensive evaluated,
      shaded, and hidden-line cases out of routine runs.
    * Evaluated-wire pipeline profiling separates region discovery, region
      work, deterministic result merge, VList export, and detailed candidate
      stages.  Unconditional BoT/REC diagnostic floods are behind existing
      librt debug flags.
    * Generic Twin exposed a quadratic region-result merge: repeated exact
      `reserve` calls recopied a 1.17-million-record vector for every region.
      One checked reservation plus ordered move insertion reduced Release
      merge time from about 5.2 seconds to 0.02 seconds with identical hashes.
    * `havoc.g` remains evaluator-bound: Release runs produce 4.27 million
      candidates from 17.3 million face pairs and spend about 12-13 seconds in
      pair evaluation.  Parallel work is deferred until pair jobs own isolated
      hit buffers, segment resources, counters, and ordered result records.
    * Do not add further root/evaluator aggregation or redesign thin-shell
      candidates without a measured whole-path gain.  Keep boolweave as the
      default evaluator and keep shaded/hidden-line tessellation work separate
      from normal wire draw.
    * Normal wire now preserves per-object Obol database sources across view
      changes.  REDRAW checks source staleness and requests rendering without
      replaying publication; Debug Havoc and Generic Twin redraw measure below
      1 ms with unchanged source counts and geometry hashes.
    * Initial normal-wire realization now uses compact per-object CAD records.
      Havoc retains 3,601 semantic database sources while eliminating 3,601
      intermediate scene nodes.  Controlled compact/classic runs improve
      setup by roughly 35-45 percent and produce identical rendered hashes.
      A mesh-LoD-enabled Havoc draw remains compact and measured about 0.73
      seconds in the current Release profiling build.
    * Progressive Moss measurements after the retained-render fixes show
      proxy-first draw publication around 12-19 ms and typical submitted
      AABB/OBB/mesh availability around 25-50/50-65/65-75 ms.  A 192-candidate
      stress run submitted in 10 ms and reached usable OBB/mesh results in
      about 0.29/0.31 seconds.  Its slow initial frame was synchronous
      full-detail overdraw, reinforcing that production large-model startup
      must use the deferred proxy-first path.
    * Exact path operations use a normalized path-to-instance index.  qged tree
      rows cache their draw presentation state until existing draw-observer
      notifications invalidate the affected items, eliminating the scene-wide
      source sort and database walk previously performed for every paint.
    * Mature persistence around stable identity `(database object, occurrence,
      draw mode, view scope)`.  Track geometry, appearance, placement, and
      selection revisions independently; database events must mark only affected
      sources stale.  Share immutable geometry across occurrences, update source
      display state in place, and apply add/remove diffs transactionally rather
      than replacing complete path sets.
    * Retained CAD batching is now active and LoD-aware.  The current post-fix
      Havoc interaction profile is still rendering-bound in Obol VList/CAD
      traversal and Mesa.  Investigate retained backend GPU buffers only with
      larger-model evidence; this work belongs in Obol/libbrlobol, not another
      GED redraw layer.
    * Replace multi-instance LoD demotion with compact-entry task scheduling.
      Each retained compact instance must keep occurrence identity, transform,
      Boolean role, cache identity, result binding, and cancellation ownership
      without manufacturing scene nodes.
    * Stress queue/result behavior at 10^4-10^6 candidates.  Measure and bound
      obsolete stage results after the visible threshold is satisfied, coalesce
      superseded AABB/OBB/mesh results per occurrence, and enforce a main-thread
      application budget that cannot consume an interaction frame.
    * Validate cold/warm deferred LoD in real qged and MGED sessions while
      rotating, zooming, changing views, editing, erasing, and closing the
      database.  Confirm stale generations cannot publish, autoview ownership
      transfers correctly, and first useful pixels arrive before full-detail
      evaluation on Generic Twin, Havoc, and substantially larger models.

    Exit condition: the Release corpus is deterministic; retained changes
    improve their targeted stage by at least 1.5x without small-model or normal
    wire regressions; any parallel result is merged in original job order.
    GUI verification must include a real-model REDRAW transaction, repeated tree
    painting, cold/warm progressive startup, cancellation under camera churn,
    and interactive view changes, not only headless initial drawing.

    remains required, but those platforms must not restore alternate scene

13.  COMPLETE: Preserve FAST and QUALITY software wireframe modes.

    * Obol now carries a per-view AUTO/QUALITY/FAST software-wire policy.
      AUTO and QUALITY use the full OpenGL path over OSMesa; explicit FAST
      permits the direct transform/clip/raster path for eligible plain
      wireframes and falls back to QUALITY for unsupported content.
    * libbrlobol exposes the policy per view controller and propagates it
      through traversal state to both compact CAD assemblies and ordinary
      VList shapes.  `ged_draw_perf --software-wire` and `--render-frames`
      provide repeatable selection and steady-state measurement.
      Applications can query or switch the active view with
      `dm set software_wire` and
      `dm set software_wire auto|quality|fast`; `-d` selects a named DM/view.
    * A 512-instance Obol benchmark measured QUALITY at 1.95 ms/frame and
      FAST at 1.40 ms/frame (1.4x faster), with a 9.9/255 mean pixel
      difference and essentially identical coverage.  Workload matters.
      With a persistent OSMesa context and retained flattened fixed-function
      QUALITY batch, compact `havoc` measured 161-165 ms first-frame and
      13.8-14.1 ms steady-frame QUALITY; FAST samples measured 49-74 ms first
      frame and 9.5-16.0 ms steady.  Generic_Twin measured
      190.1/39.8 ms QUALITY versus 64.5/21.9 ms FAST.  AUTO remains
      quality-first; FAST is an explicit lower-quality performance choice.
    * OSMesa QUALITY avoids the bundled Mesa 7 GLSL interpreter, which was
      measured at roughly 359 ms/frame on havoc.  Obol recognizes its
      software context, retains a fixed-function flattened VBO batch, and
      libbrlobol keeps offscreen renderers/contexts alive across image frames.

14.  Remaining libdm capabilities survey

    * More generally, the "dm" libged command's role will evolve from actual
      different dm backends to providing options to Obol - sw vs hw vs rt
      vs txt vs nu (no-op) Obol backend selection will replace the current
      separate dm backends, and other libdm options that make sense should
      be transitioned in some manner - please consider how best to do that
      and propose a design.
    * One specific concern I do know is there is the ability of libdm to
      create a window.  That is deliberately not an Obol scope - my current
      thought there is for libbrlobol to provide the equivalent of dm and fb
      open functions that use caller registered functions - similarly to how
      Obol itself needs information to set up a context provided by the app.
      Then MGED and rt can register Tk window setup functions from libtclcad,
      qged can do the same by registering appropriate libqtcad functions,
      and by default (nothing registered) the opens fail as no-ops.  We *may*
      consider guaranteeing window creation with GLFW down the road, but not
      yet.  To make this work properly you may need to pull in work from the
      https://github.com/BRL-CAD/brlcad/tree/bindings branch - that is allowed

`BRLCAD_RUN_SLOW_TESTS=1`.  Routine checks must keep the default Moss matrix
short; large-model timing belongs in `.build_perf/` and must report individual
draw, first-readback, submission, AABB, OBB, mesh, and service-stop phases.

Before removing a legacy dependency, also build and test on every affected
window-system platform.  Use `.build_perf/` for final release/performance
measurements, not for routine development.

Definition of Fully Stood Up
-----------------------------

The migration is complete when supported GED, qged, MGED, rtwizard, Archer,
and GSH workflows have one authoritative shared Obol scene, scoped local
geometry only for independent views, and one render endpoint per host view;
drawing, interaction, LoD, editing, readback, and framebuffer streaming do
not require libbsg or graphical libdm paths; no fallback silently creates
legacy scene state; and the remaining drawing-related libdm compatibility can
be disabled or deleted without reducing covered functionality.
