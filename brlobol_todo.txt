BRL-CAD Obol Drawing TODO
=========================

Last reviewed: 2026-07-11
Branch: brlobol

Purpose
-------

This file lists remaining work needed to complete the Obol/libbrlobol drawing
migration.  Completed implementation history and performance investigations do
not belong here.  Durable design notes should move to `doc/notes/`.

Current Baseline
----------------

The active drawing path is Obol-based.  libbsg and the legacy OGL, WGL, X,
QtGL, swrast, and tkswrast graphical paths are retired.  GED owns drawing
transactions and view bookkeeping; libbrlobol owns retained BRL-CAD scene
realization; libimgstream owns framebuffer transport; Tk and Qt supply Obol
display hosts.  FAST and QUALITY OSMesa wireframe modes are available.

The remaining architectural compatibility layer is libdm.  libtclcad/MGED
still use portions of its command, display, and framebuffer surface.  The
goal is to replace those responsibilities rather than reproduce `struct dm`
under a new name.

Required Architecture
---------------------

* A GED view has one authoritative Obol scene and one display endpoint.
* Geometry is source-local; instances supply placement and retain occurrence
  identity, material, visibility, selection, edit intent, and export metadata.
* Realized LoD is view-local.  Shared sources are not mutated for one view.
* libbv owns passive view mechanics, not scene or display ownership.
* libbrlobol owns BRL-CAD source realization, retained features, picking,
  selection, edit previews, LoD, and BRL-CAD render-engine adapters.
* Obol owns renderer-neutral scene traversal and render-engine interfaces.
* librt supplies BRL-CAD geometry evaluation and the future interactive `rt`
  renderer without owning application display state.
* libimgstream owns image storage, framebuffer protocol, and transport.
* Applications own native windows, toolkit event loops, and GL contexts.
* Explicit renderer requests never silently fall back to another renderer.
* Missing scene, host, or capability ownership fails explicitly.  No legacy
  scene or display path may be recreated as a fallback.

Deferred Scope
--------------

Evaluated wireframe optimization is shelved.  Preserve existing correctness
and build coverage, but do not spend active migration effort on its scaling,
parallelization, candidate generation, or benchmark performance.  Normal
wireframe and shaded display remain the interactive performance priorities.

Enabling Cleanup
----------------

These refactors are valid deliverables when they simplify or de-risk the
remaining work.  They should be done immediately before the work they enable,
not accumulated as an independent rewrite.

E1. Keep the dependency and ownership boundaries mechanically visible.

    Maintain a target-level inventory of libdm, libbrlobol, libimgstream,
    libtclcad, and libqtcad dependencies.  Extend the pivot guard as each
    responsibility moves so deleted dependencies, global hosts, immediate DM
    drawing, and alternate scene publication cannot return unnoticed.

E2. Isolate compatibility at narrow, deletable boundaries.

    Move surviving `struct dm`, callback-table, and `struct fb` access behind
    explicitly named migration adapters.  New endpoint, host, renderer, input,
    and image-stream code must not include libdm headers.  Each adapter needs a
    caller inventory and a deletion condition tied to the numbered task that
    replaces it.

E3. Factor common host and presentation mechanics before adding engines.

    Extract endpoint lifecycle, frame scheduling, resize/DPI propagation,
    capture, pixel presentation, and callback shutdown from toolkit-specific
    implementations.  Tk and Qt should contain only native window/context,
    event-loop, and image-presentation code.  Do not duplicate the same
    engine-selection or controller synchronization policy in both hosts.

E4. Provide endpoint-native test and application helpers.

    Replace repeated test-only DM attachment and application setup with small
    headless, Tk, and Qt endpoint fixtures.  Centralize deterministic capture,
    generation draining, timeout, and teardown helpers so new tests exercise
    the target architecture and remain fast.

E5. Delete superseded code in the same change that removes its final caller.

    Avoid compatibility layers whose only purpose is making an obsolete path
    compile.  When a migration exposes dead commands, plugins, option tables,
    callbacks, factories, tests, or dependency rows, remove them and tighten
    the guard immediately.  Preserve behavior only when an identified caller
    and replacement requirement remain.

Priority 0: Display Endpoints and Host Factories
------------------------------------------------

1. Define the display endpoint API.

   Add an opaque `brlobol_display_endpoint_t`, with a C++ wrapper, binding one
   `BRLObolViewController`, one render-engine policy, and zero or one host
   instance.  Add a dedicated endpoint slot to GED view state; do not overload
   the legacy display-manager slot.

   Specify controller ownership, host-factory retention, stream detachment,
   callback shutdown, and destruction order.  Mutable state is per endpoint;
   there must be no process-global active display host.

   Exit condition: endpoint status, capture, and typed property access work in
   DM-less qged, Tk-hosted MGED, and headless tests.

2. Replace single-host registration with a versioned factory ABI.

   Use a copied, size/version-checked callback table with stable name,
   priority, capabilities, probe/create/destroy, controller binding, frame
   request, resize, capture, polling, input delivery, and pixel presentation.
   Registration returns a retained token; unregister must reject live use.

   Initial capabilities include TOPLEVEL, EMBEDDED, SYSTEM_GL, PIXEL_PRESENT,
   PROGRESSIVE_PRESENT, INPUT, READBACK, FRAMEBUFFER_PRESENT, MULTI_VIEW, and
   THREAD_AFFINE.  Toolkit calls run on the host thread.  Worker threads may
   only enqueue frame requests, and no callback may occur after close returns.

   Refactor the existing headless, Tk/Togl, TkPhoto, Qt GL, and Qt image hosts
   into factories.  A visible open with no compatible host fails cleanly.

   Exit condition: simultaneous endpoints use isolated hosts and teardown is
   safe with active rendering and image streams.

3. Adopt the bindings branch's semantic input model.

   Port normalized events, binding contexts, and action dispatch so Tk and Qt
   do not maintain separate hard-coded interaction profiles.  Keep action and
   context ownership scoped to an application/endpoint rather than copying the
   branch's process-global registries into the host ABI.

   Exit condition: Tk and Qt produce the same semantic camera, selection,
   edit, framebuffer, and faceplate actions from equivalent input.

Priority 0: Render Engines and Typed Policy
-------------------------------------------

4. Define Obol's render-engine contract.

   Render engines declare capabilities and whether they render directly into
   a host context or publish pixel/depth/identity frames.  Required choices:

   * `auto`: deterministic selection from endpoint and host capabilities;
   * `hw`: Obol using a host-provided system OpenGL context;
   * `sw`: Obol using OSMesa and host pixel presentation;
   * `rt`: Obol using a libbrlobol/librt renderer and pixel presentation;
   * `none`: retain scene state without rendering; and
   * `diagnostic`: traverse and report without posing as a graphical backend.

   Explicit `hw`, `sw`, and `rt` requests fail on capability mismatch.  FAST
   versus QUALITY remains a separate OSMesa wireframe policy.  Plot, PS, and
   SVG are export actions, not render engines.  `ert` remains a separate
   command-driven render stream rather than an alias for interactive `rt`.

   Exit condition: engine selection is independent of toolkit host selection,
   and a headless endpoint can exercise every compatible engine.

5. Replace libdm option tables with typed endpoint properties.

   Each property needs a stable name, type, allowed range/values, mutability,
   capability predicate, getter, and setter.  Initial ownership is:

   * endpoint/host: size, device-pixel ratio, title, visibility, vsync;
   * controller: background and software-wire policy;
   * bv/input: camera, perspective, clipping, and navigation bounds;
   * renderer: depth, lighting, transparency, antialiasing, and stereo;
   * retained features: color, line style/width, font, and visibility; and
   * retained composition: framebuffer visibility and ordering.

   Immediate matrices, draw begin/end, HUD begin/end, primitive calls, swap,
   flush, clipping helpers, and global mutable draw state are not properties.

   Exit condition: unknown and unsupported properties fail explicitly, and no
   production option uses backend `bu_structparse` state.

6. Implement the retained interactive librt engine.

   libbrlobol must adapt the authoritative Obol scene, camera, visibility, and
   style state to librt.  Maintain a revision-keyed retained librt scene and
   acceleration state; camera-only frames must not re-walk or rebuild database
   geometry.  Render tiles progressively, cancel stale generations on camera
   or scene changes, and publish partial/final frames through the endpoint.

   Provide typed `render.rt.*` policy for frame budget, worker count, sampling,
   and progressive quality.  Optional depth and identity planes should support
   composition and exact interaction without tying picking to display quality.
   Obol's NanoRT/Embree examples may inform the generic engine seam, but `rt`
   remains the BRL-CAD-native renderer.

   Exit condition: qged and MGED can interactively select `rt`; camera motion
   cancels stale work; unchanged geometry is retained; headless image results
   are deterministic at a fixed final quality.

Priority 1: Replace the libdm Command and Compatibility Surface
---------------------------------------------------------------

7. Convert the GED `dm` command to endpoint operations.

   Preserve the command name for scripts, with this target surface:

       dm status [-V view]
       dm list [endpoints|hosts|renderers]
       dm open [-V view] --host name --renderer auto|hw|sw|rt|none
       dm close [-V view]
       dm host [-V view]
       dm renderer [-V view] [auto|hw|sw|rt|none|diagnostic]
       dm get [-V view] [property ...]
       dm set [-V view] property value
       dm diagnostics [-V view]

   `-V` is the canonical view selector.  Temporary aliases may translate
   `attach`, `type`, `types`, `initmsg`, `bg`, and `-d` into typed endpoint
   operations, but may not instantiate compatibility renderers.  Screengrab
   must use endpoint capture exclusively.

   Exit condition: qged and MGED control equivalent endpoint state through the
   same command without inspecting a DM plugin call table.

8. Complete framebuffer separation.

   Replace `imgstream_fb_display_host_set` and other single global host state
   with per-open endpoint/factory presentation.  Remove `dm_get_fb` fallbacks
   from `ert`, screengrab, and libged image commands after host coverage exists.
   Move remaining standalone `fb_*` compatibility APIs and utilities onto an
   imgstream compatibility library.

   Exit condition: GUI framebuffer presentation and fbserv do not require
   `struct dm`; memory, file, and remote streams remain GUI-independent.

9. Delete remaining immediate and plugin compatibility code.

   Finish MGED/libtclcad retained realization for faceplate, labels, grid,
   ADC, axes, rubber band, menus, center dot, edit previews, and framebuffer
   ordering.  Delete their post-sync immediate DM calls rather than
   implementing them in the endpoint API.

   Replace plot/PS plugins with retained-scene export actions and convert
   `plot3-dm` to a small Obol viewer/importer if it remains useful.  Remove
   `dm-tkobol`, `dm-obol`, the DM plugin loader, and the rendering call table
   once their callers are gone.

   Exit condition: adding a new production use of an immediate DM callback or
   graphical DM plugin is rejected by the pivot guard.

10. Remove final libdm dependencies.

    Audit libtclcad, MGED, rtwizard, Archer, RT tools, ART/ADRT, framebuffer
    utilities, and image commands.  Migrate required behavior to endpoints,
    host factories, Obol export actions, or libimgstream; delete unused paths.

    Exit condition: drawing, window hosting, input, readback, and framebuffer
    streaming build and run without libdm.  Any unrelated surviving libdm API
    must have an explicit owner and deprecation plan.

Priority 1: Large-Model Interactivity
-------------------------------------

11. Complete incremental retained-source updates.

    Use stable identity `(database object, occurrence, draw mode, view scope)`.
    Track geometry, appearance, placement, visibility, and selection revisions
    independently.  Database events mark only affected sources stale; add,
    remove, and update operations apply transactionally without replacing the
    complete displayed path set.  Share immutable geometry across occurrences.

    Exit condition: camera-only redraw performs no source publication;
    placement/style edits do not rebuild geometry; localized database edits do
    not walk or republish unaffected sources.

12. Finish compact-entry LoD scheduling.

    Replace multi-instance demotion with tasks addressed directly to retained
    compact entries.  Preserve occurrence identity, transform, Boolean role,
    cache identity, result binding, and cancellation ownership without creating
    intermediate scene nodes.

    Stress 10^4-10^6 candidates.  Coalesce superseded AABB/OBB/mesh results per
    occurrence, bound queued and obsolete results, and enforce a main-thread
    application budget that cannot consume an interaction frame.

    Exit condition: proxy-first startup and progressive refinement remain
    responsive under camera churn, view replacement, edits, erase, database
    close, and endpoint teardown; stale generations cannot publish.

13. Validate and optimize the normal wireframe and shaded hot paths.

    Profile cold draw, first useful pixels, steady camera rotation, zoom,
    selection/illumination, source updates, traversal, submission, and
    presentation in real qged and MGED sessions.  Use Generic Twin, Havoc, and
    substantially larger models.  Compare hw and both OSMesa wire policies.

    Investigate retained backend GPU buffers or deeper Obol batching only when
    profiles show traversal/submission remains material.  Changes belong in
    Obol/libbrlobol, not another GED redraw layer.  Require deterministic image
    hashes and a measured whole-path improvement without small-model regressions.

    Exit condition: first useful pixels precede full-detail realization,
    rotations avoid scene/source work, and interaction remains bounded while
    asynchronous refinement is active.

Priority 2: Platform and Application Closure
--------------------------------------------

14. Validate every supported application and host.

    Exercise qged, MGED, GSH, rtwizard, and Archer with hw and sw endpoints;
    add `rt` when implemented.  Cover multiple views, resize, DPI changes,
    background/faceplate composition, input, selection, editing, screengrab,
    framebuffer overlay/underlay, ERT, close, and database replacement.

    Complete native runtime testing on X11, Windows, and macOS.  Platform fixes
    must improve the Obol hosts rather than restore OGL/WGL or alternate scene
    synchronization paths.

    Exit condition: the supported host/application matrix has automated smoke
    coverage and no platform requires a legacy graphical backend.

Verification Gates
------------------

Fast boundary and protocol checks:

* `ninja -C .build`
* `ctest --test-dir .build -R '^(brlobol_pivot_guard|imgstream_test|imgstream_fb_compat_test|imgstream_fbserv_auth_test|imgstream_fbserv_lifecycle_test)$' --output-on-failure`
* `git diff --check`

Core drawing and interaction checks:

* `ctest --test-dir .build -R '^(libbrlobol_|ged_test_obol_draw_sync|ged_test_view_command|ged_test_view_independent|ged_test_selection_semantics|ged_test_snap_semantics)' --output-on-failure`
* `ctest --test-dir .build -R '^ged_test_drawing_(basic|faceplate|lod|select|quad)$' --output-on-failure`

Host and streaming checks:

* `ctest --test-dir .build -R '^(test_qged_obol_fbserv|regress-qged-ert|gsh_obol_(smoke|ert_smoke|progressive_lod)|mged_obol_(smoke|ert_smoke|progressive_lod))$' --output-on-failure`
* `ctest --test-dir .build -R '^test_qtcad_obol_' --output-on-failure`

Slow progressive-LoD cases remain opt-in through `BRLCAD_RUN_SLOW_TESTS=1`.
Large-model timing belongs in `.build_perf/`, not routine correctness runs.

Completion
----------

The migration is complete when supported applications use one authoritative
Obol scene and one endpoint per hosted view; normal drawing, interaction, LoD,
editing, capture, and framebuffer streaming require neither libbsg nor libdm;
explicit hw, sw, and rt engines share the same scene and policy model; and no
fallback silently creates legacy scene or display state.
