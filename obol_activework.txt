BRL-CAD Obol Active Work Guide
==============================

Last refreshed: 2026-06-25

Purpose
-------

This is the first file a new or resumed AI session should read before working
on the Obol migration.  It is intentionally current and action-oriented.  Use
`obol_worklog.txt` for detailed history, rationale, and older verification
records consolidated from the former root guidance files.


Working Rules
-------------

* Work on the oboltest branch unless the user redirects.
* Do not rebase oboltest again unless the user explicitly asks.
* Primary BRL-CAD build directory is `build/` and uses Ninja.
* If modifying embedded Obol sources, build in `obol/build` and run install so
  BRL-CAD CMake can detect the staged update.
* The compile/test cycle is slow.  Batch low-risk related changes when root
  causing failures will still be straightforward.
* Keep Obol-canonical code free of new public BSG/libdm dependencies.
* Preserve user and existing worktree changes.  Do not revert unrelated edits.
* Keep `/tmp` clean.  This is a shared machine.
* Single tests over 180 seconds are a problem to investigate or split.
* Avoid premature profiling work during migration unless a change introduces a
  catastrophic slowdown.
* Update this file when active priorities, percentages, remaining blockers, or
  verification baselines materially change.


Migration Intent
----------------

BRL-CAD should use Obol as the canonical scene, view, interaction, and
rendering API for interactive 3D applications.

The migration is parallel-first: build the Obol path beside the current
BSG/DM path until it reaches production parity, then remove public libbsg,
libdm, dm_plugins, and BSG/DM-shaped application APIs.  Temporary internal
bridges are acceptable while a phase is incomplete.  No long-lived public BSG
or DM compatibility layer is part of the target design.

libbrlobol is the BRL-CAD-specific Obol extension library.  It should define
BRL-CAD Obol nodes, actions, details, and narrow application services.  It
must not become a generic replacement for BSG's render-item/backend-scene
model.

Remaining Work
--------------

The near-term work is still Phase 5 wrapper retirement, not profiling.  Batch
only related wrappers where ownership and tests are straightforward.

Current immediate draw-bridge blockers are retained scene-ref/root/scope
handoffs, retained BSG-backed feature/polygon internals behind context
helpers, public BSG-shaped snap/scene-ref bridge signatures, qtcad draw
transaction/observer ownership, and the guarded direct `libbsg` dependency
rows in `libdm` and `libged`.  Do not treat retired private wrapper names as
remaining work when the corresponding context helper is still intentionally
BSG-backed.

GED retained bridge:

* Keep the public BSG-typed GED draw snap and scene-ref entry points only as
  bridge shims.  Their first-candidate, update-callback, LoD bounds callback
  install, context info/LoD, scale, autoview, and independent-view boolean
  internals are now neutral, but the public BSG-shaped signatures and retained
  `bsg_scene_ref` handoffs cannot retire until the wider draw-view API
  boundary is replaced.
* Treat the remaining production helper calls as three concrete groups:
  retained active-view group/overlay/redraw BSG view use, retained scene-root
  group-creation plus scene-ref handoff helpers, and public BSG-shaped
  scene-ref realization handoffs.  Transaction active save/restore,
  transaction/tree/scene-root view-set iteration, transaction DB-event
  scene-root-ref reads, scene-root draw-context recycling, scene-root query
  refs, scene-root attach, scene-attached checks, and BSG-backed active-view
  lookups now use neutral or context-shaped helpers.  The private mesh-LoD
  load pass-through is gone; retained draw realization now converts through
  the central draw-ref helper before calling neutral
  `rt_mesh_lod_load_view_scene_ref` directly.  The reset/free path now uses
  neutral `rt_mesh_lod_free_scene_ref`; do not flatten the remaining
  root/scope paths by local casts.  Migrate them only with a neutral API
  boundary that preserves retained-scene correctness.
* `ged/draw.h` now owns the public declarations and the public context info/LoD
  helpers use neutral `ged_draw_view_context_*_get/apply` names.  No production
  code directly includes `ged/bsg_ged_draw.h`, bridge-owned transaction redraw
  info/LoD and autoview paths plus draft/refs/view primitive-wireframe,
  realization-policy, polygon scale reads, and tree/transaction/record
  independent-view boolean checks now use neutral RT context helpers.  GED
  draw-record selected/highlighted shape-ref selection paths now use opaque
  context helpers, with retained BSG selection mechanics contained inside the
  draw-view bridge implementation.  GED draw-tree independent-scope refs now
  use neutral `rt_view_context_independent_scope_ref`; remaining tree
  active-view use reads through `ged_view_active_ctx` but is still tied to
  retained BSG group creation.  GED draw transactions now use neutral context
  helpers for active-view save/restore, active-view fallback reads, and GED
  view-set iteration, and the DB-event view-root revalidation path now queries
  neutral `rt_view_scene_ref` roots through
  `ged_draw_view_context_scene_root_rt_ref` before converting only the
  retained draw-intent revalidation target, but still has retained BSG view
  handoffs for redraw and finalization.
  GED draw scene-root view-set iteration and recycle-pool lookup now use
  neutral context helpers, scene-root ref/attached queries and root attach use
  neutral RT helpers, and active-view reads go through `ged_view_active_ctx`,
  but active-view group creation and the retained scene-root backend still
  require the wider scene-root API migration.

qtcad retained bridge:

* Keep qtcad on the neutral `ged/draw.h` include while migrating retained
  draw transactions/observers to Obol/libbrlobol ownership.
* Keep retained DM and framebuffer host bridge operations guarded until they
  have direct Obol/libbrlobol ownership.

Lower backend and link graph:

* Move retained libdm draw/backend behavior off BSG ownership.
* Remove remaining direct `libbsg` dependency rows from `libdm` and `libged`
  only after their guarded API surfaces no longer require it; keep `libqtcad`
  and `libtclcad` retired direct `libbsg` rows guarded so they do not return.
* Remove `qged`'s direct `dm_plugins` dependency when the Obol/qtcad display
  path can own backend selection.
* Start Phase 6 hard removal only after public headers, source includes,
  target dependencies, installed artifacts, and tests no longer need libbsg,
  libdm, or dm_plugins as compatibility surfaces.

Obol/libbrlobol parity work still open:

* qtcad visible Obol rendering and draw synchronization are not yet complete.
* Diagnostic overlays are mid-migration.
* libimgstream/framebuffer ownership remains incomplete.
* Performance optimization is deferred unless migration work introduces a
  single-test runtime above 180 seconds or an obvious catastrophic slowdown.

only if its ownership and tests are straightforward.  The targeted BSG-named
RT wrapper scan for `ged_view_legacy.cpp` and qtcad is now empty.  Production
draw consumers no longer include the BSG-named GED draw header directly, the
public draw-view context info/LoD helpers and draw.cpp realization

autoview plus draft/refs/view primitive-wireframe info, LoD, and scale reads
now route through neutral RT context helpers.  The tree/transaction/record
independent-view boolean checks now use the same neutral RT context helper.

as a local rename.  The next useful GED batch should either prove that one of

handoff helpers can move to an existing neutral call without weakening
ownership, or start replacing the public BSG-typed draw
snap/scene-ref API surface.  Remaining qtcad work is retained draw
transaction/observer behavior behind `ged/draw.h` plus retained DM/framebuffer
host ownership.  Remaining lower-level work is the direct `libbsg` rows in
`libdm` and `libged`, qged's direct `dm_plugins` edge, and the lower
backend/display ownership that still depends on those rows.
