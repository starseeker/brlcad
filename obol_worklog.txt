BRL-CAD Obol Worklog
====================

Last compressed: 2026-07-07

Purpose
-------

This is a compressed historical summary for the Obol migration.  Exact diffs
belong to git history.  Current work state belongs in `obol_activework.txt`;
durable design contracts belong in `doc/notes/`.

Major Milestones
----------------

Database drawing moved to Obol/libbrlobol.

* GED draw transactions use Obol scene/source ownership for active database
  draw, erase, redraw, material, bounds, and source-record behavior.
* Retained BSG draw ownership is no longer an active fallback for migrated
  paths.
* Source-local geometry, explicit instance transforms, material/color-table
  refresh, and primitive internal publication are libbrlobol responsibilities.

View and command visuals moved toward Obol scene objects.

* View features, annotations, polygons, line sets, and command diagnostics now
  have Obol/libbrlobol store paths.
* rtcheck, NIRT/qray, check overlap, GQA, BREP/NMG diagnostics, overlay uplot,
  `vdraw send`, and preview helpers are covered by the command-scene model.
* The redesigned `view line`/object behavior uses Obol concepts rather than
  the old `view obj` syntax.

LoD and cache ownership moved to libbrlobol.

* Persistent draw data uses `BU_DIR_CACHE/.DbDrawCache`.
* Mesh POP LoD APIs and cache ownership moved out of retained BSG direction
  and into libbrlobol.
* Progressive qtcad tests cover startup, manual expansion, automatic bounded
  expansion, wire LoD, and shaded BoT LoD.
* AABB/OBB proxy geometry is leaf-solid data; comb bounds are bottom-up
  aggregates.

Framebuffer and display host work moved toward Obol.

* qtcad ordinary painting is Obol-only.
* qged fbserv traffic is bridged through libbrlobol image streams.
* GSH and MGED have headless Obol attach/screengrab and ERT smoke coverage.
* Framebuffer stream updates are dirty/present split: protocol writes do not
  mutate scene graph state directly.

libbv was reintroduced as a clean view-mechanics library.

* Native librt view contexts are libbv-backed.
* libbv owns view math and generic input/knob state only.
* Scene behaviors are routed through Obol/libbrlobol adapters or return
  explicit empty/no-op results.

Evaluated wireframe was modernized.

* `rt_eval_wireframe` exposes the core full-path evaluated wireframe feature.
* The boolweave-backed method is the default.
* The older BigE-style path remains only as a comparison option.
* Very thin shell models such as `havoc.g` remain an optimization/candidate
  generation stress case.

Strict-warning cleanup landed.

* FreeBSD clang/clang++ 21 `-Werror` issues were fixed directly where found.
* libfort wide-character C/C++ compatibility was corrected.
* RT-family shared globals were centralized through `src/rt/ext.h`.
* Obsolete retained-BSG-only tests were removed instead of maintained.

Current Handoff
---------------

Use `obol_activework.txt` for next steps.  The highest-value follow-up remains
removing remaining retained BSG/immediate libdm callers, then hardening
progressive large-root drawing and app-host framebuffer/readback behavior.
