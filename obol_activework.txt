BRL-CAD Obol Active Work Guide
==============================

Last refreshed: 2026-07-05
Branch: oboltest2

Purpose
-------

Read this file first when resuming Obol migration work.  It records the
current target state, active risks, verification gates, and next actions.  Use
`obol_worklog.txt` for compressed history and `doc/notes/` for durable design
contracts.

Workspace Rules
---------------

* Build directory: `build/`, generated with Ninja.
* Python command: `python3.11`.
* Debugger: `lldb`.
* Obol source checkout: `obol/`.
* Preserve preexisting worktree changes; do not revert unrelated edits.
* Retire legacy BSG paths when they conflict with a clean Obol design.
* Keep Obol/libbrlobol boundaries explicit instead of accumulating one-off
  compatibility paths.
* Update this file and relevant `doc/notes` files when the migration plan,
  design invariant, or verification baseline changes.

Current Stance
--------------

Obol/libbrlobol is the canonical scene, view, interaction, and rendering path
for migrated BRL-CAD interactive workflows.  Retained BSG/libdm code may remain
compiled for no-owned-scene compatibility and old applications, but new
correctness work should not preserve parallel BSG ownership when an Obol answer
is clear.

The current workspace builds cleanly with FreeBSD clang/clang++ 21.1.8 and the
project's strict `-Werror` settings.  Do not respond to new warnings by adding
suppressions first; prefer real ownership, declaration-order, initialization,
and API-boundary fixes.  The libfort C/C++ wide-character API now uses
`ft_wchar_t`, RT-family shared globals are centralized in `src/rt/ext.h`, and
the old standalone `rt_view_legacy_bsg` test has been retired rather than kept
as current coverage.

The common non-scene view mechanics are now moving back out of BSG into a
clean libbv, not into librt.  The mainline source in
`/home/starseeker/brlcad_vanilla` still has the old `include/bv` and
`src/libbv` implementation, but that API is not a compatibility target.  Use
it only as reference material for concepts and math.  The new libbv has short
`bv_*` naming and owns camera/view state, matrix updates,
autoview-bounds math, screen/model transforms, input/knob state, and view-set
bookkeeping.  librt now has a native/libbv-backed `rt_view_context` path for
neutral view mechanics, while explicit `_bsg` constructors remain for retained
fallback tests and old callers.  libbv still must not own scene objects,
display lists, Tcl/display-manager state, polygon stores, snap/selection
resolution, LoD caches, or retained scene graph behavior; libbrlobol/Obol
should own the scene graph and richer Coin interaction objects.
Persistent drawing cache policy also belongs with libbrlobol.  librt may
provide geometry queries and extraction primitives, but AABB/OBB/metadata
cache ownership and background draw-realization policy should not live in
librt.

Framebuffer streaming follows the same boundary rule.  The fbserv wire
protocol is transitional code in libdm today, but its long-term home should be
a small framebuffer/image-stream protocol layer beside libimgstream/libicv, not
libbrlobol.  libbrlobol should own the Obol scene representation of streamed
images, view placement, refresh scheduling, picking/interaction, and lifecycle.
`BRLObolFramebufferStream` is the reusable libbrlobol helper for attaching an
`imgstream` framebuffer to an Obol window host and forwarding pixel, view, and
cursor state into the scene.  It should remain free of fbserv packet parsing
and `struct fb` compatibility.
qged installs its own Qt-aware bridge; GSH, classic MGED, and other plain GED
hosts use the libged Obol fbserv bridge.  Classic MGED and TclCAD now expose
`ert` through the Obol-capable GED path and present pending framebuffer stream
state from their view refresh loops before render traversal.

The next push should favor removing remaining old-style non-Obol drawing
drivers before expanding richer Coin behavior.  Richer behavior needs only the
minimum stable contracts now: owner, scope, lifecycle, capability, style,
pick/selection identity, metadata, custom-provider teardown, and database-edit
invalidation.  Locking down every manipulator/detail-panel behavior while old
drawing paths still exist would force the design to support code paths we are
trying to delete.

Core Invariants
---------------

* Database-source primary geometry is source-local.  `drawMatrix` is placement
  metadata, not a transform baked into primary point/index arrays.
* Realized BRL-CAD database leaves use shared local geometry plus explicit
  per-instance OpenInventor transforms from tree-walk state.
* The visible leaf shape owns path identity, material/region state, selection,
  visibility, highlight, edit intent, LoD wrapper state, and export metadata
  even when drawable arrays are shared.
* LoD is view-aware.  Multiple views may choose different display/staged LoD
  for the same scene while preserving identical database, selection, edit, and
  identity semantics.
* Active display LoD for shared geometry is view-local.  Shared mesh nodes keep
  identity, source metrics, bounds, draw/material/selection state, and optional
  source/full-detail arrays; `BRLObolViewController` owns active
  `BRLObolViewLodState` payloads and binds them into Coin traversal.
* Persistent drawing cache data has one filesystem root:
  `BU_DIR_CACHE/.DbDrawCache`.  libbrlobol owns the draw proxy/metadata cache
  (`draw_data.format`) for AABB, OBB, object-local draw metadata, and
  full-path aggregate draw metadata.  libbrlobol also owns the mesh POP LoD
  cache implementation/API (`brlobol_mesh_lod_*`).  Mesh POP LoD data shares
  the same root through `mesh_lod.format`.  Cache setup must tolerate an empty
  or relative `BU_DIR_CACHE` by treating the cache path as current-directory
  relative, never by attempting to create `""` or `/.DbDrawCache`.  librt does
  not own draw-cache or mesh-LoD cache state.
* AABB/OBB draw proxies are leaf-solid geometry.  Comb nodes may have cached
  metadata and scene/source nodes, but comb bounding boxes are derived
  bottom-up from available transformed leaf facts for drawing/autoview; do not
  synthesize comb proxy geometry by recursively walking the database in the
  draw path.
* Database object change notifications invalidate draw-cache proxy/metadata
  records for the changed object and all indexed ancestor objects on affected
  paths.  Duplicate instance ids are canonicalized to object names before
  invalidation; only the directly changed object clears its mesh-LoD cache key.
* External database-source primary geometry published by Obol/GED providers is
  a legitimate source-local realization even when it is proxy geometry for a
  different final draw mode.  Source replacement/state sync must preserve and
  revalidate this external primary until an explicit erase, clear, replacement,
  or stale database edit invalidates it.
* Legacy BSG mesh LoD code is quarantined to `BU_DIR_CACHE/.BsgMeshLodCache`.
  It must not share, version, or clear libbrlobol's `.DbDrawCache`; new cache
  work belongs in libbrlobol while the retained BSG renderer path is removed.
* Applying active display LoD requires an explicit view state.  A direct
  `SoBRLLodUpdateAction` with no `BRLObolViewLodState` rejects matched results
  instead of mutating shared mesh fields; non-render tools needing LoD should use
  a scratch view/controller state or consume provider output directly.
* Bounds and autoview apply transforms explicitly.  Autoview keeps the
  historical padded database-object envelope separate from tight scene bounds.
* Shared geometry reuse is action-scoped today.  Persistent reuse needs
  explicit keys, revision inputs, refcounting, invalidation, and edit behavior.
* Command-produced visuals are scene objects, not anonymous decorations.
  Shared scene scope is the default unless a command explicitly requests
  view-local results.
* Framebuffer protocol handling is backend-neutral.  Callers should target the
  fbserv operation table or a future libimgstream-side protocol library rather
  than direct `struct fb` or display-manager state.  Obol hosts consume the
  resulting image stream through `BRLObolFramebufferStream` as
  scene/presentation data.
* Framebuffer producer threads are dirty publishers only.  They may write
  `imgstream` pixels and fb-compatible state, but must not mutate Coin fields
  or rebuild Obol geometry.  `SoBRLImageSource` stream callbacks update only an
  atomic pending-generation marker; application/update owners call
  `BRLObolFramebufferStream::present` or equivalent refresh logic before a
  read-only render traversal.

Current Baseline
----------------

* GED basic drawing passes through Obol capture.  Normal database draw modes
  use direct Obol providers instead of retained `_ged_drawtrees` mirrors.
* Autoview was preserved: `autoview2` calls the Obol database autoview bridge,
  and `draw_obol.cpp` exposes libbrlobol scene bounds to GED.  Deferred leaf
  expansion does not fall back to recursive database object bounds when Obol
  source bounds are empty; autoview remains pending until leaf-source bounds
  are published or the user changes the camera.
* Direct wire, shaded-BoT, shaded, and hidden-line draws expand requested roots
  with `db_walk_tree_leaf_instances`, realize leaf database sources, and ensure
  an explicit Obol group for the requested root.
* Startup/deferred leaf expansion creates database-source nodes and applies
  cached metadata without forcing leaf realization.  Leaf solids with cached
  AABB records can publish proxy line sets as source-local external primary
  geometry; comb roots remain metadata/source structure until leaf proxy data
  is available.
* A bounded post-proxy expansion bridge can now expand union children of
  already drawn database sources without invoking the full leaf-realization
  path.  The single-source API consumes available libbrlobol child AABB cache
  records, applies the child path placement matrix, publishes child proxy line
  sets for leaf solids as source-local external primary geometry, and keeps
  comb children as metadata/source nodes rather than calculating comb boxes
  from the database.  Visible-frontier APIs repeat that prewarm/expand step
  over the current database-source frontier under a requested root, so an
  application can advance recursive refinement in bounded render-thread passes.
  The companion prewarm path submits child AABB cache tasks through the
  attached `BRLObolLodService`, so cache population can run on worker threads
  before expansion consumes the records.
  `test_qtcad_obol_progressive_lod_generic_twin_startup_expand` verifies
  `Generic_Twin.g all` grows from the startup metadata root through
  service-backed visible-frontier passes, increases source-tree depth,
  publishes leaf AABB proxies, refreshes autoview from Obol source bounds, and
  produces an image-visible frame change without wireframe tessellation.
* The draw metadata cache has both object-local records and full-path aggregate
  records.  Full-path metadata refresh uses librt tree-state walking to cache
  inherited region id, air, material id, LOS, color, shader, and inheritance
  state for a realized leaf path while preserving the object-local records used
  for direct directory/attribute facts.
* qtcad startup-refine coverage now verifies the next transition as well:
  after the deferred proxy first frame is visible, the same target can be
  promoted to the mesh-backed qtcad path and then progress through view-local
  AABB, OBB, and mesh LoD payloads.
* Generic_Twin now has bounded qtcad gates for the intended large-root flow.
  Wire startup progresses metadata root -> bounded leaf AABB proxy expansion
  -> direct Obol wire realization -> view-local AABB/OBB/mesh LoD, and
  `view lod mesh 0` clears view-local payloads so full-detail wire drawing is
  centered and visible again.  Shaded large-root coverage uses shaded-BoT
  representation: BoT leaves are realized from existing BoT mesh data while
  non-BoT leaves remain wire/vlist instead of forcing full CSG tessellation.
* Obol-attached `view lod` policy changes now stay on the Obol path.  The
  command applies the neutral view policy, notifies the GED/Obol bridge,
  clears the attached view's `BRLObolViewLodState`, advances the view LoD
  policy revision, refreshes database-source view policy, and requests an
  Obol render.  Non-Obol views still fall back to legacy redraw.
* libbu cache environments are opened with `MDB_NOTLS`, so LMDB reader slots
  are tied to transaction objects rather than LoD worker threads.  This avoids
  `MDB_BAD_RSLOT` failures when BRLObol LoD workers concurrently populate and
  read `.DbDrawCache`.  `bu_mkdir` now rejects empty paths and `bu_cache_open`
  creates relative component paths under `.` when `BU_DIR_CACHE` resolves
  empty, preventing the mesh-LoD/draw-cache worker path from entering an empty
  directory creation loop.
* Native `rt_view_context` snapping uses the historical interactive tolerance
  factor of 10.0, matching the old BSG view-state initialization while keeping
  qtcad Obol database snapping on the non-legacy path.
* Repeated comb/solid instances under different transforms share local
  geometry during realization while retaining per-instance transforms and
  identity.
* Evaluated wire and evaluated sampled-points are Obol database-source
  provider outputs for the requested path.  Evaluated wire now has a librt
  core entry point, `rt_eval_wireframe(vhead, vlfree, dbip, path, tol, ttol,
  opts)`, which accepts full path/name style input and emits an RT vlist.
  The default method is the symbolic boolweave-backed evaluator; callers can
  still force `RT_EVAL_WIREFRAME_F_BIGE` for comparison/debugging.  libbrlobol
  is now only a compatibility adapter from vlist output to the BG line-command
  arrays consumed by current Obol/GED publication.  The librt core owns
  per-call resource/vlist state, deterministic per-region aggregation, active
  region CSG state, and an RTree-backed tolerant face-pair enumerator.  Current
  profiling shows `Generic_Twin.g all` is practical, while `havoc.g havoc`
  remains a pathological thin-shell candidate-volume case; future work should
  redesign candidate generation/evaluation rather than revert the boolweave
  default.
* GED draw transactions no longer fall back to retained `_ged_drawtrees`.
  Supported draw modes must realize through Obol/libbrlobol providers or
  report an explicit provider failure.  The old `draw.c` tree walker has been
  removed from the command path; `draw.c` is now a GED command-registration
  shim for draw/redraw/E/ev/loadview/preview entry points.
* qtcad ordinary canvas painting is Obol-only.  `QgGL` renders pending
  Obol/Coin work through Qt's current `QOpenGLWidget` context for visible
  system-OpenGL presentation.  `QgSW` presents Obol offscreen readback through
  QWidget painting.  The qtcad Obol readback context manager starts from Qt's
  default `QSurfaceFormat`, requests desktop OpenGL when Qt has not selected a
  renderable type, shares with Qt current/global contexts when possible, and
  falls back to OSMesa when the platform cannot create a Qt OpenGL context.
* Embedded framebuffer display is represented as Obol scene content:
  `SoBRLImageSource` feeds an `imgstream` framebuffer stream and
  `SoBRLViewportImage` places it under the window-host controller root, so
  framebuffer updates participate in normal Obol render scheduling.
  qged's fbserv integration now installs a backend operation table whose
  implementation delegates to `BRLObolFramebufferStream` for image, view, and
  cursor state.  The qged fbserv path no longer chooses between qtcad GL and
  swrast legacy framebuffer canvases, and qged no longer has an explicit
  `dm_plugins` build prerequisite.
  GSH now uses a libged Obol fbserv bridge when an Obol DM is attached and no
  application backend is installed.  fbserv watcher threads write only stream
  state; `ged_draw_obol_framebuffer_present` publishes pending framebuffer
  state from the application update owner before render.  qged presents from
  its Qt event path, while gsh's scripted/headless delay pump presents on the
  command thread to avoid OSMesa render-thread affinity problems.  `ert` smoke
  coverage now launches real rt subprocesses through the Obol IPC framebuffer
  path in both GSH and classic MGED and verifies visible rendered framebuffer
  images.
* Preview script tree redraws route through GED draw transactions, so preview
  uses the same Obol draw providers and mode-aware draw state as normal draw
  commands.  Preview eye paths remain command-scene result overlays.
* The view-object command surface is migrated: retired public spellings
  `view obj`, `view objs`, and `view gobjs` are not aliases.  `view object`
  owns lifecycle/info/visibility/style/realize; `view annotation` owns line,
  arrow, label, and axes creation/editing; `view polygon` owns polygon
  editing; `view db` owns database display/edit-proxy insertion.
* View-object lifecycle, visibility, style, and realization route through
  object-level GED draw facades.  The command layer no longer branches directly
  between feature style and shape-ref color handling.
* User-authored line, label, and axes annotation commands route creation and
  editing through annotation-level GED draw facades.  Command code parses
  syntax only; feature-store lifecycle and retained fallback stay inside the
  draw bridge.
* Legacy TclCAD data-overlay syntax is still accepted for lines, arrows, axes,
  labels, and polygons, but draw/style/points/label/polygon-outline operations,
  movement, scaling, and pick/readback now route through typed GED data-overlay
  facades rather than command-local feature-store calls.
* Command-scene publication exists for shared line/HUD/point/face/custom-node
  features.  It supports owner-scoped replacement/removal, generation fencing,
  feature metadata, per-primitive metadata, primitive selected/highlighted
  state, child-line-layer pick resolution, qtcad resolved feature picks, and
  transaction callbacks.
* rtcheck, NIRT/qray, check overlap, GQA diagnostics, BREP/NMG debug lines,
  BREP debug indexed-face output, overlay-command uplot import, `vdraw send`,
  preview eye paths, and several simple line-set command visualizations are on
  the command-scene path.  BREP extraction remains in the BREP command; generic
  indexed-face publication is isolated in the GED command-scene bridge.
* Legacy private direct-uplot feature wrappers were removed.  qray/uplot
  diagnostics now expose stream parsing plus command-scene publication; direct
  retained line-layer replacement is only an internal no-owned-scene fallback.
* Obol draw-tree navigation is explicitly non-leaf aware: shapes may have
  child/source nodes, shape-ref context round trips preserve the exact Obol
  token including draw mode, and `group_ref_of_shape` reports the top drawn
  GED group while the explicit tree keeps nested subgroups.
* A clean BSG-free libbv scaffold is in the build and neutral librt view
  constructors now produce native/libbv-backed contexts.  Explicit `_bsg`
  constructors still cover retained fallback behavior.  Native dispatch covers
  generic view mechanics, knobs, refresh/display state records, LoD policy,
  snap settings, simple display flags, Obol scene-root attachment,
  independent-view scope state, and basic model-space measurement.  Native
  scene/interaction calls use installed adapters or return neutral empty/no-op
  results rather than implicitly creating BSG storage.
  Neutral scene, feature, polygon, and selection adapter registries now live in
  `src/librt/view_context_adapters.c` instead of the explicit BSG adapter
  implementation.  Remaining public RT view entry-point dispatch still needs
  to move out of `view_legacy_bsg.c`.
* Focused GED and qtcad Obol workflows now operate on native neutral
  `rt_view_context` storage with installed Obol adapters instead of relying on
  retained BSG side effects.  Borrowed Obol view controllers can publish
  database sources/groups and activate feature/polygon stores, and qtcad local
  views use normal RT view-context lifetime destruction.
* libdm no longer exposes or uses `dm_view_context_is_retained_legacy`.
  Display-host code that must reject opaque RT view-context pointers uses
  neutral `rt_view_context_is_valid`; `rt_view_context_is_retained` is limited
  to explicit BSG fallback identity.
* A headless libbrlobol-backed `dm-obol` plugin is available.  It owns a
  `BRLObolViewController`, renders retained Obol/Coin scenes with OSMesa for
  `screengrab`, exposes only a narrow opaque controller accessor to libged,
  and intentionally treats immediate-mode libdm draw callbacks as no-ops.
  MGED/GSH/RTWizard-style refresh code should issue high-level GED draw
  transactions and then end/capture the Obol DM frame, not drive raw
  `dm_draw_objs` streams.  MGED's Obol `dozoom` path now follows this rule by
  applying a `GED_DRAW_TXN_REDRAW`; the remaining `dm_draw_objs` call in
  MGED is quarantined as non-Obol fallback.
* `dm attach obol` now registers the libdm-owned controller with the GED Obol
  draw bridge for the target GED view rather than replacing one GED-global
  controller.  A GED session owns one authoritative shared Obol scene, while
  each attached view controller owns a local root for view-local annotations,
  polygons, independent database display, and future view-local tools.  Shared
  views render `shared-root + local-root`; independent views render only their
  local root.  Database draw/clear transactions update the shared scene for
  shared scope and the matching local endpoint for independent scope.
  View-object operations resolve local records first and then shared records
  on the GED scene owner.  The converted MGED view-state, MGED shaded-mode,
  and RTWizard display-backed tests use Obol attach plus normal `screengrab`;
  RTWizard's camera-only tests remain no-DM tests.  `gsh --new-cmds` refreshes
  through a `GED_DRAW_TXN_REDRAW` transaction and has automated coverage for
  attach/draw/autoview/screengrab/teardown plus real `ert` subprocess output
  through the Obol framebuffer bridge.
  Classic/batch MGED now honors `-c -a obol` instead of silently staying on
  `nu`, and `mged_obol_smoke` guards attach/draw/autoview/screengrab/
  teardown.  `ged_test_mged_view_state` now covers multiple simultaneous Obol
  DMs, and `ged_test_drawing_quad` covers shared/local render-root behavior.
* Clearing a view display manager detaches a matching borrowed Obol controller
  before `dm_close` deletes it.  This keeps GED teardown/zap safe when a DM
  owns the controller.
* Retained BSG fallback tests that need BSG storage must opt into explicit
  `_bsg` constructors and must justify why retained fallback coverage still
  matters.  `ged_test_tcl_overlay_bsg` has been retired; Tcl/data overlay
  lifecycle coverage now belongs in the Obol/native view-command, draw-scene,
  and draw-sync tests rather than in a standalone BSG fixture.
* Obol-only draft source-state paths now update display name, visibility,
  highlight, style/material, line-set publication, evaluated-region metadata,
  and tree-result state without requiring a retained shape-ref mirror.
* libbrlobol subtree-bounds lookup now prefers database-source nodes over
  same-path structural groups, keeping repeated transformed-instance bounds
  consistent with scene-tree summary bounds.

Known Risks
-----------

* The native view context implementation is in
  `src/librt/view_context_native.c`, and neutral adapter registries are now in
  `src/librt/view_context_adapters.c`, but many public neutral RT view
  wrappers still live in `src/librt/view_legacy_bsg.c`.  Move those wrappers
  out of the legacy file once remaining BSG fallback points are isolated.
* A librt ARB import alias/free-pattern issue is still protected by a
  libbrlobol payload-magic guard.  Do not hide this with Obol/BSG sync
  compatibility; the next diagnostic should trace allocator ownership/free
  history for the aliased external buffer.
* Legacy mesh producers that still receive transformed arrays localize points
  before Obol publication.  Keep this boundary visible until those producers
  can generate source-local geometry directly.
* Lower display-stream compatibility helpers, no-owned-scene retained adapters,
  and application display-manager paths remain legacy dependencies.  qged,
  GSH, and classic MGED have Obol/imgstream-backed fbserv bridges, but the
  protocol implementation still physically lives in libdm and stronger
  intermediate-frame image verification is still needed.  Migrate features
  away from legacy paths before adding richer behavior on top.
* Remaining live `dm_draw_objs` callers are migration signals.  MGED's Obol
  path is converted, but non-Obol MGED fallback and older draw-test refresh
  helpers still need cleanup or deletion when their coverage is replaced.
* The libged Obol bridge now separates GED-owned shared scene state from
  per-view render/local roots for borrowed Obol DMs.  The remaining hardening
  is to apply this model across no-owned-scene fallback and older application
  paths, then delete compatibility paths whose only purpose was mirrored
  BSG/DM state.
* Shared-scene LoD is no longer stored as mutable active mesh fields on shared
  nodes in the controller path.  `SoBRLViewLodGroup` installs a per-view LoD
  state for render/export/measure/snap/pick traversal.  Draw/erase/source
  transactions clear attached view LoD state, and controller mesh residency
  budgeting can evict both optional shared source arrays and view-local LoD
  payloads.  Update actions now require an explicit view state, so any caller
  still expecting direct mesh mutation should be converted rather than
  grandfathered.  See `doc/notes/brl_obol_view_lod.txt`.
* LoD request submission treats render-root database sources as logical roots.
  If a transitional render root exposes both a view-local and shared copy of
  the same database source, the controller collapses matching instance
  key/path/draw-mode identities before submitting LoD work.  This prevents
  duplicate active requests while preserving full source traversal for picking,
  snap, export, and exact-detail source matching.
* AABB/OBB draw proxy, local metadata caching, and mesh POP LoD
  generation/loading moved to libbrlobol.  The transitional librt
  `db_lod_proxy_*`, `db_mesh_lod_*`, and `rt_mesh_lod_*` APIs were removed, as
  were the per-`db_i` draw/mesh cache contexts and mesh scene-ref BSG adapter
  entry points.  AABB/OBB/metadata draw-cache operations and mesh LoD cache
  handles now share libbrlobol-owned per-cache LMDB contexts so repeated status,
  get, store, and refresh operations do not open duplicate LMDB environments.
  Mesh LoD cache payload/key access is also serialized per cache context to keep
  progressive worker reads, writes, and invalidation from racing.
* The qtcad progressive LoD test now requires multiple LoD candidates and
  multiple active view-local staged payloads at the AABB, OBB, and mesh stages,
  so the cache-backed startup path is not validated solely through the first
  realized mesh.
* The qtcad progressive LoD harness now supports parameterized draw targets,
  direct/facetized modes, phase-level startup timing diagnostics,
  `--startup-only`, `--startup-refine`, `--startup-expand`, and a
  repeated-target slow CTest.
  `test_qtcad_obol_progressive_lod_startup_refine` captures the first deferred
  leaf-proxy frame for a proxy-eligible target, promotes to the normal
  mesh-backed qtcad path, and then verifies staged AABB -> OBB -> mesh
  refinement.  `slow-test_qtcad_obol_progressive_lod_repeated_moss`
  is skipped unless `BRLCAD_RUN_SLOW_TESTS=1`, then builds a four-copy private
  moss scene and requires 24 visited LoD candidates.  Generic_Twin full-root
  startup-only is now a bounded CTest gate proving metadata-only deferred draw
  returns quickly with no realized geometry and no wireframe tessellation.
  Generic_Twin startup-expand is also gated and proves the attached LoD service
  can prewarm visible-frontier leaf AABB records, consume those cached child
  proxies in repeated post-startup passes, refresh autoview from Obol source
  bounds, and render without full leaf realization.
  Generic_Twin wire-LoD and shaded-BoT LoD are now gated and use direct Obol
  source realization for the promotion phase instead of the legacy full draw
  transaction.  m35 remains a manual optimization probe.
* Cached full-path draw metadata is available through libbrlobol, covered by
  `libbrlobol_draw_cache`, consumed by startup proxy publication, and
  invalidated through both database-index fanout for indexed full paths and
  libbrlobol cache-side object-name fanout.  The cache-side path index lets
  removal/rename notifications clear stale full-path metadata even when the
  post-edit hierarchy can no longer reconstruct the old path.
* Attached Obol controller draw, erase, stale-source, erase-prefix,
  source-update, source-reference removal, source-rename, clear, clear-scope,
  and teardown transactions now have explicit scene-state coverage proving they
  clear view-local LoD payloads while preserving the intended shared-scene
  source sync.  The remaining coverage gap is no-owned-scene fallback paths.
* Evaluated wire now defaults to the boolweave-backed evaluator, with explicit
  `RT_EVAL_WIREFRAME_F_BIGE` fallback available for comparison/debugging.  The
  public `rt_eval_wireframe` vlist/options API, requested-path identity, and
  per-region result identity are the contracts to keep.  The first dynamic
  per-region worker attempt perturbed the image baseline.  Follow-up testing
  showed multiple prepared contexts are image-equivalent when consumed in serial
  region order, so the seam is serial for now.  The opt-in boolweave
  diagnostic remains a proof harness.  The boolweave evaluator matches the
  simple evaluated-wire baseline exactly and changes rook in
  subtraction-heavy bands that appear to be improvements over historical
  Big-E output.  Avoid global "bumped" databases as the primary correctness
  strategy; keep source-boundary facts explicit and use boolweave for
  deterministic interval splitting.
* Persistent cross-refresh geometry reuse is not yet designed.  PCA/canonical
  mesh matching may help later, but it should wait until legacy draw drivers
  and cache invalidation policy are stable.
* A bounded slow ERT streaming image gate is still missing.  The current
  `NIST_MBE_PMI_3.g` build artifact is an empty database because STEP
  conversion is unavailable; `NIST_MBE_PMI_7-10.g` shows distinct intermediate
  Obol framebuffer frames during single-threaded `ert`, but it is too slow for
  the default smoke suite without an explicit slow-test gate.

Next Implementation Steps
-------------------------

1. Retire remaining caller-facing workflows that still depend on retained BSG
   or immediate libdm drawing.  Treat any hit on raw draw callbacks as a
   missing high-level Obol/GED operation, not as a reason to add an adapter
   stream to `dm-obol`.  For framebuffer work, keep protocol handling behind
   backend-neutral stream operations and move presentation into Obol hosts.
2. Convert the GED basic/LoD image tests to authoritative Obol baselines after
   proving the remaining visual differences are correct.  The LoD draw test no
   longer crashes when native Obol view contexts are active; the remaining
   failures are image-parity/baseline issues.
3. Remove or port the remaining libbsg mesh payload internals once no retained
   BSG renderer path needs them.  Any remaining `rt_mesh_lod_*`/`db_mesh_lod_*`
   hits are migration bugs.
4. Rework large-root refinement scheduling so LoD submission does not visit or
   enqueue every realized mesh when a view only needs representative staged
   payloads for the next frame.  Generic_Twin startup, startup-expand,
   wire-LoD, and shaded-BoT LoD are now bounded qtcad gates; the remaining
   scale question is automatic priority scheduling of large database
   frontiers, including duplicate-instance path identity, non-union CSG child
   handling, autoview stability/settlement as leaf bounds arrive, and cache
   population that can publish AABB/OBB/mesh data as it becomes available.
5. Extend the shared-scene/per-view-root Obol attach model to any remaining
   multi-view caller/test paths.  Primary attached mutation transaction
   view-LoD invalidation is now covered; add focused coverage for
   no-owned-scene fallback paths only where those callers still need to survive
   until removal.
6. Inventory remaining legacy draw/view fallbacks and classify each use:
   explicit retained fallback, neutral libbv-backed view mechanics, or
   libbrlobol/Obol scene/interaction behavior.  Focus first on caller-facing
   workflows.  Transaction draw no longer uses retained `_ged_drawtrees`, and
   the old `draw.c` tree walker is gone from the command path; remaining work
   should target unsupported application/no-owned-scene behavior and explicit
   retained-adapter debt.
7. Continue the RT view split: adapter registries are now in
   `src/librt/view_context_adapters.c`, but public neutral RT view wrappers
   still need to move from `src/librt/view_legacy_bsg.c` into a non-legacy
   dispatch source once fallback-only retained BSG calls are isolated.
8. Add or complete explicit Obol/libbrlobol adapters for native contexts where
   broader tests still depend on retained fallback behavior: scene clear,
   command-result lookup/removal, pick, selection, snap, polygon, faceplate,
   framebuffer/readback, and application refresh.  qged, GSH, and classic MGED
   now have Obol/imgstream-backed fbserv bridges and fast ERT smoke coverage;
   next add either an explicit slow-test gate or a shorter deterministic fixture
   for intermediate streaming framebuffer image checks in attached views, then
   add qged app-level `ert` process coverage beyond the backend operation-table
   unit test.
9. Continue moving command visualizations from generic line/HUD publication to
   typed command-result records only where it helps retire legacy behavior:
   command-specific metadata, primitive pick/highlight mapping, detail-panel
   lookup, generation fencing, and asynchronous producer teardown.
10. Continue evaluated-wire modernization behind `rt_eval_wireframe`, focusing
   on the havoc thin-shell candidate explosion: stronger geometric rejection,
   reusable leaf-pair candidate results, deterministic lower-level parallel
   candidate/ray jobs, and no further PCA/canonical matching work until legacy
   draw paths and cache ownership are structurally cleaner.
11. Revisit PCA/canonical mesh matching only after cache keys, revision inputs,
   usage counts, invalidation, and edit/update behavior are stable; use it as
   optional duplicate detection, not as a correctness dependency.
