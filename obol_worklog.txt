BRL-CAD Obol Worklog
====================

Last compressed: 2026-07-04

Purpose
-------

This file is a compact historical log for the Obol migration.  Older
turn-by-turn detail was intentionally collapsed because the root text files had
grown too large to be useful as handoff documents.  Use git history for exact
diffs and use `doc/notes/` for durable design contracts.

2026-07-04: GQA overlap command-scene migration
-----------------------------------------------

GQA overlap line output now publishes through the GED command-scene API as a
shared `gqa::overlaps` command-result line layer owned by `gqa`.  The old
neutral diagnostic line-layer path remains only as no-command-scene
compatibility fallback.  `ged_test_gqa` now initializes an owned Obol scene,
requires the published feature to summarize as command-result scene content,
and still exports the overlap line segments through the GED view-record path.

This exposed a lower-level feature-store gap: line-layer builder publication
realized Coin geometry but did not preserve the layer payload in the
BRLObolFeatureStore record.  Builder-published line layers now copy per-layer
points, commands, colors, and parent-qualified layer names into the feature
record, so command-scene, diagnostic, export, snap, and measure paths have the
same stable record data.

Focused verification passed with:
`ninja -C build libbrlobol libged ged_test_gqa test_brlobol_view_store`;
`ninja -C build ged_test_obol_draw_sync test_brlobol_view_store ged_test_gqa`;
`ctest --test-dir build -R '^(brlobol_pivot_guard|libbrlobol_view_store|ged_test_obol_draw_sync|ged_test_gqa)$' -j4 --timeout 240 --output-on-failure`;
and `git diff --check`.

2026-07-04: NIRT/qray command-scene migration
---------------------------------------------

NIRT/qray plot output now publishes through the GED command-scene helper
instead of the neutral feature importer.  The `query_ray` result family is a
shared command-result line layer owned by `nirt`, with owner-scoped prefix
removal before each shot and the same owner/role metadata used by rtcheck.
`ged_test_obol_draw_sync` covers the direct uplot-to-command-scene helper,
including shared feature publication, line-layer geometry, command-result
overlay metadata, and owner-scoped removal.

The old qray display-list work flag was removed from NIRT and from the libged
draw bridge.  That flag only mutated retained BSG shape state after a NIRT run
and had no Obol command-scene contract.  The pivot guard now treats the removed
helpers as gone instead of allowing them as part of the migrated draw surface.

Focused verification passed with:
`ninja -C build libged ged_test_obol_draw_sync`;
`ctest --test-dir build -R '^(brlobol_pivot_guard|ged_test_obol_draw_sync)$' --timeout 240 --output-on-failure`;

2026-07-04: rtcheck command-scene migration and draw-scene repair
-----------------------------------------------------------------

rtcheck's uplot overlap stream now publishes through the GED command-scene
helper instead of calling the generic feature publisher directly.  The real
command path publishes shared `rtcheck::` command-result line layers with owner
metadata, `CommandResult` overlay metadata, and owner-scoped prefix cleanup.
The helper keeps a compatibility fallback internally for non-Obol contexts, but
owned Obol views now receive command-owned scene content by default.  This
matches the current line-result behavior for nirt/rtcheck/gqa: scene-level
results are visible across views unless a command explicitly requests
view-local scope.

The uplot refactor exposed that Obol line-layer feature export was flattening a
multi-layer feature into one parent line record.  GED export now enumerates
line-layer children as per-layer line records with merged parent/layer style,
per-layer colors, and per-layer point/command readback while retaining one
owned Obol feature in the store.  This preserves existing qray/NIRT-style
color-layer record semantics and is also the right boundary for future
per-result picking/highlighting.

Direct Obol database-source draw now ensures an explicit group for the
requested root path before leaf-instance realization.  This keeps later
`ged_draw_group_ref_lookup_or_create` calls idempotent and avoids creating
retained placeholders after a direct-provider draw.  Direct mesh providers also
honor the GED primitive face-set failure test hook by publishing an empty Obol
mesh result and reporting the path handled, preventing fallback to retained
`_ged_drawtrees` from reintroducing legacy indexed-face geometry.

Focused verification passed with:
`ninja -C build libged ged_test_ged_draw_scene ged_test_obol_draw_sync test_brlobol_view_store`;
`ninja -C build ged_test_draw`;
`ctest --test-dir build -R '^(brlobol_pivot_guard|libbrlobol_view_store|ged_test_obol_draw_sync|ged_test_ged_draw_scene_typed|ged_test_ged_draw_scene_core)$' -j4 --timeout 240 --output-on-failure`;
and `ctest --test-dir build -R '^ged_test_drawing_basic$' --timeout 240 --output-on-failure`.

2026-07-04: interactive command visualization direction
-------------------------------------------------------

The nirt, rtcheck, and gqa migration target was clarified as command-owned
interactive Obol/Coin scene content rather than passive overlay drawing.
libged commands should publish owned result features with lifecycle, owner/run
identity, selectable/pickable state, and command metadata.  Typed feature
records are the first rung, not the ceiling: the longer-term command-scene API
must allow controlled custom Coin scene-object providers so BRL-CAD commands
and future user extensions can publish complex nodes, manipulators, sensors,
and callbacks while preserving Obol ownership, teardown, pick detail, primitive
highlight state, and database-edit invalidation semantics.

Feature style now carries `selectable` intent through the GED feature API and
BRLObolFeatureStore realization.  The libbrlobol view-store regression verifies
that both direct line features and child shapes of published line-layer
features honor unselectable style.

The first GED command-scene publication context was added on top of the Obol
feature store.  It can begin a command-owned scene publication, replace shared
or view-local line-layer results, remove owned result prefixes, and commit the
context.  Default scope is shared/scene-general to match current nirt,
rtcheck, gqa, and uplot-style in-scene line behavior; view-local publication is
explicit.  Shared command-result records now preserve owner metadata, and
owner-scoped prefix removal filters shared records by owner when supplied.
`ged_test_obol_draw_sync` covers an rtcheck-style shared result with selectable
style, `CommandResult` overlay metadata, command owner identity, and owned
prefix removal.

Focused verification passed with:
`ninja -C build test_brlobol_view_store`;
`ninja -C build ged_test_obol_draw_sync test_brlobol_view_store`;
and `ctest --test-dir build -R '^(libbrlobol_view_store|ged_test_obol_draw_sync)$' -j2 --timeout 240 --output-on-failure`.

2026-07-04: evaluated draw providers and retained mirror removal
----------------------------------------------------------------

GED evaluated wire and evaluated sampled-points draw modes now publish through
direct Obol database-source providers for the requested path.  Evaluated
sampled-points samples the target primitive and publishes the indexed-face
payload directly to the Obol source.  Evaluated wire now factors the old Big-E
line-set producer away from retained shape refs and publishes the resulting
line set directly to the Obol source.  The Big-E algorithm remains in libged for
now, but it has a provider boundary suitable for a libbrlobol rewrite using
librt resources and, later, deterministic per-region/job parallelism.

Successful direct Obol draw providers no longer invoke `_ged_drawtrees` as a
retained BSG compatibility mirror.  The transaction layer now counts retained
draw-tree fallback invocations, and `ged_test_obol_draw_sync` asserts that
direct hidden-line, evaluated-wire, evaluated-points, current wire, and
submodel draws do not use retained draw-tree fallback or retained shape
mutation during provider draw.

Focused verification passed with:
`ninja -C build ged_test_obol_draw_sync`;
`ctest --test-dir build -R '^ged_test_obol_draw_sync$' --timeout 240 --output-on-failure`;
and `ctest --test-dir build -R '^ged_test_drawing_basic$' --timeout 240 --output-on-failure`.

2026-07-04: direct Obol leaf-source draw and ARB shading repair
---------------------------------------------------------------

GED draw transactions now use direct Obol database-source realization for
normal database draw modes.  For wire, shaded-BoT, shaded, and hidden-line
draws, the transaction layer walks requested roots with
`db_walk_tree_leaf_instances`, publishes each full leaf path as its own Obol
database source, applies display/appearance state there, and realizes through
libbrlobol.  This keeps inherited material state and tree transforms on the
same leaf-instance boundary used by libbrlobol realization, avoiding aggregate
mode-specific sources that collapse color/material state.

`_ged_drawtrees` is no longer the authoritative publication path for these
modes.  It is now retained only for no-owned-scene compatibility, unsupported
legacy callers, and exceptional fallback when a direct Obol provider cannot
realize requested roots.  Erase paths clear both Obol authoritative sources and
any retained fallback state.

Mode 2 primitive shading exposed a separate libbrlobol issue: the hand-coded
ARB shaded mesh shortcut produced inward normals for `mk_rpp`-style ARBs,
leaving flat surfaces nearly black under GL lighting.  That shortcut was
removed; ARBs now fall through to librt tessellation like other primitives, so
ARB topology and face orientation stay owned by librt.

Focused verification passed with:
`ninja -C build ged_test_draw ged_test_obol_draw_sync test_brlobol_prototype`;
`ctest --test-dir build -R '^ged_test_drawing_basic$' --timeout 240 --output-on-failure`;
`ctest --test-dir build -R '^ged_test_obol_draw_sync$' --timeout 240 --output-on-failure`;
and `ctest --test-dir build -R '^libbrlobol_prototype$' --timeout 240 --output-on-failure`.

2026-07-04: source-local-only mesh publication bridge
-----------------------------------------------------

The generic Obol database-source indexed-face publisher in `draw_obol.cpp` is
now source-local-only.  The mode-based
`ged_obol_database_source_indexed_face_points_are_world()` compatibility
adapter was removed, so the bridge no longer guesses coordinate space from
publication mode.

Legacy transformed mesh producers in `bsg_ged_draw_source.c` now localize their
points explicitly before Obol publication.  Draft tree/evaluated producers
record the local-to-scene placement matrix when Obol placement is installed,
and transformed scene-ref primitive/NMG face-set publication uses an explicit
inverse-matrix publication path for Obol while preserving the original
transformed arrays for retained BSG fallback.

The `ged_test_obol_draw_sync` source-placement mesh regression now asserts the
direct database-source publisher contract: the caller supplies source-local
points, the mesh stores those points unchanged, and the source placement matrix
remains separate.

database-source primary geometry lives in source-local coordinates, while
`drawMatrix` carries local-to-scene placement separately.  Realized database
leaves use local shared geometry plus per-instance transforms from the

The GED sync regression covers mesh publication under source placement.  The

2026-07-03: local shared geometry and librt import guard
-------------------------------------------------------

libbrlobol database realization was moved to local-space shared geometry.  The
`db_walk_tree` callback remains the source of instance paths, inherited
material/region state, and accumulated matrices, but drawable geometry is no
longer generated from transformed callback internals.  On each realization
cache miss, libbrlobol refetches the primitive with an identity matrix, checks
the imported payload magic, builds a local geometry node, and lets each visible
database leaf reference that geometry through an explicit instance shape and
transform.

The shared-geometry cache is realization-local.  Refresh removes realized
children and releases every shared target as a unit.  Persistent reuse across
refreshes was deferred until content/revision keys and ownership counts are
explicit.

A real `box.s` ARB import poison was isolated below libbrlobol: an lldb
conditional breakpoint observed `ext.ext_buf == ip->idb_ptr` before
`bu_free_external(&ext)` in `rt_db_get_internal5`.  The libbrlobol guard avoids
using poisoned callback geometry for drawable realization, but the root-cause
investigation belongs in librt allocator/import ownership.

2026-07-03: draw basic and mode-specific realization repairs
-----------------------------------------------------------

`ged_test_drawing_basic` was brought back onto current Obol paths.  The repair
work covered polygon CSG empty-target handling, Obol-owned store clearing on
GED zap, representation-specific database sources for evaluated wire,
hidden-line, and sampled/evaluated point modes, and external geometry
publication that clears stale primary realized children while preserving
auxiliary records.

The draw-mode coverage now treats mode-specific database sources as first
class Obol database-source instances rather than demoting them to generic
wireframe.  Summary reads must select the correct source instance because
wire, shaded, evaluated wire, hidden-line, and evaluated point representations
can coexist for the same logical database path.

2026-07-03: LoD action and qtcad draw-sync hardening
---------------------------------------------------

Focused LoD update failures were traced to custom-action traversal reaching
unrelated scene-state nodes.  Export, measure, snap, and source-mesh pick
actions now skip arbitrary state nodes in generic handlers and delegate only to
groups and transforms, preserving traversal and model-matrix updates without
invoking unrelated elements.

qtcad draw-sync tests were updated for representation-specific source
ownership.  A shaded source and a shared wire source for the same path may
coexist intentionally, and source erases/adds must target their own owner
scope.

Capability 2 owner-store migration summary
------------------------------------------

GED-owned feature, polygon, and selection storage were moved toward
libbrlobol ownership:

* `BRLObolFeatureStore` tracks owner-aware feature records and typed overlay
  metadata.
* GED-owned RT feature/edit-preview facade traffic publishes through neutral RT
  adapters into Obol feature records.
* `BRLObolPolygonStore` owns GED view polygons and exposes model-point update,
  readback, fill, CSG, snap, and import/export workflows through Obol-backed
  adapters.
* `BRLObolSelectionStore` tracks owner/kind-aware selected paths and qtcad
  selection updates through neutral RT selection APIs.
* Diagnostic line-layer fallback producers moved onto a typed GED/Obol facade
  instead of anonymous retained line-layer replacement.

Retained BSG implementations remain only for unowned or legacy compatibility
contexts.  They should not be expanded as primary GED-owned behavior.

qtcad/Obol rendering and view migration summary
-----------------------------------------------

qtcad visible-content capture, pick, snap, measure, export, selection sync,
overlay sync, edit preview, and draw sync have focused Obol regression gates.
The direct Obol camera bridge uses the libbrlobol view adapter rather than
private qtcad/GED camera math.  Orthographic import treats BRL-CAD `gv_size` as
horizontal view size and maps Obol camera height to `gv_size / aspect`.

Autoview uses a separate database-source envelope query so historical padded
object framing stays distinct from tight scene/subtree bounds.
