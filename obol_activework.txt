* Python command: `python3.11`.
* Debugger: `lldb`.
* Obol source checkout: `obol/`.
* Preserve preexisting worktree changes; do not revert unrelated edits.
* Retire legacy BSG paths when they conflict with a clean Obol design.
* Keep Obol/libbrlobol boundaries explicit instead of accumulating one-off
  compatibility paths.
* Update this file and relevant `doc/notes` files when the migration plan,
  design invariant, or verification baseline changes.

Current Stance
--------------

Obol/libbrlobol is the canonical scene, view, interaction, and rendering path
for migrated BRL-CAD interactive workflows.  Retained BSG/libdm code may remain
compiled for no-owned-scene compatibility and old applications, but new
correctness work should not preserve parallel BSG ownership when an Obol answer
is clear.

The next push should favor removing remaining old-style non-Obol drawing
drivers before expanding richer Coin behavior.  Richer behavior needs only the
minimum stable contracts now: owner, scope, lifecycle, capability, style,
pick/selection identity, metadata, custom-provider teardown, and database-edit
invalidation.  Locking down every manipulator/detail-panel behavior while old
drawing paths still exist would force the design to support code paths we are
trying to delete.

Core Invariants
---------------

* Database-source primary geometry is source-local.  `drawMatrix` is placement
  metadata, not a transform baked into primary point/index arrays.
* Realized BRL-CAD database leaves use shared local geometry plus explicit
  per-instance OpenInventor transforms from tree-walk state.
* The visible leaf shape owns path identity, material/region state, selection,
  visibility, highlight, edit intent, LoD wrapper state, and export metadata
  even when drawable arrays are shared.
* LoD is view-aware.  Multiple views may choose different display/staged LoD
  for the same scene while preserving identical database, selection, edit, and
  identity semantics.
* Bounds and autoview apply transforms explicitly.  Autoview keeps the
  historical padded database-object envelope separate from tight scene bounds.
* Shared geometry reuse is action-scoped today.  Persistent reuse needs
  explicit keys, revision inputs, refcounting, invalidation, and edit behavior.
* Command-produced visuals are scene objects, not anonymous decorations.
  Shared scene scope is the default unless a command explicitly requests
  view-local results.

Current Baseline
----------------

* GED basic drawing passes through Obol capture.  Normal database draw modes
  use direct Obol providers instead of retained `_ged_drawtrees` mirrors.
* Autoview was preserved: `autoview2` calls the Obol database autoview bridge,
  and `draw_obol.cpp` exposes libbrlobol scene bounds to GED.
* Direct wire, shaded-BoT, shaded, and hidden-line draws expand requested roots
  with `db_walk_tree_leaf_instances`, realize leaf database sources, and ensure
  an explicit Obol group for the requested root.
* Repeated comb/solid instances under different transforms share local
  geometry during realization while retaining per-instance transforms and
  identity.
* Evaluated wire and evaluated sampled-points are Obol database-source
  provider outputs for the requested path.  Evaluated wire now has a librt
  core entry point, `rt_eval_wireframe(vhead, vlfree, dbip, path, tol, ttol,
  opts)`, which accepts full path/name style input and emits an RT vlist.
  The default method is the symbolic boolweave-backed evaluator; callers can
  still force `RT_EVAL_WIREFRAME_F_BIGE` for comparison/debugging.  libbrlobol
  is now only a compatibility adapter from vlist output to the BG line-command
  arrays consumed by current Obol/GED publication.  The librt core owns
  per-call resource/vlist state, deterministic per-region aggregation, active
  region CSG state, and an RTree-backed tolerant face-pair enumerator.  Current
  profiling shows `Generic_Twin.g all` is practical, while `havoc.g havoc`
  remains a pathological thin-shell candidate-volume case; future work should
  redesign candidate generation/evaluation rather than revert the boolweave
  default.
* Successful direct Obol draw providers do not invoke `_ged_drawtrees`.
  `_ged_drawtrees` remains only for no-owned-scene fallback, unsupported legacy
  callers, and exceptional direct-provider failures.
* Preview script tree redraws route through GED draw transactions, so preview
  uses the same Obol draw providers and mode-aware draw state as normal draw
  commands.  Preview eye paths remain command-scene result overlays.
* The view-object command surface is migrated: retired public spellings
  `view obj`, `view objs`, and `view gobjs` are not aliases.  `view object`
  owns lifecycle/info/visibility/style/realize; `view annotation` owns line,
  arrow, label, and axes creation/editing; `view polygon` owns polygon
  editing; `view db` owns database display/edit-proxy insertion.
* View-object lifecycle, visibility, style, and realization route through
  object-level GED draw facades.  The command layer no longer branches directly
  between feature style and shape-ref color handling.
* User-authored line, label, and axes annotation commands route creation and
  editing through annotation-level GED draw facades.  Command code parses
  syntax only; feature-store lifecycle and retained fallback stay inside the
  draw bridge.
* Legacy TclCAD data-overlay syntax is still accepted for lines, arrows, axes,
  labels, and polygons, but draw/style/points/label/polygon-outline operations,
  movement, scaling, and pick/readback now route through typed GED data-overlay
  facades rather than command-local feature-store calls.
* Command-scene publication exists for shared line/HUD/point/face/custom-node
  features.  It supports owner-scoped replacement/removal, generation fencing,
  feature metadata, per-primitive metadata, primitive selected/highlighted
  state, child-line-layer pick resolution, qtcad resolved feature picks, and
  transaction callbacks.
* rtcheck, NIRT/qray, check overlap, GQA diagnostics, BREP/NMG debug lines,
  BREP debug indexed-face output, overlay-command uplot import, `vdraw send`,
  preview eye paths, and several simple line-set command visualizations are on
  the command-scene path.  BREP extraction remains in the BREP command; generic
  indexed-face publication is isolated in the GED command-scene bridge.
* Legacy private direct-uplot feature wrappers were removed.  qray/uplot
  diagnostics now expose stream parsing plus command-scene publication; direct
  retained line-layer replacement is only an internal no-owned-scene fallback.
* Obol draw-tree navigation is explicitly non-leaf aware: shapes may have
  child/source nodes, shape-ref context round trips preserve the exact Obol
  token including draw mode, and `group_ref_of_shape` reports the top drawn
  GED group while the explicit tree keeps nested subgroups.

Known Risks
-----------

* A librt ARB import alias/free-pattern issue is still protected by a
  libbrlobol payload-magic guard.  Do not hide this with Obol/BSG sync
  compatibility; the next diagnostic should trace allocator ownership/free
  history for the aliased external buffer.
* Legacy mesh producers that still receive transformed arrays localize points
  before Obol publication.  Keep this boundary visible until those producers
  can generate source-local geometry directly.
* Lower display-stream compatibility helpers, no-owned-scene retained adapters,
  and application display-manager paths remain legacy dependencies.  Migrate
  features away from those paths before adding richer behavior on top.
* Evaluated wire now defaults to the boolweave-backed evaluator, with explicit
  `RT_EVAL_WIREFRAME_F_BIGE` fallback available for comparison/debugging.  The
  public `rt_eval_wireframe` vlist/options API, requested-path identity, and
  per-region result identity are the contracts to keep.  The first dynamic
  per-region worker attempt perturbed the image baseline.  Follow-up testing
  showed multiple prepared contexts are image-equivalent when consumed in serial
  region order, so the seam is serial for now.  The opt-in boolweave
  diagnostic remains a proof harness.  The boolweave evaluator matches the
  simple evaluated-wire baseline exactly and changes rook in
  subtraction-heavy bands that appear to be improvements over historical
  Big-E output.  Avoid global "bumped" databases as the primary correctness
  strategy; keep source-boundary facts explicit and use boolweave for
  deterministic interval splitting.
* Persistent cross-refresh geometry reuse is not yet designed.  PCA/canonical
  mesh matching may help later, but it should wait until legacy draw drivers
  and cache invalidation policy are stable.

Next Implementation Steps
-------------------------

1. Inventory remaining primary old-style drawing behavior and migrate features
   to Obol providers or command-scene features.  Keep `_ged_drawtrees` and
   retained adapters as fallback only, not as mirrors for successful Obol-owned
   transactions.
2. Continue moving command visualizations from generic line/HUD publication to
   typed command-result records only where it helps retire legacy behavior:
   command-specific metadata, primitive pick/highlight mapping, detail-panel
   lookup, and generation fencing for asynchronous producers.
3. Define the minimal richer-behavior contract now, but do not overbuild it:
   object class, owner, scope, lifecycle, capabilities, style, structured
   output, pick identity, primitive metadata, custom Coin provider lifetime,
   teardown, selection/highlight synchronization, and database-edit
   invalidation.
4. Continue evaluated-wire modernization behind `rt_eval_wireframe`: keep the
   RTree-backed face-pair enumerator, but redesign the Eplot face-geometry
   stage so thin-shell models such as havoc do not require millions of
   repeated face-pair evaluations per region.  Likely next steps are
   region-local candidate queues, stronger geometric rejection before edge
   line/plane work, candidate-result reuse for repeated leaf-pair patterns
   where transforms permit it, and then parallel queued candidate/ray jobs
   with per-thread resources and deterministic merge.  Do not spend further
   time on PCA/canonical matching until legacy drawing paths and evaluated-wire
   candidate generation are structurally under control.
5. Extend repeated-instance regression coverage into LoD, selection, edit, and
   explicit database-change behavior without retained mirror state.
6. Design persistent geometry caching only after the legacy-driver cleanup is
   further along.  Define cache keys, database revision inputs, usage counts,
   invalidation, and edit/update behavior before implementation.
7. Revisit PCA/canonical mesh matching after the cache contract is stable; use
   it as optional duplicate detection, not as a core correctness dependency.
