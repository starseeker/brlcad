BRL-CAD Obol Legacy Dependency Inventory
========================================

Scope
-----

This note is the transitional allowlist for BSG, DM, and dm_plugins
dependencies while qged/qtcad, GED/TclCAD/mged, and lower-level utility
targets move to Obol.  It records direct build rows and phase ownership.  The
Obol pivot guard checks the guarded rows below against src/source_dirs.cmake;
when a dependency is removed or added, update this note in the same change.

Guarded Direct Dependency Rows
------------------------------

These rows are intentionally exact.  They document the current direct target
dependency graph relevant to the Obol pivot:

* libbrlobol: libwdb;librt;libimgstream;libbg;libbu
* libnmg: libbg;libbn;libbu
* libbrep: libbg;libbu
* libanalyze: librt;libbg;libbn;libbu
* libimgstream: libicv;libbn;libbu
* libdm: libbsg;librt;libicv;libbn;libpkg;libbu
* libged: libbrlobol;libicv;libanalyze;libwdb;liboptical;libdm;libbsg;libbu
* libqtcad: libbrlobol;libged;libdm;libbg;libbn;libbu
* libtclcad: libged;libdm;libbn;libbu
* qged: libqtcad
* mged: libtclcad

The qged executable also has a direct CMake build dependency on dm_plugins:

* qged plugin dependency: dm_plugins

The qtcad Obol workflow test targets are guarded separately.  They may link
through transitional qtcad/GED libraries while the application is migrating,
but they must not directly link libdm, libbsg, or dm_plugins:

* qtcad Obol tests: no direct libdm/libbsg/dm_plugins link

Selected converter and simulation build targets that do not use BSG APIs are
guarded separately so stale build-only direct libbsg links do not return:

* selected converter and simulate build targets: no direct libbsg link

Current Direct Legacy-View Header Owners
----------------------------------------

The pivot guard's central production allowlist currently permits 2 direct
non-test `rt/view_legacy_bsg.h` includes.  These are retirement blockers, not
target-state dependencies:

* App/shell front: 0 TclCAD/MGED/GSH files.
* GED bridge boundary: 1 file, `src/libged/ged_view_legacy.cpp`.
* RT legacy adapter boundary: 1 librt file, `src/librt/view_legacy_bsg.c`.

The direct `libged` -> `libbrlobol` row is intentional: libged owns the
neutral GED draw transaction to Obol scene-controller bridge in
`src/libged/draw_obol.cpp`, with a public C++ attach/sync surface in
`include/ged/draw_obol.h`.  The preferred boundary is `SoBRLSceneController`:
callers may attach a borrowed controller, and libged can now create an owned
controller with `ged_draw_obol_scene_controller_ensure` when no controller is
attached.  `BRLObolViewController` attach/sync APIs are wrappers for callers
that still arrive through a view.  That bridge may use libbrlobol
scene/controller APIs, but it must not depend on qtcad/qged widget APIs or
direct BSG/DM APIs.  When libged owns the controller, GED shape-record
database-source summaries prefer Obol source summaries and fall back to the
BSG-backed source adapter only when no owned Obol source answers the query.
Shape-ref display and material summaries follow the same owned-Obol-first
path for database sources.  Public GED shape display/material setters now
write those database-source fields into the owned Obol controller first and
then update the BSG source adapter as transitional display compatibility.
GED database-change stale marking follows the same owner-first path through
`SoBRLSceneController::markDatabaseSourceStale`, and group visibility now
writes to owned Obol retained group state before the transitional BSG adapter.
Group draw-intent updates now follow that owner-first path as well:
`ged_draw_group_ref_set_mode` mutates `SoBRLSceneGroup` draw intent before the
BSG adapter is synchronized, and the same private bridge is available for
group dbpath/draw-intent path updates.  Group appearance updates now also
write the Obol-represented retained fields (line width, transparency, and
color override/color) to owned `SoBRLSceneGroup` state before storing the full
legacy appearance record in the BSG adapter.  Public GED group-record
summaries now prefer the owned Obol group for draw mode, visibility, overlay,
and transparency readback while keeping the adapter-owned path/view/scope
metadata.  Direct GED shape-source release now also removes the corresponding
owned Obol database source and prunes empty Obol draw groups before releasing
the BSG source owner.  Direct GED root path erase, path-prefix erase, and draw
clear follow the same owner-first lifecycle pattern by removing or clearing
owned Obol database sources before mutating the transitional BSG adapter.
Direct GED root group-name erase now also removes matching non-overlay owned
Obol draw groups before mutating the transitional BSG adapter.
The split GED draw-scene shard set now verifies Obol-primary database
path-state, path listing, has-path, component source rename, reference
removal, bounds, display/material, source-summary, and record-query behavior.
Those paths reconstruct nested database exposure from Obol database-source
ownership plus the GED database index instead of retained BSG source records.
The `prefix` command publishes object rename events before comb-tree redraw
events in its batch so draw reconciliation can retarget existing Obol sources
before reference updates consume the old path.
The database-source API audit now finds direct `bsg_database_source_*` and
`BSG_DATABASE_SOURCE_*` use only in `src/libged/bsg_ged_draw_source.c`, where it
is classified as transitional source-adapter/no-owned-scene legacy
compatibility.  Records, transactions, the libged Obol bridge, and
`include/ged/draw.h` are clean for direct BSG database-source API use.
The core Capability 1 closeout gate passes in this build for draw-scene shards,
`ged_test_state_services`, `ged_test_obol_draw_sync`, and
`brlobol_pivot_guard`.  The qtcad closeout subset now has a guarded swrast
path: qtcad Obol tests and `ged_test_qged_swrast` can force libbrlobol's
OSMesa context manager with `QTCAD_OBOL_FORCE_OSMESA=1`, and the focused
draw-sync, selection-sync, pick, snap, measure, and qged swrast tests pass
under that route.  System OpenGL remains a follow-up platform check, but it is
not the Capability 1 migration signal.

`SoBRLSceneController` now also exports an Obol-tagged neutral
`rt_view_scene_ref` and validates the tag before recovering controller
pointers.  This gives the neutral backing-store adapter path a libbrlobol
producer/consumer for retained scene handles without routing those handles
through BSG-only adapter conversions.

Capability 2 now has a neutral RT scene-adapter boundary.  `include/rt/view.h`
declares `rt_view_context_scene_adapter`, adapter set/get helpers, and a
neutral pick-result append helper.  The retained RT implementation dispatches
render/export consistency and semantic-path pick through that adapter before
falling back to BSG.  GED-owned views install an Obol-backed adapter that uses
Obol/GED export records and database-source paths for the `rt_view_context_*`
queries still required by existing callers.
GED-owned polygon and selection traffic now also use narrow neutral RT
adapters.  The polygon adapter resolves GED-owned polygon refs through
libbrlobol's polygon store; the selection adapter resolves selection
availability/count/clear and pick-result updates through an owner/kind-aware
libbrlobol selection store.
GED-owned feature/edit-preview traffic now uses the same narrow neutral RT
adapter pattern.  The feature adapter resolves GED-owned
`rt_view_feature_ref` tokens through `BRLObolFeatureStore` for edit-preview
overlay ensure, label ensure, style/touch, geometry replacement, clear, remove,
and lifecycle event publication, while retained BSG feature storage remains
compatibility for unowned contexts.
GED-owned feature-overlay classification now lives in
`BRLObolFeatureStore` metadata.  Tcl line/arrow/axes overlays, Tcl polygon-edit
helpers, and model annotations carry typed role/class/lifecycle/order/source
metadata in Obol feature summaries and records.  Feature-store nodes remain
`view-feature` scene records so generic Obol scene traversal cannot bypass the
owner-scoped feature iterator; scene `recordRole=overlay` is still reserved
for scene-overlay geometry owned by the overlay scene path.

The Capability 1 completion path is in closeout: libged has established an
owned Obol scene/source controller, routed the guarded GED draw-scene database
behavior family into that owner, moved neutral GED records/queries to Obol
summaries for that family, and replaced the corresponding BSG-backed
root/group/shape/source mutations with Obol owner operations.  Remaining
Capability 1 work is dependency-inventory maintenance, follow-up audit
classification of any newly surfaced database scene/source BSG use as fixed
Obol ownership, no-owned-scene legacy compatibility, public bridge/API
compatibility, or non-database Capability 2/3/4 work, plus a system-OpenGL
qtcad spot check after the passing swrast gate.

* ged retained view storage: direct `ged_gvp`, `ged_views`, and
  `ged_free_views` access is limited to the private transitional GED view

  are BSG-view-storage-free

Guard Expansion Rules
---------------------

1. New Obol-canonical files must be added to brlobol_pivot_guard.cmake rather
   than relying on this inventory.
2. New qtcad Obol workflow tests must stay direct-libdm/libbsg/dm_plugins-free.
3. Any new direct libbsg, libdm, or dm_plugins dependency must add a phase owner
