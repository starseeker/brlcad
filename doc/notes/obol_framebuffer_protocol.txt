Obol Framebuffer Protocol Boundary
==================================

Status
------

The framebuffer wire protocol is owned by libimgstream.  Its public contract
is `include/imgstream/fbserv.h`; its implementation is in the
`src/libimgstream/fbserv_*.c` modules.  This includes:

* wire message identifiers and PKG dispatch;
* session authentication and TLS server contexts;
* server, listener, and client lifecycle;
* bounded byte processing and client draining;
* backend-neutral framebuffer operation dispatch; and
* disconnect, cancellation, and cleanup state.

Neither libdm nor an application host may implement a second packet switch or
packet-handler loop.  The old `src/libdm/fbserv.c`, `src/fbserv/server.c`, and
MGED-private protocol implementation are retired.

Ownership
---------

libimgstream owns protocol semantics and transport-neutral processing.
Toolkit and executable hosts own only their event-loop integration:

* qged adapts Qt sockets and notifiers;
* libtclcad adapts Tcl channels and file handlers;
* standalone `fbserv` owns its TCP or IPC listener loop; and
* libged's generic Obol bridge owns its watcher integration for headless hosts.

Hosts feed bytes through `fbs_process_client_bytes` or let the common bounded
dispatcher `fbs_drain_client` read a ready connection.  Hosts install transport
callbacks through `fbs_set_transport` or a narrow toolkit wrapper.  They do not
call `pkg_process` for framebuffer traffic and do not inspect the backend table
or listener/client arrays directly.

libbrlobol owns presentation, not protocol parsing.  Its
`BRLObolFramebufferStream` maps framebuffer state onto imgstream storage and
Obol scene content.  libged supplies the neutral GED-to-Obol framebuffer
backend used by qged, GSH, and MGED.  qged supplies its borrowed
`QgObolWindowHost`; headless and Tk hosts use their own Obol controller.

Legacy Compatibility
--------------------

The only retained libdm protocol role is `src/libdm/fbserv_legacy.c`, a narrow
backend adapter from `struct fb` operations to `struct fbserv_fb_ops`.  It does
not parse messages, own clients, or run transports.  Standalone `fbserv` and
the remaining Tcl/MGED framebuffer-object compatibility paths may install this
adapter when they intentionally expose a legacy framebuffer.

The removed `/dev/ogl`, `/dev/wgl`, `/dev/qtgl`, `/dev/swrast`, and
`/dev/tkswrast` graphical framebuffer/display-manager paths must not be used as
embedded image presentation fallbacks.  Supported visible presentation is an
Obol window host over imgstream data.

Threading Contract
------------------

Framebuffer producers and socket watchers may update imgstream pixels,
fb-compatible cursor/view state, dirty metadata, and generation counters.
They must not mutate Coin/Obol nodes or render from a transport thread.

`SoBRLImageSource` notifications only record pending generations.  The
application update owner calls `BRLObolFramebufferStream::present` (or the
equivalent source synchronization method) before requesting a render.  qged
does this on its UI thread.  GSH and MGED do it in their command/refresh owner.
Render traversal remains read-only with respect to stream publication.

Lifecycle Contract
------------------

Authentication precedes framebuffer operations when strict authentication is
enabled.  EOF, protocol failure, and host cancellation all pass through the
same common disconnect cleanup.  A host must not close a PKG client from
inside its active PKG callback; the common server records a pending drop and
performs it after dispatch returns.  `fbs_close` cancels all clients and
releases listener, TLS, and backend state owned by the server object.

Verification
------------

`imgstream_fbserv_lifecycle_test` constructs real wire frames, delivers them
one byte at a time, verifies strict authentication and rectangle dispatch, and
checks EOF and host-cancel cleanup.  `test_qged_obol_fbserv` verifies partial
and final scan bands, resize, flush/present, and readback through the Qt host.
`gsh_obol_ert_smoke` runs a real single-threaded ERT and verifies that a
meaningful partial image advances to a substantially different complete
frame.  MGED smoke tests cover the Tcl host adapter and final ERT presentation.

Future Work
-----------

The legacy `struct fb` backend adapter may be removed once standalone fbserv
and Tcl framebuffer-object compatibility can use an imgstream-native backend.
That deletion must not move protocol behavior into libbrlobol or application
code.  Platform event-loop tests remain necessary for Windows and macOS, but
the ownership contract is platform-independent.
