BRL-CAD Obol Worklog
====================

Last compressed: 2026-07-04

Purpose
-------

This file is a compact historical log for the Obol migration.  Older
turn-by-turn detail was intentionally collapsed because the root text files had
grown too large to be useful as handoff documents.  Use git history for exact
diffs and use `doc/notes/` for durable design contracts.

2026-07-04: multi-instance transform reuse hardened
---------------------------------------------------

libbrlobol database realization now carries an internal, ref-owned geometry
cache through `SoBRLRealizeAction`.  The action first seeds that cache from
already-current realized shared geometry, then realizes stale sources.  This
keeps reuse action-scoped rather than persistent, but lets legacy GED paths
that synchronize one leaf source at a time still reuse existing local geometry
for later transformed instances.

`ged_test_obol_draw_sync` now draws a repeated comb/solid hierarchy, verifies
that transformed leaf database sources share one local geometry node, checks
local/shared geometry bounds, validates transformed source and scene subtree
bounds, exercises autoview on the transformed envelope, and erases the root
without leaking sources.  GED Obol context-token DB fullpath parsing now strips
internal `@N` instance suffixes only for DB lookup so indexed Obol identity no
longer emits `db_string_to_path` warnings.

2026-07-04: evaluated-wire resource ownership hardened
------------------------------------------------------

The libbrlobol evaluated-wire provider no longer mutates or uses global
`rt_uniresource`.  Each provider call now owns an initialized librt
`struct resource`, assigns it to the evaluation `application`, and cleans it
with `rt_clean_resource` before destroying the temporary `rt_i`.

The pivot guard now requires the explicit `rt_init_resource`/`rt_clean_resource`
lifecycle in `src/libbrlobol/evaluated_wire.cpp` and rejects any
`rt_uniresource` use there.  This keeps the provider ready for future
deterministic internal parallelization with per-worker resources.

2026-07-04: evaluated-wire provider boundary moved to libbrlobol
----------------------------------------------------------------

GED evaluated-wire realization is now a thin adapter.  `wireframe_eval.c`
resolves GED runtime/source state, calls the public
`brlobol_evaluated_wire_*` line-set API, and publishes through neutral GED
shape-ref or database-source facades.  The legacy Big-E implementation was
moved behind `src/libbrlobol/evaluated_wire.cpp`, where it owns neutral
`BG_GEOMETRY_LINE_*` command generation and has no GED/BSG scene-ref
dependency.

The pivot guard now enforces the boundary: GED may call the libbrlobol
provider and publication facades, while libbrlobol must not include GED draw
or BSG private headers.  The remaining evaluated-wire work is implementation
modernization inside libbrlobol, including optional deterministic internal
parallelization.

2026-07-04: mode-aware evaluated-source refs
--------------------------------------------

GED Obol database-source refs now preserve representation mode when multiple
sources share the same database path.  The private Obol bridge exposes
mode-aware database-source record iteration, and GED context tokens include an
optional draw-mode identity so `box.s` wire, evaluated-wire, hidden-line, and
evaluated-point refs do not collapse to the same path-only token.

`ged_draw_shape_ref_realize_context` now realizes evaluated wire/point
database sources through the direct Obol provider under the same publication
scope used by draw transactions.  Retained shape-ref evaluated wrappers remain
only as fallback for true retained scene refs.  `ged_test_obol_draw_sync` now
marks an evaluated-wire source instance stale, resolves its mode-specific
shape ref, calls realize-context, and verifies the evaluated source becomes
current rather than publishing onto the shared wire source.

2026-07-04: qtcad command-result pick integration
-------------------------------------------------

qtcad Obol pick records now carry canonical feature-store pick identity in
addition to the raw Coin detail identity.  `QgObolPickRecord` preserves the
raw child `path` and `primitiveIndex`, and adds `featureName`,
`featurePrimitiveIndex`, `featurePickResolved`, and primitive metadata copied
from the resolved Obol parent primitive.  `QgObolPick.cpp` resolves real
`SoBRLPickDetail` hits through `BRLObolFeatureStore::resolvePrimitivePick`, so
Coin hits on children such as `rtcheck::overlaps/yellow` map back to the shared
parent `rtcheck::overlaps` primitive namespace.

The qtcad point/box/ray selection filters now separate database picks from
resolved Obol feature picks.  Database picks continue through the existing
database path selection flow; resolved command-result or overlay feature picks
replace selected/highlighted primitive state on the Obol parent feature and do
not publish feature/layer names as database selection paths.  The feature-state
application helper groups picked primitives by parent feature before replacing
state, so rectangle and pick-all workflows can select multiple primitives on a
single command-result feature.

`test_qtcad_obol_pick` now publishes a shared `rtcheck::overlaps` line-layer
feature, ray-picks the real Coin VLIST child `rtcheck::overlaps/yellow`,
verifies resolved parent primitive metadata, applies primitive state through
the qtcad helper, and verifies the point-selection filter updates parent
selected/highlighted primitive state without creating database selection paths.

2026-07-04: command-result primitive pick resolver
--------------------------------------------------

Command-result line-layer child picks can now resolve back to the parent Obol
feature and the parent primitive namespace.  `BRLObolFeatureStore` exposes
`BRLObolFeaturePrimitivePick` and `resolvePrimitivePick`, first checking direct
features and then mapping `LineLayer` child names by line-segment primitive
offset.  The resolved result carries the parent feature handle/name, primitive
index, and any per-primitive metadata stored on that parent primitive.

The neutral GED view API now exposes
`ged_draw_view_context_feature_pick_primitive_resolve`.  Obol-backed views try
view-local owned features first, then shared scene features; BSG-backed views
return no result.  The helper can also set selected/highlighted primitive state
on the resolved parent feature.  `libbrlobol_view_store` covers direct local
and child-layer resolution, and `ged_test_obol_draw_sync` covers
`rtcheck::overlaps/yellow` resolving to shared `rtcheck::overlaps` primitive
0 while applying parent primitive selection/highlight state.

Command-result features now have per-primitive key/value metadata.  The
libbrlobol feature store owns `BRLObolFeaturePrimitiveMetadata` records, clears

2026-07-04: command-scene custom Coin node provider
---------------------------------------------------

The Obol feature store now has a first-class `CustomNode` feature kind and
`BRLObolFeatureStore::publishCustomNode`.  Custom features preserve the
provider-returned `SoNode` under normal Obol feature ownership, replacement,
removal, metadata, primitive-state, overlay, and summary/record semantics.
Generic metadata/style/primitive-state updates keep the custom node intact, and
typed geometry mutation helpers reject custom records instead of fabricating
VLIST geometry.

GED command-scene transactions now expose
`ged_draw_command_scene_custom_node_replace`, a C-safe provider hook that
passes feature/owner/generation/scope request metadata and treats the returned
opaque pointer as a Coin `SoNode` only inside the C++ Obol adapter.  Custom
nodes are generation-fenced, shared by default, overlay-stamped as command
results, callback-reported, and removed through the same owner-scoped cleanup
path as typed line/HUD features.

`libbrlobol_view_store` covers direct custom-node publication, replacement,
metadata/style/primitive preservation, and removal.  `ged_test_obol_draw_sync`
covers command-scene provider request metadata, shared command-result
publication, metadata, primitive state, callbacks, and owner-scoped cleanup for
`custom::node`.

2026-07-04: command-scene generation fencing
---------------------------------------------

Command-scene owners now carry an optional generation field.  The Obol feature
store tracks the newest generation seen for each command owner token/id/role,
and command-scene mutation/commit paths reject nonzero generations older than
the current owner generation.  Owner matching deliberately ignores generation
so newer command runs can still remove or replace older results under the same
owner.

rtcheck now assigns a monotonically increasing command generation to each
subprocess run and passes it through the uplot command-scene helper.  This keeps
late subprocess output from replacing a newer `rtcheck::` result while leaving
generation zero as the unfenced compatibility mode for synchronous legacy
callers.  The shared line-layer builder helper now also treats command-scene
publication or commit failure as authoritative and falls back only when no
command-scene context exists.  `ged_test_obol_draw_sync` includes stale
generation regressions using `rtcheck::generation` and
`nmg::_helper_generation`, and the pivot guard now protects the store, adapter,
rtcheck, helper, and regression tokens.

2026-07-04: rtcheck command-scene migration and draw-scene repair
-----------------------------------------------------------------

rtcheck's uplot overlap stream now publishes through the GED command-scene
helper instead of calling the generic feature publisher directly.  The real
command path publishes shared `rtcheck::` command-result line layers with owner

multi-layer feature into one parent line record.  GED export now enumerates
line-layer children as per-layer line records with merged parent/layer style,

per-result picking/highlighting.

Direct Obol database-source draw now ensures an explicit group for the
requested root path before leaf-instance realization.  This keeps later
`ged_draw_group_ref_lookup_or_create` calls idempotent and avoids creating
retained placeholders after a direct-provider draw.  Direct mesh providers also
honor the GED primitive face-set failure test hook by publishing an empty Obol

`_ged_drawtrees` from reintroducing legacy indexed-face geometry.

2026-07-04: interactive command visualization direction
-------------------------------------------------------

The nirt, rtcheck, and gqa migration target was clarified as command-owned
interactive Obol/Coin scene content rather than passive overlay drawing.
libged commands should publish owned result features with lifecycle, owner/run
identity, selectable/pickable state, and command metadata.  Typed feature
records are the first rung, not the ceiling: the longer-term command-scene API
must allow controlled custom Coin scene-object providers so BRL-CAD commands
and future user extensions can publish complex nodes, manipulators, sensors,
and callbacks while preserving Obol ownership, teardown, pick detail, primitive
highlight state, and database-edit invalidation semantics.

Feature style now carries `selectable` intent through the GED feature API and
BRLObolFeatureStore realization.  The libbrlobol view-store regression verifies
that both direct line features and child shapes of published line-layer
features honor unselectable style.

2026-07-04: direct Obol leaf-source draw and ARB shading repair
---------------------------------------------------------------

GED draw transactions now use direct Obol database-source realization for
normal database draw modes.  For wire, shaded-BoT, shaded, and hidden-line
draws, the transaction layer walks requested roots with

2026-07-03: local shared geometry and librt import guard
-------------------------------------------------------

libbrlobol database realization was moved to local-space shared geometry.  The
`db_walk_tree` callback remains the source of instance paths, inherited
material/region state, and accumulated matrices, but drawable geometry is no
longer generated from transformed callback internals.  On each realization
cache miss, libbrlobol refetches the primitive with an identity matrix, checks
the imported payload magic, builds a local geometry node, and lets each visible
database leaf reference that geometry through an explicit instance shape and
transform.

The shared-geometry cache is realization-local.  Refresh removes realized
children and releases every shared target as a unit.  Persistent reuse across
refreshes was deferred until content/revision keys and ownership counts are
explicit.

A real `box.s` ARB import poison was isolated below libbrlobol: an lldb
conditional breakpoint observed `ext.ext_buf == ip->idb_ptr` before
`bu_free_external(&ext)` in `rt_db_get_internal5`.  The libbrlobol guard avoids
using poisoned callback geometry for drawable realization, but the root-cause
investigation belongs in librt allocator/import ownership.

Capability 2 owner-store migration summary
------------------------------------------

GED-owned feature, polygon, and selection storage were moved toward
libbrlobol ownership:

* `BRLObolFeatureStore` tracks owner-aware feature records and typed overlay
  metadata.
* GED-owned RT feature/edit-preview facade traffic publishes through neutral RT
  adapters into Obol feature records.
* `BRLObolPolygonStore` owns GED view polygons and exposes model-point update,
  readback, fill, CSG, snap, and import/export workflows through Obol-backed
  adapters.
* `BRLObolSelectionStore` tracks owner/kind-aware selected paths and qtcad
  selection updates through neutral RT selection APIs.
* Diagnostic line-layer fallback producers moved onto a typed GED/Obol facade
  instead of anonymous retained line-layer replacement.

Retained BSG implementations remain only for unowned or legacy compatibility
contexts.  They should not be expanded as primary GED-owned behavior.

qtcad/Obol rendering and view migration summary
-----------------------------------------------

qtcad visible-content capture, pick, snap, measure, export, selection sync,
overlay sync, edit preview, and draw sync have focused Obol regression gates.
The direct Obol camera bridge uses the libbrlobol view adapter rather than
private qtcad/GED camera math.  Orthographic import treats BRL-CAD `gv_size` as
horizontal view size and maps Obol camera height to `gv_size / aspect`.

Autoview uses a separate database-source envelope query so historical padded
object framing stays distinct from tight scene/subtree bounds.

2026-07-04: vdraw streams as command results
--------------------------------------------

`vdraw send` now publishes line-compatible, point-compatible, and
indexed-face-compatible output through command-scene ownership as shared
`_VDRW*` command-result features owned by `vdraw`.  Lines publish as
line-layer records, points publish as typed point-set records, and faces
publish as typed indexed-face-set records.  The results carry baseline metadata
(`result.kind`, `result.format`, point counts, and index counts), stay out of
the database, and remain selectable/exportable through the normal Obol feature
store.

rather than silently inserting the payload through the legacy fallback.  The
neutral overlay geometry path remains only as fallback when no command-scene
context exists or when a payload is unsupported by command-scene publication.

2026-07-04: simple line-set command visualizations
--------------------------------------------------

GED now has a shared command-scene line-set helper for single-color command

view-context accessors, but no longer accepts direct view-context line feature

`_ged_command_scene_features_remove_prefix`, which performs owner-scoped
