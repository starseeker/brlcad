HISTORICAL COVERAGE NOTE -- NOT THE RELEASE MATRIX
===================================================

This file preserves earlier realization coverage rationale.  The current
release matrix is `obol_production_readiness.md`; current progressive
invariants are in `libbobol_lod_state_contract.md`.

BRL-CAD Obol Realization Coverage Matrix
=========================================

Scope
-----

This table tracks the production database object coverage expected from the
Obol realization path.  The current libBObol path realizes BRL-CAD .g
hierarchies through SoBRLDatabaseSource and BObolSceneController, preserving
database path identity on Obol shape nodes.  Realized database leaf instances
are local-space Obol geometry plus OpenInventor transforms: libBObol uses
`db_walk_tree_leaf_instances` for path/material/transform state.  Its callback
runs before librt imports the leaf, so libBObol performs one owned local-space
primitive import on a geometry-cache miss, builds one shared local
`SoBRLVListShape` or `SoBRLMeshShape`, and gives each visible leaf a per-instance
metadata/draw-state shape referencing that shared geometry.  Wire output is
converted from rt_obj_plot bg/rt_vlist data into SoBRLVListShape only at the
realization boundary.  Shaded output is represented by SoBRLMeshShape using
direct mesh importers where available and rt_obj_tess fallback otherwise.

The required hierarchy smoke models are:

* share/db/pinewood.g, root object pinewood
* share/db/havoc.g, root object havoc

The larger maturity candidate is share/db/faa/Generic_Twin.g.  It is the
largest in-tree example, includes valid and invalid BoTs, and mixes in
implicit solids.  qtcad now has bounded Generic_Twin startup gates for the
first cache-backed root proxy, manual post-proxy cached visible-frontier AABB
expansion passes, and automatic controller-driven startup expansion through
the normal qtcad readback path.  Full large-root startup refinement is still
not a default gate because synchronous full-detail promotion can block too
long; it should be promoted only after full-detail refinement can stay within
the same bounded provider model.

The focused CTest gates are libBObol_prototype and
test_qtcad_obol_draw_sync.  libBObol_prototype requires both staged models
to load through Obol hierarchy realization, gates shaded mesh export and
measure traversal on pinewood.g, and keeps havoc.g as the larger required
wire hierarchy traversal.  This avoids duplicating havoc.g's expensive shaded
realization in the prototype gate while retaining required shaded hierarchy
coverage.  Its wire hierarchy measure uses summary counts for coverage, and
default connected-angle measurement is covered by a sparse endpoint-bucket
regression instead of relying on a quadratic all-pairs wire scan.  Vlist
measure and snap traversal must stay linear over SoBRLVListShape command
arrays; indexed segment lookup rescans the command stream and made the
prototype hierarchy measure path scale poorly on pinewood.g and havoc.g.
GED draw transaction coverage now exercises the same leaf-instance realization
boundary for normal database draw modes: wire, shaded-BoT, shaded, and
hidden-line draws expand roots to full leaf paths and realize those paths as
Obol database sources instead of relying on aggregate BSG draw-tree
publication.  This is required for shaded modes because aggregate root mesh
sources collapse per-leaf material/color state unless they explicitly retain a
sub-instance partition.
Evaluated-points draw mode is also covered as an Obol/libBObol external
representation.  Its librt sampled-point helper now treats degenerate CLINE
sample normals as recoverable: the CLINE normal routine falls back to a radial
axis normal and otherwise returns an empty normal for the sampler to discard,
instead of aborting the process.  This keeps mode 5 usable on
Generic_Twin.g and havoc.g while preserving robust primitive behavior.
Direct provider draws also ensure an explicit Obol group for the requested
root path before leaf-instance realization.  The group is the scene/object
identity boundary for comb/root operations; leaf database sources remain the
geometry realization boundary.  Later GED group lookup must therefore find the
existing Obol group and must not create a retained placeholder after a direct
draw.
Direct mesh providers honor the GED primitive face-set failure test hook by
publishing an empty handled Obol mesh result rather than falling back to
retained `_ged_drawtrees`.  This keeps failure-mode tests tied to the direct
provider contract and prevents legacy indexed-face geometry from silently
reappearing.
Database-source realization cache ownership is internal to libBObol.  A
`SoBRLRealizeAction` clears its temporary cache, seeds it from already-current
realized shared geometry in the traversed scene, and then realizes stale
database sources.  This preserves local geometry reuse when GED or another
caller synchronizes transformed leaf instances in separate transactions, while
still avoiding a persistent cross-refresh cache until key/invalidation/refcount
policy is explicit.
After realization, `SoBRLDatabaseSource` can prepare an internal compiled
`SoCADAssembly` for eligible simple wire or mesh children.  While
explicit child shapes remain in the scene, that assembly is a render
acceleration cache keyed to the source node id and explicit children remain
authoritative for identity, editing, export, measure, snap, and exact picking.
`SoBRLDatabaseSource::compactRealizedGeometry()` can then promote eligible
whole-instance state into a compact source-owned instance index, remove the
explicit primary child shapes, and use the CAD assembly plus compact action
adapters as the aggregate representation.  The scene controller can also opt
into direct compact realization for stable simple leaf sources, which avoids
building transient explicit primary children before creating the compact
assembly.  `libBObol_prototype` gates direct wire, direct shaded, repeated
comb-instance preparation, scene-controller compact policy, compact selected
vs. unselected grouping, compact hidden/unpickable filtering, compact
BRL-aware picks, and per-primitive draw-intent fallback.  Direct leaves prepare
one part/instance, repeated transformed instances share one part with multiple
instances, whole-instance state can remain compact, and per-primitive draw
intent keeps explicit traversal.  Progressive AABB/OBB/mesh-LoD cache
promotion is now covered through view-local compact CAD payloads: source-level
LoD results bind to `BObolViewLodState`, compact database sources render the
view payload through traversal state, and the shared source is not mutated.
`libBObol_prototype` gates compact source AABB proxy and mesh payloads for
bounds and BRL-aware picking without materializing child nodes.  qtcad
progressive LoD gates the background-service path through AABB, OBB, and mesh
payload stages with rendered image checks.  The Generic_Twin
startup-auto-expand gate verifies that `BObolViewController` automatic
progressive providers can advance visible database-source frontiers during
normal qtcad rendering without explicit test-side prewarm/expand calls.
LoD-on wire realization also has a source-local optimized startup path for
high-face BoTs: it builds an immediate AABB proxy from BoT vertex bounds,
avoids full mesh realization, and lets view-local LoD payloads replace that
proxy as cache/service results arrive.
Staged mesh LoD payload copying also owns optional active normals as a
provider-neutral triangle-corner array, so normal payloads do not leak the
underlying cache container into libBObol consumers.  The mesh-LoD provider
now loads from the libBObol-owned `.DbDrawCache/mesh_lod.format` store, and

Preserved Identity
------------------

Every realized drawable Obol node must preserve:

* full database path, including combination instances
* source instance key for occurrence-specific selection and pick routing
* source revision and realized source/input/view revisions
* primitive name and type identity at shape level
* inherited region/material identity currently carried by db_tree_state:
  region id, air code, GIFT material id, LOS, material color, and shader
* face or line-segment primitive index for pick/export/snap/measure
* visibility, selectability, selection, highlight, ghost, hidden-line, edit
  emphasis, LoD policy, and color override fields

The visible instance shape owns the identity and draw-intent fields above even
when its drawable arrays come from a shared local geometry node.  Explicit
geometry setters on a visible shape detach it from the shared source,
preserving direct GED/edit mutation semantics.  LoD-backed mesh instances keep
a per-instance `SoBRLLodMeshShape` wrapper so view-specific display LoD state
can change independently of shared full-detail source geometry.
`ged_test_obol_draw_sync` now covers the same solid reached through repeated
comb instances under different transforms.  The regression requires the two
visible leaf sources to reference one shared local geometry node, keeps that
geometry in source-local coordinates, validates transformed source/subtree
bounds, verifies logical visibility/highlight transactions on the repeated
instances, checks direct source-instance stale/redraw reuse from an
already-current sibling, guards logical redraw against retained fallback state,
covers shaded shared local mesh reuse, and runs autoview against the
transformed scene envelope.
The same GED/Obol sync gate covers a comb containing two identical child
occurrences of the same solid.  Draw expansion enables librt comb instance
specifiers, publishes both occurrence-qualified source instances, reuses one
local geometry node, hides only the targeted first occurrence, and verifies a
Coin ray pick of the visible second occurrence reports the second source
instance key.

External primary geometry published to a database source follows the same
source-local rule.  Line, point, and indexed-triangle payloads must be in
source-local coordinates; `drawMatrix` remains placement metadata.  Legacy
draw-tree and scene-ref mesh paths that obtain transformed arrays localize
points explicitly before Obol publication.  The generic database-source mesh
publisher is source-local-only and no longer uses draw mode to infer point
space.

Primitive shaded realization should prefer librt-owned topology over
duplicated libBObol face tables.  ARB/RPP shaded meshes now use the generic
librt tessellation path; the removed hand-coded ARB shortcut produced inward
normals for `mk_rpp` boxes and failed the GED mode 2 drawing baseline under
lighting.

Evaluated draw modes are provider-owned Obol database-source outputs for the
requested path.  Evaluated sampled-points publishes the sampled indexed-face
payload directly to the Obol source.  Evaluated wire now has a librt core
entry point, `rt_eval_wireframe(vhead, vlfree, dbip, path, tol, ttol, opts)`,
which accepts full path/name style input and emits RT vlist line commands.
Options flags can force the historical Big-E path for comparison/fallback or
explicitly select the symbolic boolweave default.
libBObol database sources now call that librt API directly and convert its RT
vlist output into the retained Obol line shape.  The former public
`BEvaluatedWire` array adapter and its duplicate conversion path are gone;
correctness work remains behind the librt vlist API.  The default evaluator is
the symbolic boolweave path.  It owns per-call librt resource/vlist state
rather than using `rt_uniresource`, exports typed line records only at the API
boundary, and aggregates per-region results in deterministic ordinal order
with debug names retained for diagnostics.  Dynamic per-region worker
evaluation is intentionally gated off after changing the image baseline; two
prepared contexts are image-equivalent when evaluated in serial region order,
so the next cleanup should preserve region-order semantics while isolating
candidate generation from ray/classification work and parallelizing queued ray
jobs with per-thread resources and deterministic merge.  The current proof
harness can be enabled with `BOBOL_EVAL_WIRE_BOOLWEAVE_DIAG=1`.  The
boolweave evaluator injects known source-surface intervals, uses boolweave
interval splitting plus ternary CSG state, matches the simple evaluated-wire
baseline, and changes rook in subtraction-heavy bands that appear to be better
than the historical Big-E result.  The current candidate pipeline uses a
tolerant RTree face-pair enumerator; `Generic_Twin.g all` is practical, but
thin-shell models such as `havoc.g havoc` need a redesigned candidate
generation/evaluation stage rather than a return to the historical Big-E
default.

Standalone material-object identity, first mesh edge/vertex action identity,
and typed edit-preview intent identity across pick/snap/measure/export are now
covered.  SoBRLEditPreview can publish explicit edit-intent id/role metadata
separate from preview-node identity, while preserving the old preview-id
fallback.  The supported edit lifecycle is now covered from begin/motion and
snap through authoritative preview replacement, accept/reject, selection
change, database mutation, modifier/focus cancellation, plugin reuse, and
active-edit teardown.  MGED and QGED application policy invokes one endpoint
action and QGED editors explicitly commit, reset, or cancel their retained
preview during lifecycle transitions.  BOT face and vertex interaction uses
stable database indices and forces exact indexed detail when required.  The
currently supported ellipsoid, extrusion, and revolve editors expose
primitive parameters rather than tessellated face/edge/vertex selection, so
there is no curved tessellation sub-identity to preserve today.  Any future
curved sub-object tool must either define persistent IDs or request exact
full-detail representation before it becomes supported.

Librt Leaf-Import Ownership Boundary
------------------------------------

The former defensive second primitive import is gone.  Drawing realization
uses the public `db_walk_tree_leaf_instances` traversal, whose callback receives
the full path, accumulated tree state, and leaf directory entry before librt
imports a primitive.  On a cache miss libBObol performs the only primitive
import, with no instance matrix, owns that `rt_db_internal` until geometry has
been copied into the cache, and releases it on every exit path.  The accumulated
`tsp->ts_mat` is retained separately as occurrence placement, including nested
and repeated instances.

This boundary was introduced after a transformed callback internal was observed
to alias storage released by the traversal import path.  It removes that
callback-internal lifetime from the contract instead of attempting to validate
or repair a borrowed internal.  Payload magic is still checked as input
validation; a successfully imported but invalid payload is owned and freed
before the leaf is rejected with a diagnostic.

Draw-Test Realization Findings
------------------------------

After separating polygon, text, and axes raster tolerances, the draw-mode
realization failures in `ged_test_drawing_basic` have been brought onto
first-class Obol/libBObol paths:

* v022, `draw -m3 all.g`: passes through direct evaluated-wire publication.
  GED draw mode 3 is represented as a mode-specific Obol database source
  (`REPRESENTATION_EVAL_WIRE`) and realizes via `draw_m3`/bigE output instead
  of falling back to ordinary primitive wireframe.
* v023, `draw -m4 all.bot`: passes through hidden-line mesh rendering.
  GED draw mode 4 is represented as `REPRESENTATION_HIDDEN_LINE`; libBObol
  realizes the database source as mesh and renders an invisible depth-fill pass
  followed by a polygon-offset line overlay so coplanar mesh edges survive
  without exposing occluded back edges.
* v024, `draw -m5 all.g`: passes through sampled-face-set publication.
  GED draw mode 5 is represented as `REPRESENTATION_EVAL_POINTS`; the Obol
  source receives the sampled indexed-face-set mesh and uses the published
  geometry bounds for autoview.  External mesh publication replaces any
  generic database-realization primary children so stale unevaluated mesh
  geometry cannot leak into the sampled/evaluated source.
* v026, `draw -m3 scene.g` on rook.g: passes after evaluated-wire external
  publication updates source bounds from the realized geometry and replaces
  generic primary VLIST children.  This avoids autoview framing against stale
  pre-evaluation database bounds and prevents Boolean tool-solid wireframes
  from rendering beside the evaluated result.

Mode 1 shaded BoT/polysolid, mode 2 unevaluated shaded, mixed
shaded/wireframe cases v020, v021, and v025, and the mode-specific v022-v024
and v026 cases now pass the current OSMesa-backed Obol image gate.  Future
changes should preserve the representation-mode split rather than collapsing
non-shaded database sources back to generic wireframe realization.
The evaluated-mode regression case to guard against is applying generic
display settings after creating a mode-specific source: the underlying
libBObol draw mode is still wireframe for evaluated wire and point modes,
but the exact `REPRESENTATION_EVAL_WIRE` or `REPRESENTATION_EVAL_POINTS`
state must remain authoritative.  GED display mutations that know an exact
GED draw mode must update the source representation explicitly, and
libBObol draw-mode-only mutations must not demote existing non-simple
representations.  Summary reads also need to use the selected database source
instance, not the first source sharing the same logical database path, because
wire/shaded/evaluated mode sources can coexist during a transaction.
GED Obol shape refs must preserve the same representation-mode identity:
mode-specific refs carry an explicit draw mode in their Obol context token,
and evaluated shape-ref realization enters that mode's publication scope
before calling the direct evaluated provider.
External GED primary geometry publication has an additional hardening contract:
line, annotation, point, and indexed-face publishers clear existing primary
realized children on the target `SoBRLDatabaseSource` before installing the new
external payload, while preserving auxiliary VLIST/source children.  This is
covered by `SoBRLDatabaseSource::clearRealizedGeometry` in libBObol and by the
current `ged_test_draw` Obol image gate.

Transform-specific hardening added a focused `ged_test_obol_draw_sync`
regression for mesh publication under source placement.  The test sets a
non-identity source placement, publishes a source-local mesh payload, and
verifies that the resulting `SoBRLMeshShape` stores those source-local points
while the database source keeps the placement matrix.  This protects the direct
publisher contract; transformed legacy producers are covered by the draw-mode
image gates.

Further Representation Work
---------------------------

1. Preserve the `GED_DRAW_MODE_EVAL_WIRE`, `GED_DRAW_MODE_HIDDEN_LINE`, and
   `GED_DRAW_MODE_EVAL_POINTS` representation paths in qged/qtcad integration
   work, including source bounds updates from external geometry publication.
2. Keep the existing repeated-solid/comb, bounds, autoview, selection/edit,
   duplicate-occurrence, and CSG identity regressions when adding new instance
   representations.
3. Keep persistent draw/LoD cache keys, object/path invalidation, database
   replacement, and cross-refresh lifetime rules centralized in libBObol.
4. Promote BREP and BSpline/NURB shaded rows from diagnostics to stable native
   or tessellated representation when the underlying converters are reliable.
5. Promote diagnostic/fallback rows such as BREP, legacy HF, annotation, and
   point-clouds to native Obol representations where that adds stable user
   value.
6. Extend stable edge/vertex identity only when a future native or tessellated
   curved editor actually exposes those sub-entities; do not invent identity
   for parameter-only tools.
7. Keep the bounded Generic-Twin metadata-only startup, automatic background
   expansion, mixed implicit/mesh identity, proxy-to-compact handoff, and
   repeated-scene stress gates as the production scheduler evolves.
8. Continue optional large-draw optimization at the measured rendering
   bottleneck: retained GPU buffers or batching may improve VList submission.
   Do not restore GED publication replay or render-time root aggregation; the
   current retained source/index path already makes redraw effectively free.
