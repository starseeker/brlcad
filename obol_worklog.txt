BRL-CAD Obol Worklog
====================

Last compressed: 2026-07-05

Purpose
-------

This file is a compact historical log for the Obol migration.  Turn-by-turn
detail was intentionally collapsed because the root text files had become hard
to use as handoff documents.  Use git history for exact diffs and `doc/notes/`
for durable design contracts.

2026-07-05: Clang 21 strict-warning hardening
---------------------------------------------

The active build is now clean under FreeBSD clang/clang++ 21.1.8 with the
project's strict `-Werror` settings.  The libfort warning was fixed directly:
`src/libbu/fort.h` now exposes `ft_wchar_t` so C++ callers still use

consistently.  Related libbu C++-compat fixes include explicit const-null
returns in `path_normalize.c` and C++ literal-operator spelling cleanup in

removed instead of patched because it only exercised retained BSG adapter

The IGES converter also had actual correctness hazards surfaced by the newer
compiler.  `iges/main.c` includes the converter extern contract before defining

2026-07-05: Obol framebuffer dirty/present split and GSH ert smoke
------------------------------------------------------------------

Hardened the Obol framebuffer bridge around a read-only render traversal.
`BRLObolFramebufferStream` no longer mutates Coin/Obol scene nodes from pixel,
view, cursor, or protocol write operations.  Those operations update
`imgstream` and fb-compatible state only.  `BRLObolFramebufferStream::present`
is now the explicit update-phase operation that refreshes `SoBRLImageSource`,
syncs `SoBRLViewportImage`, and applies framebuffer view/cursor state.

`SoBRLImageSource` stream dirty callbacks no longer write Inventor fields.
They update only an atomic pending-generation marker, exposed through
`hasPendingStreamUpdate`; explicit refresh/present calls consume the stream
state on the application/update owner.  The coarse
`BRLObolViewController` scene-graph mutex added during earlier crash
debugging was removed because render threads should be read-only and the
mutex caused controller teardown assertions.

qged now presents pending framebuffer stream state from its Qt update callback
before requesting a view refresh.  libged now has an Obol fbserv bridge for
non-Qt hosts with `ged_draw_obol_framebuffer_present` and
`ged_draw_obol_framebuffer_release`; `screengrab` presents pending framebuffer
state before asking the DM for an image.  GSH releases the bridge before
closing attached Obol DMs.

GSH `ert` support was shaken down for the headless Obol DM.  fbserv watcher
threads remain dirty publishers only.  Rendering remains on the command thread
because the OSMesa-backed dm-obol renderer is thread-affine in this setup; the
gsh-local `delay sec usec` pump now periodically drains subprocess output and
applies view/framebuffer updates on that thread using wall-clock timing.

2026-07-05: qged fbserv backend isolation
-----------------------------------------

Introduced a backend-neutral fbserv operation table in libdm so the wire
protocol no longer has to call directly through `struct fb` operations.  The
legacy `struct fb` path remains as the compatibility backend, while new hosts
can install their own framebuffer implementation and expose size, pixel,
cursor, view, colormap, flush, poll, and help operations.

qged now installs an Obol/imgstream framebuffer backend for embedded
framebuffer traffic.  The bridge opens an `imgstream` framebuffer sized to the
active `QgView`, attaches it to the Obol window-host framebuffer scene
placement, forwards fbserv pixel updates into the image stream, and schedules
normal qtcad view refresh.  The pixel/view/cursor lifecycle is now factored
into libbrlobol as `BRLObolFramebufferStream`, leaving qged with thin fbserv
operation shims plus Qt sizing/refresh notification.  The qged fbserv path no
longer chooses qtcad GL versus swrast legacy framebuffer canvases, no longer
depends on `dm_plugins`, and does not overwrite libdm's per-client protocol
state with a raw framebuffer pointer.

The design decision for libdm retirement is recorded: fbserv packet/protocol
handling should eventually move to a small framebuffer/image-stream protocol
library beside libimgstream/libicv, while libbrlobol owns only Obol scene
presentation, interaction, and lifecycle for the resulting image stream.

2026-07-05: draw/qtcad Obol presentation cleanup
------------------------------------------------

Removed the retained `_ged_drawtrees` fallback from GED draw transactions and
removed the old `draw.c` tree walker from the command path.  `draw.c` is now a
GED command-registration shim for draw/redraw/E/ev/loadview/preview entry
points; supported transaction draw modes realize through Obol/libbrlobol
providers or report explicit provider failure.

qtcad ordinary canvas painting is Obol-only.  `QgGL` renders pending Obol/Coin
work through Qt's current `QOpenGLWidget` context for visible system-OpenGL
presentation, while `QgSW` presents Obol offscreen readback through QWidget
painting.  The qtcad Obol readback context manager now starts from Qt's default
`QSurfaceFormat`, requests desktop OpenGL when Qt has not selected a renderable
type, shares with Qt current/global contexts when possible, and falls back to
OSMesa when the platform cannot create a Qt OpenGL context.  Embedded
framebuffers are represented as Obol scene content via `SoBRLImageSource` plus
`SoBRLViewportImage` under the window-host controller root.

The stale `ged_test_qged_swrast` and display-manager backend benchmark
sources/tests were retired.  The GED draw command macro was restored to the
scanner-standard `X, XID` form, and a CMake reconfigure regenerated wrappers
including `ged_exec_draw` and `ged_exec_redraw`.

2026-07-05: Generic_Twin wire/shaded LoD hardening
--------------------------------------------------

Generic_Twin large-root LoD coverage now avoids the legacy full draw
transaction for the expensive promotion phases.  The wire startup-LoD test
still begins with a deferred metadata root and bounded visible-frontier leaf
AABB proxy expansion, but full wire promotion now installs a direct Obol
database source and realizes it through libbrlobol.  That removed the prior
multi-minute libged transaction stall.  The same test verifies staged
view-local AABB, OBB, and mesh LoD payloads, rendered image changes, centered
wire output, and `view lod mesh 0` clearing active view-local payloads while
returning to full-detail wire drawing.

Wire-mode BoT LoD now renders mesh payloads as triangle edges instead of
falling through to shaded triangles.  BoT mesh import is prioritized ahead of
generic indexed-face/tessellation paths, so BoT wire/shaded LoD uses the mesh
already present in the primitive.  Non-BoT wire-mode mesh-role sources stay on
vlist plotting to avoid accidental tessellation.

The shaded Generic_Twin gate uses shaded-BoT representation.  libbrlobol now
treats shaded-BoT like wire mode for non-BoT leaves: non-BoTs remain vlist
wire geometry while BoTs become mesh shapes.  This keeps the large-root
shaded test bounded and avoids NMG/CSG tessellation failures such as `half`
primitive tessellation while still exercising shaded BoT mesh LoD.

`view lod` now notifies attached Obol views directly.  For Obol-attached
views, policy changes clear `BRLObolViewLodState`, advance the view LoD policy
revision, refresh source realization view policy, and request an Obol render
instead of calling legacy `redraw`.  Non-Obol views still fall back to redraw.

The libbu LMDB cache wrapper now opens environments with `MDB_NOTLS`, tying
reader slots to transaction objects rather than worker threads.  This removed
`MDB_BAD_RSLOT` failures when BRLObol LoD worker threads concurrently queried
and populated `.DbDrawCache`.

The shaded Generic_Twin LoD gate initially timed out after the mesh stage.
`lldb` showed the main thread blocked in `BRLObolLodService::stop`, with LoD
workers contending inside mesh-LoD cache context creation and one worker
calling `bu_mkdir("")`.  The cache path setup now rejects empty directory
creation, skips explicit creation of an empty cache root, and makes
`bu_cache_open` build relative component paths under `.` when `BU_DIR_CACHE`
resolves empty.  The shaded LoD gate now completes in about 2.7 seconds, with
service shutdown taking milliseconds.

2026-07-05: leaf-only proxy expansion and Generic_Twin wire startup

2026-07-05: service-backed bounded frontier post-proxy expansion
---------------------------------------------------------------

Added a GED/Obol bridge API for bounded direct-child database-source expansion
after a deferred startup source is present.  The bridge resolves the requested
path through the GED database index, expands direct union children without
calling the full leaf-realization path, applies each child's path placement
matrix, and publishes cached child leaf AABB proxy line sets as source-local
external primary geometry.  It intentionally consumes libbrlobol draw-cache
records rather than refreshing missing subtree AABBs inside the expansion call,
so large-root expansion stays cache-driven instead of blocking on database
walks.
Duplicate direct-child instances and non-union CSG children are skipped until
explicit instance identity and CSG-aware partial visualization rules are
designed.

Added a companion GED/Obol prewarm API that submits bounded direct-child AABB
proxy tasks through the attached `BRLObolLodService`.  Those tasks refresh
libbrlobol `.DbDrawCache` records on worker threads and do not publish
view-LoD payloads.  The application/render thread can then call expansion to
consume ready cache records and mutate the Coin scene.

The direct-child API is now wrapped by visible-frontier APIs that collect the
current database-source frontier under a requested root and repeat the same
bounded prewarm/expand step for each visible source.  This keeps cache
population on worker threads while allowing the render/application thread to
advance recursive proxy refinement in explicit, bounded passes.

`test_qtcad_obol_progressive_lod` now has `--startup-expand`, and CTest
registers `test_qtcad_obol_progressive_lod_generic_twin_startup_expand`.  The
Generic_Twin case draws `all` with deferred leaf expansion, captures the root
metadata-only startup frame, then runs service-backed visible-frontier passes.
The original direct run reached `sources=1->25`, `depth=1->3`, and
`proxies=24`; later leaf-only hardening changed the expected startup frame to
metadata-only for comb roots and verifies rendered output after leaf proxy
publication plus autoview refresh.

2026-07-05: path-aware draw metadata cache and startup consumption
------------------------------------------------------------------

The libbrlobol draw cache now has full-path aggregate metadata records in
addition to object-local metadata records.  `brlobol_draw_path_metadata_*`
status/refresh/invalidate/store/get APIs use exact full-path cache keys, and
refresh derives inherited region id, air, material id, LOS, color, shader, and
inheritance state from `db_follow_path_for_state` rather than duplicating
tree-walk rules.

`libbrlobol_draw_cache` now builds a top-comb/region/leaf fixture proving that
object-local leaf metadata remains plain while full-path metadata captures the
inherited aggregate draw state.  The same test covers reopen persistence,
exact path invalidation/refresh, whole-database clear, and null/error handling
for the path metadata API.

Startup proxy publication now consumes full-path metadata when cached proxy
geometry is shown before full leaf expansion.  The GED/Obol bridge applies the
cached region, air, material id, LOS, and shader fields to the external-primary
proxy shape while preserving existing display-state material override
precedence.  Attached views use the same mode-scoped database-source instance
lookup as proxy publication, so metadata is applied to the source instance
that actually owns the startup proxy geometry.

GED database-index invalidation now also clears exact full-path metadata keys
for indexed paths containing a changed object.  This covers leaf edits, reused
ancestor paths, and comb metadata changes that affect descendant inherited
state.  A libbrlobol path-index side record now lets object-name invalidation
scan and clear cached full-path metadata entries containing the changed object
name, covering destructive removal/rename cases where the post-edit index may
no longer reconstruct the stale full path.

2026-07-05: qtcad startup-refine progressive LoD coverage
---------------------------------------------------------

The cache ownership answer remains libbrlobol: persistent draw proxy,
metadata, and mesh POP LoD payloads live under `BU_DIR_CACHE/.DbDrawCache` and
are versioned/invalidated by libbrlobol, not librt.  librt remains the source

snap, pick, export, measure, and exact source matching.

changed the evaluated-wire image baseline.  Follow-up diagnostics forced two
worker contexts, serialized full region evaluation, and then evaluated regions
serially while alternating contexts.  Alternating contexts in region order

2026-07-05: GED/DM LoD service integration and Obol draw sync hardening
-----------------------------------------------------------------------

The progressive LoD notification model is currently implemented in
libbrlobol, not librt.  `BRLObolLodService` owns worker threads, accepts
source/cache-backed LoD requests, and exposes a result-ready subscription.
That callback is only a notification: `BRLObolViewController` marks pending
results, and the application/DM render path explicitly drains and applies
results with the view-local `BRLObolViewLodState`.  librt remains the
deterministic provider/cache layer and does not mutate Coin scene state or
drive application event loops.

Added shared libged controls for this service through
`view lod service status|start|stop|poll`.  The Obol DM backend now submits
view LoD requests and drains pending results from its render path when
auto-submit is enabled, matching the intended "draw now, refine as background
results arrive" behavior while keeping each attached view's LoD state
independent.

The Obol draw bridge was hardened in several places needed by that model:

* owned scene controllers now always ensure the GED transaction observer;
* independent view transactions are no longer skipped when they target
  source owners in the shared scene;
* redraw/source-stale handling re-realizes evaluated-wire and evaluated-point
  external representations under the correct publication scope;
* mesh-LoD publication now creates `SoBRLLodMeshShape` instances instead of
  plain mesh shapes, so service submissions recognize them as LoD-backed;
* database-source realization policy changes update identity/staleness state;
* polygon lookup handles names containing `::` correctly.
