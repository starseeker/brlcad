BRL-CAD Obol Drawing: Remaining Work
====================================

Purpose
-------

This is the operational backlog for finishing the Obol/libbrlobol drawing
migration.  It records verified behavior, open defects, and the next required
work.  It is not an implementation history or benchmark log.  Put durable
design rationale in doc/notes/ and performance captures in .build_perf/.

Architecture Invariants
-----------------------

* Obol is the only graphical scene and rendering path.  Do not add a libdm,
  libbsg, OGL, WGL, or application-local scene fallback.
* A hosted GED view has one GED view context, one display endpoint, one Obol
  controller, and one factory-owned host identity.  Applications own native
  windows and event loops, not parallel renderer or scene lifetimes.
* libbrlobol owns BRL-CAD realization, retained drawing features, picking,
  selection, edit previews, compact occurrences, and view-local LoD.  libbv
  remains passive view state only.
* Tk and Qt hosts own native context/widget and pixel presentation only.
  Endpoint/host-factory code owns lifecycle, resize/DPI propagation, renderer
  policy, capture, framebuffer composition, progressive presentation, and
  callback shutdown.
* The endpoint property registry is the only production renderer-policy
  surface.  dm get/set may expose it while retained, but may not recreate
  backend option tables or bu_structparse renderer state.
* Explicit renderer requests fail if unsupported.  They never silently select
  another engine.  FAST and QUALITY are software-wire policies, not engines.
* Remove a compatibility adapter when its final caller moves.  Update the
  caller inventory and its tests in the same change.

Recent Compatibility Cleanup
----------------------------

MGED's framebuffer-server transport now uses the session-owned Tcl interpreter
directly.  It no longer queries a display-manager shell merely to find the
same interpreter; the remaining framebuffer bridge is explicitly tracked as a
separate ownership migration.

MGED no longer owns a `struct dm`, opens a null display manager, or keeps a
per-display `struct fb`/fbserv object.  Its `mged_display` record is
application view and input state only, not a graphical compatibility boundary.
Attachment opens the `tkobol` endpoint,
and external image rendering plus the framebuffer listener use the
session-owned GED Obol/imgstream backend.  MGED does not directly link
libdm.  The pivot guard and headless/Tk attachment smokes cover this boundary.
Its GUI script names `tkobol` directly; the fake Tcl `dm_bestXType` and
`dm_validXType` selectors are deleted rather than preserving a one-option
display-manager discovery surface.

rtwizard no longer links libdm or requires DM plugins.  Its embedded ArcherCore
view uses the TclCAD/GED `tkobol` endpoint path, and GUI raytrace previews now
use that view's session-owned Obol/imgstream IPC stream with overlay
composition rather than a separate OGL/WGL framebuffer window.  Headless/file
output remains an independent in-memory imgstream workflow.

QGED's framebuffer adapter no longer owns a parallel Qt/Obol bridge.  Libged
selects the active display endpoint's existing host when it installs the
session framebuffer stream and publishes retained image updates there; QGED
only maps TCP/IPC readiness to its Qt event loop and requests a repaint.  The
generic path retains capture-provider cleanup when a stream moves between
views, and QGED clears its non-owning adapter target before GED destroys the
fbserv session.

The unused Qt namespace-alias and global-namespace compatibility headers are
deleted.  Qt callers use the direct public API, and the pivot guard prevents
those compatibility surfaces from returning.

Qt's public view, quadrant, tree-interaction, and combination classifications
are enum classes.  The integer aliases were deleted; QgView and QgQuadView
accept typed values, and the pivot guard rejects restoration of the old names.

TclCAD no longer directly links libdm, owns a `struct fb`, or keeps a per-view
fbserv shell.  Its Tk factories retain opaque factory-host instances, while
libged owns the one session Obol/imgstream bridge.  The bridge binds its
capture provider to the active or explicitly selected output endpoint and
clears it before moving to another view.  TclCAD supplies a notifier fallback
only when the bridge has no endpoint-owned worker transport.  The Tk widget,
Archer four-pane, and MGED framebuffer lifecycle tests cover this boundary.

Standalone `rt` and `fbserv` use the toolkit-neutral libbrlobol display-session
API for visible legacy device names.  At CMake configuration they directly
link one toolkit provider: QtCAD is preferred, with TclCAD as the fallback.
Their small `#ifdef` selector includes only that library's C-compatible
registration header; neither application calls raw Qt, Tcl, or Tk APIs.
`fbserv` polls the session from its existing service loop.  `rt` runs each
visible-display frame through the display-session runner: ray work executes on
a worker while the opening thread polls the native session.  Pixel callbacks
only coalesce a frame request; retained image synchronization and toolkit
dispatch remain on the owner thread.  If neither Qt nor Tcl/Tk is built,
visible device specifications fail explicitly and non-window imgstream targets
are the supported headless choice.  `/dev/null` remains the explicit
no-presentation diagnostic sink for raytrace benchmarks; it retains only
framebuffer compatibility metadata, allocates no imgstream image or pixel
buffer, does not initialize a provider, and causes rt to skip framebuffer
I/O.  Both software and System-GL Qt provider selections have Xvfb smoke
coverage, and the toolkit-neutral session contract verifies the same
owner/worker split without either toolkit.

Verified Baseline
-----------------

The following was verified locally from the current checkout and .build:

* Legacy ISST CPU image presenters are independent of graphical display
  managers.  Tcl/Tk `isst` presents RGB frames through a Tk photo, while Qt
  `qisst` uses a worker-produced `QImage` and QWidget.  Both have Xvfb smoke
  coverage; neither target requests libdm or a Qt OpenGL module.

* libbrlobol unit coverage passes 15/15 tests.  This includes endpoint and
  host lifetime, headless host, render, LoD realization/service/cache,
  view-store, image source/display, and NanoRT renderer coverage.
  Factory-owned headless presentation realizes pending sources, advances
  progressive work, preserves the requested frame reason, and retains a
  pending frame while progressive work remains.
* GED/Obol integration passes ged_test_obol_draw_sync,
  ged_test_mged_view_state, and ged_test_drawing_basic.
* Qt's direct-context build covers endpoint/controller ownership, Qt GL and
  software hosts, draw/faceplate/selection synchronization, picking, edit
  preview, real-model wire and shaded interaction, and progressive LoD on
  Generic Twin.  QGED, qsketch, all Qt Obol test binaries, and the focused
  non-slow test set build after removal of the old Qt view wrapper.
* GSH headless basic, ERT, and progressive-LoD smoke tests pass.  GSH binds
  its standard headless host factory, framebuffer composition is synchronized
  into the common render root, and ERT exposes partial then final output.  The
  deliberately delayed LoD diagnostic accepts either AABB or OBB as its
  coarse representation before a final mesh payload; normal first draw remains
  free to use final data whenever it is already ready.  MGED headless smoke,
  ERT, and progressive-LoD smoke tests pass.
* TclCAD's command, cleanup, Tk thread-affinity, widget, and Archer four-pane
  lifecycle tests pass under Xvfb.  The session framebuffer bridge is checked
  across top-level, embedded, and software Tk hosts; creating an auxiliary
  pane does not retarget the active stream.  Their shared Xvfb preflight marks
  only an unavailable display server as infrastructure-skipped; once it starts,
  product failures remain test failures.
* MGED's isolated-X attachment smoke opens and resizes a direct hardware
  `tkobol` endpoint, delivers a shifted primary-pan gesture to its child
  widget, captures a frame, and releases the host.  Tk input now uses a
  host-unique bindtag bridge rather than an X11-only raw-event callback, so
  Windows WGL uses the same normalized endpoint path.  Native Windows and
  macOS runtime validation remains supported-matrix work.
* QGED's framebuffer test shares the visible endpoint/controller with GED and
  verifies that libged's generic ensure path selects that host, retained overlay
  attachment, physical resize, packet-driven presentation, active-pane host
  handoff, and detach.  A handoff removes the retained image nodes from the old
  controller and recreates them at the new endpoint's physical size.  QGED
  retains only its Qt socket/notifier adapter.  The generic host test verifies
  retained underlay, interlay, and overlay placement.  GED's per-view render
  root is ordered shared geometry, interlay, then local faceplate/interactive
  features; the controller keeps the same interlay root valid for direct hosts
  and GED rebinding.
* Background policy is endpoint-owned after attachment.  A passive `bv`
  background seeds a newly attached GED endpoint or a newly created standalone
  Qt canvas exactly once; normal Qt refresh, framebuffer capture, and endpoint
  re-registration cannot overwrite it.  TclCAD's public `bg` command reads
  and writes the typed controller background properties.  This is covered by
  GED endpoint, Qt controller, and Tk widget smoke tests.
* Normal drawing controls use composed Obol render roots.  Their runtime cache
  is isolated from extracted APNG controls; basic, faceplate, LoD, selection,
  quad, and AET tests are registered and pass in the main checkout.
* Deferred draws retain independently requested modes until each realizes;
  mixed shaded/wire drawings no longer leave an earlier root proxy visible.
  The renderer uses a small polygon offset so coplanar wire overlays remain
  visible over separately published shaded sources.
* `libbrlobol_window_host` exercises factory capability selection, resize/DPI,
  capture, input isolation, simultaneous endpoint teardown, and a blocking
  in-flight frame callback.  Endpoint destruction waits for that callback
  before closing, detaching, destroying, and releasing its factory host.
  The Qt host regression also runs its `qt-gl` endpoint under an isolated Xvfb
  display: it requires a valid current QOpenGLWidget context, direct Obol
  widget presentation, framebuffer readback, and endpoint capture.  The
  ordinary offscreen Qt suite cannot establish that system-GL contract.
* LoD service cancellation removes queued cache writes as well as queued
  result publication.  Its cache-writer boundary rechecks cancellation after
  dequeue, and a deterministic blocked-writer test proves a cancelled
  refinement cannot persist after the writer becomes available; the next live
  generation still writes normally.

Do not treat this as full application or platform validation.  The embedded
ArcherCore configuration used by the historical rtwizard GUI now passes the
endpoint-ownership lifecycle test under Xvfb, but Windows/macOS Tk semantic
input and full application workflows have not been validated.

Immediate Test and Validation Gaps
----------------------------------

1. QGED ERT isolated-X coverage is complete.

   `regress-qged-ert` owns an Xvfb server, reports an unavailable server as
   the standard infrastructure skip, and treats a failure after the display
   probe as a product regression.  It verifies QGED's software endpoint
   launches external `rt` through the IPC stream, uses the laid-out canvas
   dimensions, completes, and leaves QGED alive.  The current run passed
   13/13 checks in 2.65 seconds.

2. Broad application ownership remains unproven.

   The source matrix covers QGED, MGED, GSH, standalone rt/fbserv, Qt, and Tk.
   Direct Tk and embedded ArcherCore lifecycle coverage now exists, but
   auxiliary views, multiple simultaneous views, host detach/reattach, and
   full supported application workflows still need explicit evidence before
   their remaining compatibility shells are deleted.

Priority 0: Endpoint Completion
-------------------------------

1. Complete the hosted-application ownership audit.

   Make a small source-and-test matrix for QGED, MGED, GSH, rtwizard, Archer,
   standalone rt/fbserv, and auxiliary windows.  For every hosted view,
   identify its GED context where applicable, endpoint, controller, host
   factory, input endpoint, framebuffer stream, close path, and tests.  Move
   remaining application-owned controller/host lifetimes into endpoint
   factories; delete a duplicate only after the matrix proves it is
   unreachable.

   Exit condition: each supported hosted view has exactly one of each required
   identity and no graphical command creates a parallel scene or host.

   Source audit: `doc/notes/obol_hosted_application_ownership.txt` records
   QGED, MGED, GSH, standalone rt/fbserv, Tcl Ged, Archer, and rtwizard
   ownership.  `rt_null_sink` proves `/dev/null` needs neither a provider nor
   retained image storage; visible rt/fbserv display smoke tests cover the
   one-session host path.  Archer and the historical rtwizard GUI share Tcl
   Ged's endpoint path; they do not own a second renderer.  The fake `dm_list`
   Tcl discovery command and Ged's ineffective `-type` option are deleted, so
   those callers name `tkobol` directly.  `tclcad_test_archer_obol_smoke`
   passes under `xvfb-run` using
   the view-only embedded `ArcherCore` configuration used by the historical
   rtwizard GUI; it proves four hosted endpoint and GED teardown.  `RtControl`
   is now GED-only and has no unreachable `Mged` branches.  QGED ERT GUI
   coverage and the lazy quad-pane path are now explicit: the Qt host
   regression creates all four panes, verifies each owns one distinct GED
   context/endpoint/controller identity, switches back to one pane while a
   secondary pane is active, and recreates the quad.  Pane destruction
   unregisters its GED context and clears an active context before freeing it.
   The Tk widget lifecycle smoke now keeps a software pane alive while it
   deletes the active hardware pane, proves the promoted endpoint can render
   and capture, then verifies its final teardown.
   The QGED endpoint-host regression also closes and reopens a Qt software
   host through `dm`: the GED context, endpoint, and controller identities
   remain stable while the native host is replaced.  An explicit endpoint
   background property also survives that swap: host-local passive Qt state
   seeds only a locally owned controller, never a retained endpoint
   controller.  QGED framebuffer setup follows the same rule: it associates
   the visible endpoint with the active GED context, then asks libged to
   ensure the session stream.  Libged obtains the host from that endpoint, so
   Qt retains only event-loop delivery and repaint scheduling rather than a
   second framebuffer/controller lifetime.
   Continue the matrix audit for auxiliary views and complete application
   workflows before deleting their remaining compatibility shells.

   Completed Qt slice: QgLegacyView and its context type-punning adapter are
   deleted.  QgView, QgSession, and QgPluginContext expose typed
   `bv_context *` identities; QgGL/QgSW each own one bv_context and cannot
   swap in an external view.  QGED plugins, filters, quad views, canvas
   input, qsketch, and their tests now use direct GED/bv context APIs.
   Preserve this model while completing the remaining application matrix; do
   not reintroduce a Qt-only compatibility view type or type-erased view
   handoff.

2. Close host-factory lifecycle gaps.

   Validate simultaneous hosts, resize/DPI, capability discovery, system-GL
   context ownership, OSMesa photo/pixel presentation, callback thread
   affinity, and close during active rendering.  Factory ABI remains C-only,
   versioned, and toolkit-free.

   Exit condition: close drains callbacks before endpoint/image-stream release
   and two endpoints cannot exchange host, framebuffer, or input state.

   Current evidence: the core factory test covers isolated simultaneous
   endpoints, host capability selection, resize/DPI dispatch, input routing,
   capture, and close while a factory frame callback is in flight.  Endpoint
   detach clears the factory callback before controller destruction, and the
   GED teardown releases framebuffer composition before either object; the
   six-case MGED view-state test completes under Memcheck with zero invalid
   accesses.  The factory replacement regression verifies that a failed new
   host leaves the live host untouched, while a successful replacement releases
   only the old factory instance and preserves the endpoint controller and
   input route.  The Qt software-host test verifies that a worker-requested frame
   enters the canvas only on the Qt application thread.  On X11, the Tk
   factories use a per-host nonblocking pipe registered with the Tcl event
   loop, rather than Tcl thread events, so TkPhoto also renders a
   worker-requested frame on its owner thread when Tcl itself is non-threaded.
   The isolated-X Qt regression now opens a visible `qt-gl` endpoint with an
   explicit hardware engine and both system-GL and pixel-presentation
   requirements.  It proves the factory retains a `QOpenGLWidget` through
   controller binding, makes its native context current, consumes an Obol frame
   through direct widget rendering, and supports both framebuffer readback and
   endpoint capture.  The regression caught and prevents a lifecycle defect
   where controller binding closed the just-created `QgGL` canvas and silently
   recreated a `QgSW` canvas under the `qt-gl` factory name.  Retain supported
   Windows/macOS host coverage, including the Windows Tk worker path, before
   considering this complete.

3. Finish typed policy migration.

   Audit every remaining drawing setting.  Migrate camera/navigation bounds,
   retained feature style/visibility, non-framebuffer image composition,
   antialiasing, and future stereo settings through typed endpoint properties.
   Each property needs stable name, type, allowed range/enum, owner,
   mutability, capability predicate, getter, setter, and explicit unsupported
   result.

   Exit condition: no production drawing option mutates backend state directly,
   and unknown/invalid/unsupported properties fail explicitly.

   Current slice: GED exposes endpoint-backed get/set helpers and perspective,
   faceplate framebuffer mode, ERT underlay setup, framebuffer clear, and
   QGED's framebuffer plus faceplate visibility controls use typed endpoint
   properties.  Framebuffer composition is now a four-value endpoint policy
   (`off`, `overlay`, `underlay`, `interlay`): QGED exposes all values, MGED
   maps its `fb_overlay` semantics without collapsing interlay, and TclCAD's
   `set_fb_mode` translates its public numeric ordering at the command boundary
   rather than treating fbserv state as renderer authority.  The helpers return
   explicit unsupported status when no endpoint is attached; they do not restore
   a direct-renderer fallback.  Global highlight now updates compact occurrence
   state as well as source state, and the MGED regression settles asynchronous
   realization before comparing baseline, highlighted, and cleared captures.
   Background is now controller-owned after endpoint attachment: the passive
   `bv` value only seeds a new endpoint, and TclCAD `bg` maps directly to
   `controller.background.bottom` and `controller.background.top`.  Qt repaint
   and GED framebuffer capture no longer reverse that ownership by copying
   `bv` colors into a live controller.  The endpoint reattachment regression
   proves a typed background mutation survives stale passive state.  The dead
   public GED software-wire integer bridge is removed; all production
   software-wire policy uses `controller.software_wire`, and the pivot guard
   forbids restoring the duplicate API.  MGED's `set perspective`,
   `perspective_mode`, and toggle hooks use the same `view.perspective`
   property; its historical disabled `-1` sentinel maps to canonical
   orthographic `0`, so the endpoint also rebuilds the projection matrix and
   refreshes the controller.  The MGED smoke verifies the attached `45` then
   `0` policy transition.  Non-framebuffer composition now has a concrete
   endpoint owner: `composition.rt.layer` persists its `underlay`, `interlay`,
   or `overlay` choice before the retained RT image exists and safely reparents
   that image when changed live.  The retained-RT regression proves both the
   pre-render policy and live reparenting, rather than leaving the renderer's
   image layer hardcoded.  Obol already implements two-eye rendering for
   anaglyph, interleaved-row/column, and separate/quad-buffer modes, with a
   configurable eye offset.  Do not expose `renderer.stereo.*` yet: first
   prove an end-to-end hardware endpoint with a stereo-capable surface,
   capability reporting, mode-specific output, capture semantics, and clean
   mono restoration.  Qt can request stereo buffers, but the currently
   vendored Togl source has no public stereo-widget option despite stale
   internal masks; neither host currently requests stereo buffers.  OSMesa
   support remains unproven and must report unsupported rather than silently
   falling back.  This keeps stereo an Obol-backed endpoint policy when it is
   ready, rather than adding per-application setters.
   `renderer.antialiasing` now maps to Obol's
   portable single-pass line/point smoothing in system GL and every
   offscreen presentation path; it deliberately leaves accumulation-buffer
   multipass rendering disabled so an ordinary policy change cannot create an
   unbounded interactive cost.  The property boundary now rejects Boolean
   values outside its declared `0..1` range rather than coercing them, so all
   typed renderer-policy failures are explicit.  The three established HUD
   font controls (`params`, `center_dot`, and `scale`) are now bounded typed
   `view.faceplate.*.font_size` properties.  TclCAD's `fontsize` command and
   GED's params-font command use those properties for an attached endpoint;
   an unattached view retains only passive state until it receives one.
   The corresponding params, center-dot, and scale colors are typed
   `view.faceplate.*.color` properties with normalized RGB values.  GED and
   TclCAD use those properties when an endpoint is attached.  MGED's color
   scheme remains the default producer for its center dot and status text, but
   a direct endpoint override survives ordinary refresh; an explicit `rset cs`
   color mutation synchronously republishes the scheme defaults to displays
   using that scheme.  Attached GED `view faceplate` center-dot, grid,
   model/view-axes, scale, and params controls use typed endpoint properties,
   as do the corresponding TclCAD controls; only pre-attachment configuration
   updates passive state.  The complete grid policy is endpoint-owned:
   visibility, adaptive/snap, anchor, resolution, major spacing, and color.
   The complete model/view axes policy is likewise endpoint-owned: visibility,
   position, size, line width, colors, labels, triple-color, and tick
   visibility/style.  GED and TclCAD stage compound commands and publish only
   changed attached fields.  MGED's retained axes and color scheme are explicit
   default producers: they republish their owned fields on a real MGED
   configuration or scheme change, but routine redraws preserve newer direct
   endpoint properties.  ADC visibility, line color, tick color, and line
   width are typed endpoint policy; its Obol overlay emits independently styled
   line and tick geometry.  Semantic MGED ADC/model-axis/view-axis actions
   publish their visibility property.  `mged_obol_smoke` covers the MGED
   override/republication transition for center dot, axes, and ADC styling,
   while endpoint, image-baseline, and Tk widget tests cover the full property
   schemas, staged grid/axes updates, and Boolean validation.  The interactive
   selection rectangle is likewise a retained local Obol feature: its geometry
   remains passive per-gesture view data, while visibility, color, line width,
   and line style are typed endpoint policy.  Continue with remaining
   image-composition requirements and the defined stereo-host validation
   before adding any per-application renderer setters.

4. Complete semantic input migration.

   Define endpoint actions and result routing for MGED editing, ADC, snapping,
   rate controls, selection, framebuffer gestures, and faceplate actions.
   Retire native handling only after equivalent endpoint behavior is tested.
   Validate the portable Tk event bridge on Windows and provide a supported
   macOS Tk host before claiming cross-platform semantic equivalence.

   Current slice: Qt canvases and the Tk/MGED host normalize input and dispatch
   through each endpoint's independent profile and action handler.  They cover
   standard camera motion, wheel zoom, view shortcuts, ADC, and axis toggles;
   an unhandled action deliberately returns to application-specific edit/ADC
   handling instead of a graphical-DM callback.  The obsolete `BRLOBOL_INPUT_KEY`
   and `BRLOBOL_INPUT_POINTER` aliases are deleted and guarded.  Qt's endpoint
   controller regression sends `A`, `M`, and `V` through a real endpoint and
   verifies that they update the canvas-local ADC, model-axis, and view-axis
   state, in addition to its camera, wheel, and drag coverage.  The standard
   profile marks the beginning and end of a primary shifted pan: MGED uses
   them to establish and release a snapped view-only pan baseline, and owns
   the intervening snapped primary-pan motion.  Its Tk attachment smoke
   generates that gesture at the actual host child and requires the
   grid-aligned center change.  It deliberately returns all edit, ADC,
   rate-knob, and non-primary paths to the existing command state machine.
   Pointer-delta navigation is now passive libbv state with validated setters,
   shared clamping, and `view.navigation.{min_delta,max_delta,rotate_scale,
   scale_scale}` endpoint properties.  Qt and MGED semantic drags use the
   common libbv adjustment path, while TclCAD's retained edit commands use the
   same clamp and per-view policy values.  Wheel and click behavior remain
   explicit host policy rather than being misclassified as pointer deltas.
   TkObol views whose host advertises input install the shared keyboard-only
   profile and a per-view endpoint action handler for canonical A/M/V
   faceplate toggles and view orientations.  Their existing
   pointer/edit/selection bindings remain TclCAD-owned until equivalent
   semantic actions exist.  A host without input capability retains TclCAD's
   established keyboard bindings rather than claiming actions it cannot
   receive.  The generic Tcl bindings omit only the endpoint-owned keys, and
   the X11 Tk host observes both its child widget and top-level container
   because Tk delivers keyboard focus at the latter.  The libbrlobol input test
   covers the keyboard profile; the Tk widget smoke verifies that the
   overlapping Tcl bindings are absent on an input-capable host.
   Canonical fixed-orientation actions now have one libbrlobol implementation
   shared by Qt, TclCAD, and MGED.  It updates only the caller-owned bv view
   context; each application remains responsible for its own repaint and
   application state.  Obol display traversal, source-backed exact mesh
   refinement, and librt exact refinement now likewise have one libbrlobol
   picker.  GED adapts its typed result to selection state and QtCAD adapts it
   to feature-overlay state; both retain their application selection policy
   without independently traversing the scene.  Deferred source requests are
   reported by that common picker so a client does not incorrectly take a
   coarse fallback while exact data is pending.  The same view-query API now
   owns typed snap traversal and optional source-backed full-detail refinement:
   GED's first-candidate helper remains nonblocking, while QtCAD's exact-snap
   helper may consume a ready result or enqueue a bounded request.  QtCAD maps
   the typed result into its public record and retains its gesture/edit policy.
   The common A/M/V faceplate actions now share one endpoint helper: it toggles
   the typed ADC/model-axis/view-axis visibility property when an owner exists,
   or the equivalent passive `bv` state for a standalone controller.  QtCAD
   and TclCAD no longer duplicate that property mutation; MGED retains only its
   menu/default-producer synchronization after the common action succeeds.
   The common helpers intentionally leave editing, snap gesture policy, rate
   controls, and broader faceplate policy outside this narrow boundary.
   The libbrlobol window-host test verifies both a recognized orientation and
   explicit rejection of a non-orientation action; GED and QtCAD selection,
   pick, and snap regressions cover the shared queries.
   Continue with explicit endpoint actions and tests for editing, snap gesture
   routing beyond view-only panning, rate controls, selection gesture routing,
   framebuffer gestures, and faceplate actions, then validate native Windows
   and macOS Tk event adapters.
   Tk hosts now install a host-unique bindtag before their native widget and
   containing toplevel bindings.  It normalizes key, button, motion, wheel,
   resize, focus, and expose input through Tcl substitutions and dispatches to
   the endpoint, replacing the former X11-only raw-event handler.  The same
   bridge is used by WGL without importing Xlib behavior.  The MGED attachment
   smoke drives a real generated pointer gesture through this bridge, while the
   Tk widget smoke verifies the installed endpoint key callback and avoids
   overlapping Tcl key bindings.  Validate it on native Windows; macOS still
   needs a supported Tk host.

Priority 1: Rendering and Progressive Behavior
-----------------------------------------------

5. Harden deferred and progressive realization.

   Stress camera churn, edits, erase, database replacement/close, view
   replacement, endpoint teardown, and large models.  Workers must not access
   attached Coin, GED, or toolkit state; stale generations must not publish;
   ready final data may replace a proxy before first draw; autoview must remain
   active while scene bounds change.

   Bound worker queues, cache memory, result-application time, and
   interactive-frame work.  Fix responsiveness in libbrlobol/Obol rather than
   adding GED redraw layers.

   Exit condition: useful pixels precede full detail when work is outstanding,
   camera-only frames avoid source work, and interaction stays bounded through
   refinement.

   Completed cache-frontier slice: the public visible-expansion operation now
   publishes only AABB proxies already populated by the worker cache; it never
   synchronously rebuilds a missing leaf proxy.  The Generic Twin four-pass
   regression starts a bounded proxy-only service and advances one visible
   source per pass, preventing an accidental full-tree expansion while still
   verifying cache prewarm, proxy publication, depth growth, and autoview.
   The default combined frontier/full-detail policy now advances cache-backed
   proxy work while detached final realization runs.  Ready final data still
   wins before first draw, but if temporary children were published, compact
   adoption removes only descendants owned by that root before requesting the
   next frame.  Frontier work is restricted to active deferred root instances,
   so it cannot expand an unrelated realized combination.  The GED lifecycle
   regression covers that handoff, duplicate occurrences, subtract/intersect
   identity, automatic autoview settlement, and user-view cancellation.  LoD
   tests require staged image changes only in explicit diagnostic runs; normal
   runs prove applied payload state and presentable output while allowing final
   data to win before first capture.

   Result-ready callbacks may remove themselves or another callback reserved by
   the same dispatch.  The service distinguishes that local reservation from
   a genuinely concurrent callback, suppresses the removed callback before

Priority 2: Interactive librt Engine
-------------------------------------

10. Implement retained interactive rt.

    Partially landed: BRLObolRtRenderer snapshots visible database sources,
    camera, clipping, source placement, and source appearance into retained
    librt acceleration.  Geometry revisions are independent of camera,
    selection, highlight, color, and placement revisions.  Endpoint rt is
    selectable without a non-Obol fallback, runs librt only on worker threads,
    presents through an Obol image node on the owning thread, cancels stale
    jobs, and produces a deterministic fixed-final capture.  It currently
    publishes a low-resolution one-sample preview followed by a full-resolution
    final image; QGED/MGED-style direct controller redraw requests restart it.
    The full image is an adaptive row scheduler: `render.rt.frame_budget_ms`
    targets its publication interval and adjusts the next row batch from
    measured cost.  `render.rt.quality=interactive` enables the coarse preview
    while `final` skips it; both retain the same deterministic final image.
    `render.rt.workers`, `render.rt.samples`, and
    `render.rt.preview_scale` are also typed endpoint policies.  The retained
    renderer regression proves tiled output is byte-identical to the monolithic
    final image and the endpoint property values persist.  Camera matrices,
    background, clip planes, lighting, and transparency are also retained
    presentation state: changes advance presentation revision without preparing
    geometry again.  Lighting/transparency affect RT shading directly, and a
    direct controller lighting mutation restarts the endpoint worker before
    capture observes the frame.

    Optional final-frame depth and source-identity planes are now available
    without coupling interaction data to RGB sample count.  Depth is normalized
    camera depth with `1` for background; source identity is a retained-frame
    source token with `0` for background.  `renderWithPlanes` and its tiled
    form expose the C++ renderer data, while endpoint RT capture exposes typed
    depth and source-ID buffers only after the matching RGB frame is accepted
    on the owner thread.  The output-plane regression verifies both direct
    retained rendering and endpoint capture.

    Semi-transparent source composition now traces the nearest hit from each
    source and composites those hits back-to-front.  Fully opaque frames retain
    the direct nearest-hit fast path; source sorting is enabled only when a
    partially transparent source is present.  This preserves geometry behind a
    translucent source instead of blending it only against the background.
    `libbrlobol_rt_render` constructs overlapping red and green sources and
    verifies their deterministic blended result and that disabled transparency
    keeps the front source opaque, alongside the tiled, output-plane,
    cancellation, and endpoint cases.

    Next: expand the simple final material/shading treatment and validate
    visual parity, cancellation, and interactive cadence in live QGED and
    MGED sessions.  Introduce region/primitive identity only when a concrete
    interaction consumer requires it; source identity must remain sufficient
    for display composition and source-level selection without growing every
    RT frame's memory footprint.

    Exit condition: QGED and MGED use the time-budgeted rt path interactively;
    camera motion cancels stale work; unchanged geometry is retained; output
    planes support composition where needed; and fixed-final-quality headless
    images remain deterministic.

Completion Standard
-------------------

The migration is complete only when every supported hosted view uses the one
Obol scene/endpoint model; normal drawing, interaction, LoD, editing, capture,
