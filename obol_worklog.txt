BRL-CAD Obol Worklog
====================

Last compressed: 2026-07-04

Purpose
-------

This file is a compact historical log for the Obol migration.  Turn-by-turn
detail was intentionally collapsed because the root text files had become hard
to use as handoff documents.  Use git history for exact diffs and `doc/notes/`
for durable design contracts.

2026-07-04: Documentation reset
-------------------------------

The root handoff files were shortened to reflect the current migration state:
finish retiring old-style non-Obol drawing drivers first, while defining only
the minimal richer-behavior contracts needed to keep command-result and custom
Coin work on a stable path.  `obol_legacy_dependency_inventory.txt` was reduced
to guard-visible dependency rows, active owners, removal conditions, and
current blockers instead of historical prose.

2026-07-04: View object command surface replaced
------------------------------------------------

The public `view obj`, `view objs`, and `view gobjs` spellings were retired
instead of kept as aliases.  The replacement surface is split by responsibility:
`view object` handles lifecycle, info, visibility, style, and realization;
`view annotation` handles line, arrow, label, and axes objects; `view polygon`
handles polygon editing; and `view db` handles database display/edit-proxy
insertion.

Line annotations accept one or more point triples in `create` and `append`.
`view annotation line remove` removes a zero-based point range, and
`view annotation line clear` removes the line feature.

View-object lifecycle, visibility, style, and realization now route through
object-level GED draw facades.  Feature, database shape-ref, and Obol overlay
group style dispatch lives in the draw bridge, including color support for
`view db add --as` aliases and capability rejection for unsupported arrow
settings.

2026-07-04: Multi-instance transform reuse hardened
---------------------------------------------------

libbrlobol database realization now carries an action-scoped shared-geometry
cache.  The action seeds from already-current realized shared geometry, then
realizes stale sources.  Repeated comb/solid instances can share source-local
geometry while retaining per-instance transforms and identity.

`ged_test_obol_draw_sync` covers repeated transformed instances, shared local
geometry reuse, source/subtree bounds, autoview on the transformed envelope,
visibility/highlight transactions, direct stale/redraw reuse from current
siblings, shaded shared mesh reuse, and erase cleanup.

2026-07-04: Evaluated-wire boundary moved to libbrlobol
-------------------------------------------------------

GED evaluated-wire realization became a thin adapter.  `wireframe_eval.c`
resolves GED runtime/source state, calls the public
`brlobol_evaluated_wire_*` line-set API, and publishes through neutral GED
shape-ref or database-source facades.  The legacy Big-E implementation now
lives behind `src/libbrlobol/evaluated_wire.cpp` and no longer depends on GED
or BSG scene-ref internals.

The provider no longer mutates global `rt_uniresource`; each call owns and
cleans a librt `struct resource`.  Remaining work is libbrlobol-internal
modernization, including optional deterministic parallel evaluation with
per-worker resources.

2026-07-04: Mode-aware evaluated source refs
--------------------------------------------

Obol database-source refs now preserve representation mode when multiple
sources share a database path.  Wire, evaluated wire, hidden-line, evaluated
points, and shaded refs no longer collapse to one path-only token.
Evaluated source realization enters the direct Obol publication scope for the
ref's mode before calling the provider; retained evaluated wrappers remain
fallback only for true retained scene refs.

2026-07-04: Command-scene result model expanded
-----------------------------------------------

The GED/libbrlobol command-scene API now publishes owner-scoped shared or
view-local features with replacement/removal, generation fencing, metadata,
primitive metadata, primitive selected/highlighted state, child line-layer pick
resolution, and transaction callbacks.

Typed feature kinds include line layers, line sets, point sets, indexed face
sets, HUD labels, and custom Coin nodes.  The custom-node hook lets commands
provide an opaque Coin node through a C-safe callback interpreted only by the
C++ Obol adapter, while preserving the same owner, scope, metadata, primitive
state, generation, replacement, and removal rules as typed features.

rtcheck, NIRT/qray, check overlap, GQA diagnostics, BREP/NMG debug lines,
overlay-command uplot import, `vdraw send`, preview eye paths, and several
simple command line-set visualizations now publish through command-scene
helpers instead of anonymous direct view-line mutation.

2026-07-04: qtcad command-result picks integrated
-------------------------------------------------

qtcad Obol pick records now carry resolved feature-store identity in addition
to raw Coin detail.  Real child line-layer picks can resolve back to the parent
command-result feature and primitive namespace, with primitive metadata copied
into the pick record.

qtcad point, box, and ray selection filters separate database picks from
resolved Obol feature picks.  Resolved command-result and overlay feature picks
update Obol selected/highlighted primitive state instead of being treated as
database selection paths.

2026-07-04: Database drawing and autoview stabilized
----------------------------------------------------

Normal database draw modes moved to direct Obol providers.  Wire, shaded-BoT,
shaded, and hidden-line draws expand requested roots to leaf database-source
instances and realize those sources in libbrlobol.  Successful direct providers
no longer mirror through `_ged_drawtrees`.

The GED basic drawing test passes through Obol capture.  Autoview was retained:
`autoview2` uses the Obol database autoview bridge, and GED can read
libbrlobol scene bounds for autoview.

2026-07-04: Source-local geometry contract hardened
---------------------------------------------------

External database-source publication and direct realization now require
source-local point/index arrays.  `SoBRLDatabaseSource::drawMatrix` remains
placement metadata.  Legacy transformed producers explicitly localize points
before publishing to libbrlobol.

An ARB import alias/free-pattern failure is guarded by refetching primitive
geometry with an identity matrix and validating payload magic before plotting
or tessellation.  The guard avoids building drawable geometry from poisoned
tree-walk callback internals; the underlying librt alias still needs root-cause
diagnosis if reproduced outside Obol.
