= brlinst

A focused C++ generator for BRL-CAD Windows installers. One generated executable
supports an interactive Win32 wizard and quiet installation. Windows builds also
generate native MSI packages from the same JSON and staged files. Every version has
its own directory, shortcuts, registration, and uninstaller.

This is a new implementation requiring Windows acceptance testing before release
use. It has no NSIS, Inno Setup, Delphi, scripting interpreter, or downloadable
prerequisites. Those projects served as implementation references; no source
from either project is currently copied into this tree.

== Build

This tool lives in `misc/tools/brlinst` and is configured as a separate CMake
project. Run the following commands from that directory. Its sources are included
in BRL-CAD source distributions; building BRL-CAD does not automatically build or
install brlinst.

Windows 10/11 x64 and a Visual Studio C++ toolchain with the Windows SDK:

[source,powershell]
----
cmake -S . -B build -A x64 -DBRLINST_BEXT_ROOT=C:/src/bext
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
----

Dependencies are taken from the existing source trees, not downloaded:

* zlib: `BRLINST_ZLIB_SOURCE` defaults to `${BRLINST_BEXT_ROOT}/zlib/zlib`.
  `BRLINST_BEXT_ROOT` defaults to a `bext` checkout beside the BRL-CAD checkout;
  set it explicitly if the populated dependency sources are elsewhere.
  Only its compression/decompression sources are compiled, into this build
  directory. The bext checkout is not modified. If no source is present, CMake
  looks for an installed static zlib via `ZLIB_ROOT`.
* nlohmann JSON 3.11 or newer: `BRLINST_JSON_INCLUDE` points to the directory
  containing the single-header `json.hpp`. The default is the containing BRL-CAD
  checkout's `src/libbu`, or a sibling `brlcad/src/libbu` when brlinst is extracted
  as a standalone project. This path can also be set explicitly.

Outputs are `brlinst.exe`, `brlinst-stub.exe`, and `brlinst-uninstall.exe`.
Windows builds enable `BRLINST_WITH_MSI` by default and additionally build
`brlinst-msi-actions.dll`; use `-DBRLINST_WITH_MSI=OFF` to omit MSI support.
Keep them together. The generator is a console application; the runtime is a
native GUI application with no extra runtime redistribution requirement when
built with MSVC's static runtime configuration.

For alternate toolchains, set `BRLINST_EXTRA_NOTICES` to any additional runtime-library
notices that must accompany generated executables. These are embedded in the
installed NOTICE.txt as well.

The package/core tests also build on Unix. Windows resource customization and
runtime builds require a Windows target toolchain. Unix packaging with an icon
is intentionally unsupported in this release.

== Generate an installer

[source,powershell]
----
brlinst.exe --config product.json --source C:/stage/brlcad --output BRL-CAD-setup.exe
brlinst.exe --verify BRL-CAD-setup.exe
----

`--stub` and `--uninstaller` can override the adjacent runtime executables.
The output must not exist and must be outside the staging tree. All regular
files in the tree are installed; symlinks, reparse points, Windows device names,
case-colliding files, and traversal paths are rejected. Empty source directories
are not included. `.brlinst` is reserved for bookkeeping.

Every generated package includes `.brlinst/NOTICE.txt` with the brlinst and dependency licenses.

The packager verifies every compressed file before publishing the output. The
runtime verifies the entire payload before creating its destination. CRC-32
checks detect corruption; publisher authenticity is supplied by Authenticode,
not by these checksums.

== Product JSON

[source,json]
----
{
  "formatVersion": 1,
  "id": "org.brlcad.brlcad",
  "name": "BRL-CAD",
  "version": "7.42.0",
  "publisher": "BRL-CAD Development Team",
  "website": "https://brlcad.org/",
  "welcome": "This wizard installs this version separately from other versions.",
  "license": "COPYING",
  "icon": "brlcad.ico",
  "shortcuts": [
    {"name": "MGED", "target": "bin/mged.exe", "workingDirectory": "@profile", "desktop": true},
    {"name": "Manual", "target": "share/doc/index.html", "desktop": false}
  ]
}
----

`formatVersion`, `id`, `name`, `version`, `publisher`, `license`, and `shortcuts`
are required. `shortcuts` may be empty. The optional icon is a Windows `.ico`;
welcome text and an HTTPS website are optional. License and installer-icon paths
are relative to the JSON file, or absolute. Other paths use forward slashes and
are relative to the staged payload. Unknown fields and duplicate JSON keys are
errors. The license is displayed as information; there is no additional license
acceptance switch for quiet installation.

Each shortcut has a name and target. Optional properties are `icon`, `arguments`,
`workingDirectory`, and `desktop` (default true). The working directory defaults
to `@profile`, which stores `%USERPROFILE%` in the shortcut for resolution when
launched; `.` means the installation directory. Other values are relative
payload directories. Targets, icons, and working directories must exist in the
staged tree. Applications can be renamed, added, or removed in JSON without
changing the engine. Desktop eligibility does not enable desktop shortcuts by
default; the installer user makes that choice.

Product IDs and versions use ASCII letters, digits, dots, underscores, and
hyphens. Registration identity includes ID, version, and x64, with registry hive
selecting scope. Names shown to users and used by shortcuts include version,
architecture, and scope. There is no registry-state compatibility with legacy
NSIS or MSI installations; those retain their original uninstallers.

== EXE installation

[source,powershell]
----
# Graphical wizard:
./BRL-CAD-setup.exe

# Quiet, current-user installation:
$p = Start-Process ./BRL-CAD-setup.exe -Wait -PassThru -ArgumentList '--quiet --scope user --start-menu on --desktop off --path off --log "C:/logs/install.log"'
$p.ExitCode

# Quiet machine installation, from an elevated process:
./BRL-CAD-setup.exe --quiet --scope machine
----

The default scope is `user`; the default location is a versioned folder beneath
Local AppData's Programs directory. Machine installation defaults beneath
Program Files and requests elevation only in interactive mode. Quiet machine
operations require an already elevated process and never display UAC prompts.

For this first release, machine destinations must be new/empty folders directly
beneath Program Files. This keeps privileged uninstall records out of arbitrary
user-writable directory hierarchies. User destinations can be on another fixed
local drive. The parent directory must already exist. Network and removable
destinations are unsupported.

Runtime arguments:

[cols="1,3"]
|===
|`--quiet` |No application dialogs; failures go to the log and inherited stderr.
|`--scope user\|machine` |Current user by default.
|`--directory PATH` |Override the versioned default destination.
|`--start-menu on\|off` |On by default.
|`--desktop on\|off` |Off by default.
|`--path on\|off` |Off by default. Append this version's `bin` directory to the matching scope's PATH.
|`--log FILE` |Append an operation log; otherwise create a uniquely named log in TEMP.
|`--recover` |Remove an interrupted installation made by this product/version; requires `--directory`.
|`--help` |Display command-line help; use with `--quiet` for inherited stderr.
|===

CLI choices initialize the wizard, or directly control quiet installation.
PATH entries are not reordered. Existing equivalent entries are not claimed or
removed. Other versions' PATH entries remain intact. Existing same-version
brlinst registrations are rejected; uninstall explicitly first.

Exit codes: 0 success, 2 invalid arguments/configuration, 3 existing installation,
4 elevation required, 5 cancelled, 6 operational failure. In PowerShell, use
`Start-Process -Wait -PassThru` to reliably wait for a GUI-subsystem executable.

== EXE uninstallation and recovery

Run `.brlinst/uninstall.exe` inside that version's directory, or use Windows
Installed apps / the Start Menu entry. It supports `--quiet` and `--log`.
The scope and destination come from the journal and cannot be overridden.

The journal records operation intent before changes. Failed installs attempt
rollback. If interruption or files in use prevent cleanup, rerun that version's
uninstaller. If interruption occurred before the uninstaller was written, run
its original installer with `--recover --directory PATH`; completed installations
must use their installed uninstaller.

Uninstall removes unchanged owned files, owned shortcuts, registration, and the
PATH entry it added. It preserves modified files, unrelated files, and nonempty
directories. Files in use produce a retryable error; interactive operations offer
Retry/Cancel, quiet operations return failure. No applications are killed and
no reboot deletion is scheduled.

The final running uninstaller image is removed by a temporary helper after the
original process exits. Main-process success means payload/integration removal
finished and the helper was launched. Self-removal failures are recorded in the
same log and can be retried with the remaining uninstaller. A small helper
executable remains in its private TEMP directory for normal temporary-file
cleanup. This asynchronous self-removal is the only deferred operation.

Power-loss recovery depends on filesystem durability. Journals and extracted
files are flushed before publication; this is not a full machine-wide transaction
manager. CRC fingerprints preserve accidentally modified files but are not a
cryptographic defense against a user deliberately modifying their own payload.

== MSI generation and installation (Windows only)

[source,powershell]
----
brlinst.exe --format msi --config product.json --source C:/stage/brlcad --output BRL-CAD-setup.msi
brlinst.exe --verify BRL-CAD-setup.msi

# Full wizard:
msiexec /i BRL-CAD-setup.msi

# Quiet per-user install (Start Menu on, desktop and PATH off by default):
msiexec /i BRL-CAD-setup.msi /qn /norestart ALLUSERS=2 MSIINSTALLPERUSER=1

# Quiet machine install, run from an elevated process:
msiexec /i BRL-CAD-setup.msi /qn /norestart ALLUSERS=1 BRLINST_PATH=1

# An explicit destination and options:
msiexec /i BRL-CAD-setup.msi /qn /norestart INSTALLDIR="C:\Apps\BRL-CAD 7.42.0" BRLINST_STARTMENU=0 BRLINST_DESKTOP=1 /l*v install.log

# Remove using the original package, or Installed apps:
msiexec /x BRL-CAD-setup.msi /qn /norestart /l*v uninstall.log
----

MSI generation requires executing the Windows generator: it calls the system
`msi.dll` database APIs and `cabinet.dll` FCI compressor. No WiX, msitools, LGPL
code, scripting compiler, or MSI engine is bundled. Unix generators retain EXE
support, using cross-compiled Windows runtimes. `--format exe` is the default;
the output extension alone does not select the generation format.

Keep `brlinst-msi-actions.dll` beside the generator. It is embedded into the MSI
and performs read-only destination/OS validation. All filesystem, registry,
shortcut, PATH, rollback, and uninstall changes use standard Windows Installer
actions. The MSI installs no brlinst EXE uninstaller or recovery journal.

Both full GUI and `/qn` use one package; `/qb` supplies Windows Installer's basic
progress display. The full wizard shows welcome/license information, scope and
options, destination, review, progress, and completion. Scope and options are
chosen before MSI costing; after moving to the destination page, changing them
requires restarting setup. The destination can be typed directly. Start Menu,
desktop, and PATH command-line properties accept `1` or `0`.

Every version has a distinct ProductCode and component identities; rebuilding
one version retains those identities and gives the package a fresh PackageCode.
Uninstall an existing version before reinstalling it. Automatic upgrades,
repair, feature selection, patch generation, advertisement, and administrative
extraction (`/a`) are outside this backend's initial scope.

Defaults use a versioned folder with `(x64, MSI)` in its name, in the current
user's Programs folder or Program Files. MSI shortcuts are similarly marked,
so EXE and MSI registrations do not claim the same shortcuts. A read-only
preflight rejects nonempty destinations, linked paths, network/removable drives,
and machine destinations outside a direct child of Program Files. Keep each
installation in its own directory. Legacy WiX/NSIS installations remain owned
by their original installers.

MSI follows Windows Installer's ownership rules: packaged files can be removed
even if modified, and PATH entries/shortcuts are managed by MSI components.
It does not implement the EXE backend's fingerprint-based preservation policy.
Unlisted user files are retained. Do not store user work in packaged files.
MSI resolves shortcut working-directory environment variables when creating
shortcuts: `@profile` can therefore resolve to the installing account for a
machine-wide shortcut. Check this behavior when testing MGED/Archer; use an
explicit shared working directory in a custom JSON configuration when appropriate.
Windows Installer controls files-in-use handling; automatic restart is suppressed,
and a successful operation can return `3010` when a reboot is needed. MSI exit
codes are Windows Installer codes, independent of brlinst EXE runtime codes.
Use `Start-Process -Wait -PassThru` when capturing `msiexec` completion in PowerShell.

Initial MSI format limits are checked during generation:

* Canonical numeric `major.minor.build`, bounded by `255.255.65535`.
* At most 32,767 files including the installed license notices, and at most
  1.5 GiB of uncompressed payload in a single embedded MSZIP cabinet. The final
  database must be smaller than 2 GiB. EXE packaging retains its separate limits.
* Product text and payload filenames must be representable in Windows-1252.
  License text is converted from UTF-8 to RTF with Unicode escapes, up to 60 KB
  of RTF. Installer destination paths use Windows Unicode APIs.
* Shortcut argument fields are limited to 255 characters after escaping, and
  generated desktop shortcut names to 115 UTF-8 bytes before the short alias.

`--verify` checks MSI storage, authored table constraints, and the presence of
the embedded cabinet header. It does not decompress the cabinet, run the ICE
suite, or prove that an installation succeeds. These require Windows tests.

== BRL-CAD / CPack integration

Build BRL-CAD normally, adding this optional configure hook:

[source,powershell]
----
cmake -S C:/src/brlcad -B C:/build/brlcad -DCMAKE_PROJECT_BRLCAD_INCLUDE=C:/src/brlcad/misc/tools/brlinst/cmake/BRLCAD.cmake -DBRLINST_EXECUTABLE=C:/src/brlcad/misc/tools/brlinst/build/Release/brlinst.exe
cmake --build C:/build/brlcad --config Release
cmake --build C:/build/brlcad --config Release --target package-brlinst
----

The hook adds packaging targets after BRL-CAD has configured its existing CPack
setup: `package-brlinst` for EXE and, on Windows hosts, `package-brlinst-msi` for
MSI. It uses CPack External staging and returns packages to the build directory.
Set `BRLINST_FORMATS=exe` when the generator was built without MSI support; Unix
hosts default to EXE only. Separate CPack staging roots let both targets coexist.
Existing NSIS/WiX generators are not changed. If another project hook is in use,
include this module from that hook instead of replacing it.

The default configuration advertises MGED, Archer, and RtWizard only when their
build targets exist, and adds manual links when those files are staged. Set `BRLINST_PRODUCT_CONFIG` to a complete custom JSON file
to control the shortcuts or add manuals. `examples/brlcad.json.in` illustrates
those definitions; substitute BRL-CAD's installation paths and version, retaining
`@profile` literally. Only reference manuals actually present in your build.

For another CMake project, include `cmake/Brlinst.cmake` after `include(CPack)`
and call `brlinst_add_package(CONFIG product.json EXECUTABLE /path/to/brlinst)`.
Add `FORMATS exe msi` on Windows to create both targets. The BRL-CAD defaults omit
resource-icon customization when packaging on Unix; the cross-built EXE stub's
existing resources are retained.

== Signing and validation

Sign `brlinst-uninstall.exe` first if desired, then package it. Keep the setup
stub unsigned. Sign the final generated installer last, then run `--verify`
and the Windows smoke test again. Package offsets are independent of the
certificate table, and the package is aligned before signing. Generation rejects
executables near the 4 GiB PE signing limit. No signing certificates are bundled.

Portable automated tests cover corruption/truncation, path rejection, file
collisions, signature-table placement, extraction, cancellation, rollback,
recovery, and preserving user data. On Windows, also run:

[source,powershell]
----
powershell -ExecutionPolicy Bypass -File tests/windows-smoke.ps1 -BuildDirectory build/Release
----

This creates isolated current-user test installations, exercises two versions,
checks shortcuts/PATH/registry, and removes them through their uninstallers.
It preserves logs and test user files. Run it on a disposable test account.
It does not test machine-wide UAC or graphical layout.

Before releasing BRL-CAD installers, test on clean Windows 10 and 11 x64 VMs:
interactive navigation, high DPI and keyboard use, Unicode destinations,
current-user and all-users installs, UAC cancellation and alternate credentials,
quiet exit codes, files in use, low disk space, interruption/recovery, signed
artifacts, and actual BRL-CAD application launch without development tools.
Wine can supplement these checks but does not replace Windows validation.

MSI authoring tests run natively without Windows: schema/foreign-key integrity,
wizard navigation, version limits, literal argument handling, and identities
across versions and reordered payloads. On Windows, CTest additionally generates
and reads MSI packages and exercises the CPack MSI target. It does not install
products automatically. Run the optional installation checks explicitly:

[source,powershell]
----
# Generate and inspect packages only (also run by Windows CTest):
powershell -NoProfile -ExecutionPolicy Bypass -File tests/windows-msi-smoke.ps1 -BuildDirectory build/Release
# Install two versions, check payloads/shortcuts/PATH, remove independently:
powershell -NoProfile -ExecutionPolicy Bypass -File tests/windows-msi-smoke.ps1 -BuildDirectory build/Release -Install
# Repeat for all users from an elevated PowerShell:
powershell -NoProfile -ExecutionPolicy Bypass -File tests/windows-msi-smoke.ps1 -BuildDirectory build/Release -Install -Machine
----

Use disposable Windows accounts/VMs. The MSI script preserves packages and logs;
installation tests retain their deliberately unowned test file. Before release,
run Windows SDK ICE validation (including the dual-purpose package checks) in
Orca, and test the full wizard, cancellation/rollback, files in use, UAC,
Unicode destinations, both scopes, and actual BRL-CAD payloads. These Windows
acceptance checks have not been executed on the FreeBSD development host.

The MSI implementation follows Microsoft's published
https://learn.microsoft.com/en-us/windows/win32/msi/database-tables[table schemas],
https://learn.microsoft.com/en-us/windows/win32/msi/single-package-authoring[single-package authoring guidance],
and https://learn.microsoft.com/en-us/windows/win32/msi/sql-syntax[database API syntax].
It contains no source or UI templates copied from WiX or msitools.
