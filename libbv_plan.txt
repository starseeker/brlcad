BRL-CAD libbv Refactor Plan
===========================

Last refreshed: 2026-07-08

Purpose
-------

libbv is BRL-CAD's scene-graph-free view mechanics library.  It owns passive
view state, view math, view sets, lightweight lifecycle callbacks, and generic
view-quality preferences.  It must not own databases, display managers,
Obol/Coin scene objects, command policy, realized LoD payloads, framebuffer
protocols, Tcl state, or BSG compatibility behavior.

Current Ownership
-----------------

libbv currently owns:

* `struct bv`, `struct bv_set`, `struct bv_context`, and
  `struct bv_context_set`.
* Camera/view scalars, matrices, AET/orientation, keypoint, current point,
  model/view/screen transforms, autoview bounds math, and view hashes.
* Passive mouse/input bookkeeping, knobs, refresh flags, frame time, zclip,
  framebuffer mode, cleared state, and user data.
* Passive faceplate/overlay records: grid, ADC, model axes, view axes, center
  dot, scale overlay, parameter display, and interactive rectangle state.
* Passive snap preferences and grid snap math.
* Generic view snapshot and sampling preference data:
  `bv_view_info`, `bv_lod_settings`, and `bv_lod_policy`.

The old `rt_view_info` and `rt_view_lod_policy` names are now compatibility
aliases/wrappers over libbv data and helpers.  Primitive plotting/LoD
signatures now use `bv_view_info` directly; the old RT names remain only in
the LoD compatibility header/helper layer and its tests.

Completed Migration State
-------------------------

* GED view-state storage allocates and owns `bv_context` /
  `bv_context_set` directly.
* qtcad, MGED, TclCAD, GSH, `ged_draw_perf`, GED DM setup, and GED-linked draw
  tests use libbv or GED owner APIs for passive view state.
* Production libged no longer calls `rt_view_context_*` for passive state.
* libbrlobol reads view mechanics from `bv_context` / `struct bv` and syncs
  Obol cameras through `syncCameraFromViewContext`.
* qsketch publishes line sets through libbrlobol/Obol feature-store APIs; it
  no longer uses `rt_view_context_line_set_create`.
* librt primitive plotting and LoD callbacks use `bv_view_info` directly.
  `rt_view_info` is now a wrapper/alias name only.
* The old RT view-context facade, scene-ref API, feature/polygon adapters, and
  `view_legacy_bsg` implementation have been removed from librt.
* GED draw scene identity is represented by `ged_draw_scene_handle`, a
  GED-owned opaque handle whose backend can be Obol, legacy, or empty.  GED
  draw plumbing no longer carries `rt_view_scene_ref`.
* libbrlobol no longer exposes RT scene-ref bridge helpers on
  `SoBRLSceneController` or mesh-LoD cache APIs.
* Draw-test passive setup/inspection uses libbv helpers.  Scene snap/measure
  coverage uses final GED/libbrlobol/Obol APIs, not RT context adapters.
* `ged_test_measure_semantics` was removed.  `ged_test_snap_semantics` is a
  pure libbv grid-snap test.
* The old libdm backend draw-item test was removed; dm-obol immediate-mode
  callbacks are no-ops and high-level GED/libbrlobol draw publication is the
  expected path.
* GED draw LoD policy APIs still expose `ged_draw_view_lod_policy` as a
  `struct bv_lod_policy` typedef, but the per-view policy, independent-scope
  flag, and Obol scene-root token now live in a libbrlobol
  `BRLObolViewAttachment`.
* `BRLObolViewController` owns its view-local realized LoD payloads through
  `BRLObolViewAttachment`, not as raw controller members.  Shared source
  geometry remains scene-controller/database-source state; active LoD payloads
  remain view-local.
* GED-created view contexts and externally attached Obol controllers share
  `BRLObolViewAttachment` instances while attached.  Attach/replacement binds
  the GED host record to the controller attachment; detach/unbind restores a
  GED-owned attachment copy carrying passive host state forward.
* Passive overlay, input, snap, and faceplate records are libbv types in
  production code.  The old passive `rt_view_*` record names and init macros
  are no longer exposed by `rt/view.h`.
* MGED edit setup converts `bv_context` to an `rt_edit_view` snapshot through
  `rt_edit_view_from_context`; the stale `edit_legacy_bsg.h` adapter header
  has been removed.
* The no-op GED edit-matrix view API and the unused BSG `gv_edit_mat` display
  field have been removed.  MGED high-level Obol refresh no longer stages a
  per-frame edit matrix through view state.
* qged edit plugins publish preview geometry through GED view feature refs,
  which resolve to libbrlobol/Obol edit-preview features.  The earlier
  duplicate production path that also mutated the qtcad widget's Obol preview
  directly has been removed.
* Obol viewport readback is available through
  `BRLObolViewController::renderToImage`.  `dm-obol` delegates display-image
  capture to that controller API, and GED screengrab uses a GED-private Obol
  bridge for Obol-backed views before falling back to raw DM readback for
  non-Obol display managers.
* GED exposes a narrow opaque Obol-controller lookup/ensure API for a view
  context.  App-host helpers such as fbserv/readback use that GED/libbrlobol
  controller association instead of probing `dm_obol_controller`.

Boundary Rules
--------------

Keep in libbv only data and math that are meaningful without a database, a
display backend, Tcl, a framebuffer server, or an Obol scene.

Do not move these into libbv:

* Obol/Coin nodes, scene refs, CAD packets, source publication, or view-local
  scene roots.
* Drawable geometry, display lists, command visualization objects, realized
  LoD payloads, LoD caches, or cache-population workers.
* Selection state, picking results, feature stores, polygon stores, editing
  behavior, manipulators, or object snap hit testing against scene/database
  content.
* Display-manager pointers, TclCAD data, application update hooks,
  framebuffer protocol handling, Auth/TLS, or fbserv wire logic.
* Compatibility wrappers whose only purpose is preserving BSG behavior.

Remaining Targets
-----------------

1. Finish retargeting edit visualization to the modern editing stack:
   librt edit operations, libged/MGED/qtcad command policy, and
   libbrlobol/Obol preview/manipulator realization.  The old edit-matrix
   display-path API surface and qged direct-widget preview fallback are gone;
   remaining work is native MGED edit-preview behavior and richer manipulator
   integration.
2. Retire remaining app-host/display legacy dependencies: fbserv protocol
   ownership and libdm window-open assumptions that should become
   Obol/libbrlobol/libbv or image-stream responsibilities.  Obol-backed
   screengrab/readback and fbserv setup now use the GED/libbrlobol controller
   association; raw DM readback remains only for non-Obol display managers.
3. Keep libbv tests focused on pure view mechanics.  Test scene realization,
   picking, selection, realized LoD, progressive cache behavior, and
   framebuffer behavior in libbrlobol/libged/qtcad/MGED/GSH tests.

Verification
------------

Use `build/` for implementation checks.  Reserve `build_perf/` for final
goal-level release/performance validation.

Focused debug checks:

* `ninja -C build libbv librt libged libqtcad bv_test rt_view_info ged_test_view_command ged_test_obol_draw_sync ged_test_snap_semantics ged_test_mged_view_state ged_test_rtwizard_view qsketch test_qtcad_obol_draw_sync test_qtcad_obol_faceplate_sync test_qtcad_obol_snap`
* `ctest --test-dir build -R '^(bv_basic|rt_view_info|libbrlobol_lod_update_action|libbrlobol_mesh_lod_cache|ged_test_view_command|ged_test_obol_draw_sync|ged_test_snap_semantics|ged_test_mged_view_state|ged_test_rtwizard_view|test_qtcad_obol_draw_sync|test_qtcad_obol_faceplate_sync|test_qtcad_obol_snap)$' --output-on-failure`
* `ctest --test-dir build -R ged_draw --output-on-failure`
* `git diff --check`

Final goal-level checks:

* Build and test the same targets in `build_perf/`.
* Run draw-performance/image gates that cover normal wire, LoD-enabled wire,
  shaded/hidden-line, selection highlighting, faceplate/grid, and progressive
  cache behavior.
