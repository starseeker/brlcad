BRL-CAD Obol Debug Draw Performance Notes
=========================================

Scope
-----

The historical table below characterizes the initial debug build using
`build/bin/ged_draw_perf`, the source target in `src/gtools/ged_draw_perf.cpp`.
The probe owns a headless GED/Obol endpoint and has no libdm dependency.  All
listed runs used `--profile --autoview --render`, a 512x512 render target, and
a fresh temporary cache directory with `--clear-cache`.

Use `misc/tools/obol_draw_perf.sh <build-dir> <output-dir> 3 quick` for the
routine corpus.  The `full` tier also runs evaluated, shaded, and hidden-line
draws on the large models and may take a long time.  Each case has an isolated
cache, per-run log, stage counters, and rendered RGB hash.  A release build in
`.build_perf` is required for performance conclusions; debug results are for
instrumentation and correctness work only.

Interpretation
--------------

Normal wire is not dominated by primitive plotting: plot/vlist conversion is
small compared to source realization, replacement, and render traversal.  The
previous CAD aggregation experiments were not retained because measured
complexity outweighed the benefit in this build.

LoD wire improves rendered point count and render time for Generic_Twin, but
source publication remains the draw-time bottleneck.

Full shaded and hidden-line style paths are tessellation dominated on
implicit-heavy models.  That is a shaded-mode optimization task, not a grid or
faceplate regression.

Evaluated wire is dominated by the librt candidate pipeline.  With
`RT_EVAL_WIREFRAME_PROFILE=1`, `Generic_Twin.g all -m3` reported:

* total evaluated-wire profile time: 10.77 s;
* candidate stages: edge candidates 1.13 s, intersection candidates 3.78 s,
  intersection face indexing 1.92 s, pair evaluation 1.44 s;
* boolweave candidate evaluation: 1.18 s.

The shorter `evaluated-wire boolweave eval summary` reports only the
candidate-eval portion, not total candidate setup/export time.  Thin-shell
havoc evaluated-wire remains a separate long-term algorithm task.

Fixes From This Pass
--------------------

Evaluated-points mode previously aborted on some Generic_Twin CLINE samples
because `rt_cline_norm` called `bu_bomb` on degenerate grazing normals.  CLINE
normal calculation now falls back to a radial normal and otherwise lets the
sampler discard an empty normal.  `Generic_Twin.g all -m5` and
`havoc.g havoc -m5` now complete.

Next Optimization Targets
-------------------------

The neutral-endpoint Release measurements supersede the earlier DM-backed
debug timing for optimization decisions:

* Generic Twin evaluated wire emits 1,171,060 ordered line records.  Repeated
  exact vector reservation made result merge take about 5.2 seconds.  A single
  checked reservation and ordered move insertion reduces that stage to about
  0.02 seconds and preserves image hash `b3852519b131c346` across repeated
  open/draw/render/close cycles.
* Generic Twin Release draw time changed from 9.32 seconds cold and about 6.3
  seconds warm to 4.67 seconds cold and 4.7-5.1 seconds warm.  Candidate and
  boolweave stages alone are not large enough to justify parallelism there.
* Havoc evaluated wire emits 4,495,576 ordered records and remains dominated by
  4.27 million candidates from 17.3 million face pairs.  Pair evaluation takes
  about 12-13 seconds of a 21-23 second evaluator run.  This is the appropriate
  parallelism experiment only after all per-job mutable state is isolated.

Continue to reduce normal-wire source publication/render traversal overhead
without adding CAD aggregation unless fresh Release measurements prove it
pays.  Treat full shaded/hidden-line tessellation as a separate workstream.

July 2026 Retained-Source Results
---------------------------------

Normal wire publication and GUI redraw were profiled again with Havoc and
Generic Twin after establishing indexed, persistent Obol database sources.

* Obol node field metadata is now registered once per class rather than once
  per instance.  Generic Twin normal-wire realization fell by about 30 percent
  and warm whole-draw time fell by about 12 percent in the Release probe.
* The scene controller maintains normalized path-to-instance indexes.  Exact
  source operations no longer scan every database source, and removal of one
  duplicate occurrence leaves another occurrence indexed for that path.
* `GED_DRAW_TXN_REDRAW` no longer replays draw publication or enumerates shape
  summaries.  It checks retained sources for stale realization, realizes once
  only when necessary, and requests a render.  Debug Havoc redraw changed from
  more than 20 seconds to 0.7 ms in `ged_draw_perf`; Generic Twin measured
  0.6 ms.  Source counts and deterministic geometry hashes were unchanged.
* The qged profile `qged_gui.perf` identified a separate presentation problem:
  44.8 percent of sampled cycles were under `QTreeView::drawRow` because each
  paint recomputed `ged_draw_path_state`, copied and stable-sorted all source
  summaries, and walked database leaves.  `QgItem` now caches draw presentation
  state and invalidates it from existing draw-observer notifications.
* An interaction-only post-fix Havoc profile (five software-rendered viewport
  drags) sampled about 735 million cycles.  `ged_draw_path_state` and GED redraw
  work were no longer measurable.  Remaining active cost was real rendering:
  about 47 percent below Obol scene traversal, 44 percent in
  `SoBRLVListShape::GLRender`, with most of that in Mesa rasterization.

Deferred-root startup is an explicit draw option rather than a changed default.
The first stage publishes a root bounds proxy and the second stage promotes the
same request to exact full detail.  Debug first-proxy times were about 89 ms for
Havoc and 134 ms for Generic Twin.  Final normal-wire and shaded image hashes
match direct full-detail draws.

The next normal-wire rendering optimization, if larger models demonstrate a
need, should target render batching or retained GPU buffers for VList sources.
Do not reintroduce source aggregation into GED: the current profile shows that
publication and redraw overhead have been removed and the remaining hot path is
inside Obol/backend rendering.

2026-07-15 Release Workflow Gate
--------------------------------

The Release probe was rerun after the final controller/presentation changes.

The progressive `render_ms` field is deliberately not a single interaction
latency: the probe polls until detached realization settles.  First-frame and
steady-frame values are the useful-pixel and settled interaction measures;
draw, source counters, and the existing stage profile identify realization
and submission cost.  Style churn exercises retained source deltas and the
same rendering path used by selection, line style/color, and lighting policy.
All six cases settled with no remaining work, bounded RSS, one retained source,
and stable hashes across repeated captures.  Eightfold geometry raises memory
approximately linearly but leaves redraw at 0.02 ms, confirming that retained
redraw does not replay publication.

System-GL comparison remains a hosted measurement, not a hidden mode in the
OSMesa probe.  Native QGED/MGED X runs exercised the same HW endpoint and
produced nonblank wire, shaded RT, camera-motion, capture, and faceplate
frames.  The existing native QGED sampling profile places the remaining hot
cost in Obol traversal/VList submission and Mesa rasterization; it finds no GED
redraw or path-state work.  FAST/QUALITY therefore remain explicit OSMesa wire
policies, while native GL is selected and measured through its real toolkit
host rather than simulated by the neutral probe.
