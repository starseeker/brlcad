BRL-CAD Obol Active Work Guide
==============================

Last refreshed: 2026-07-04
Branch: oboltest2

Purpose
-------

This is the first file to read when resuming Obol migration work.  It is kept
short on purpose: current invariants, active risks, verification gates, and
next actions live here.  Use `obol_worklog.txt` for compressed history and
`doc/notes/` for durable design notes.

Workspace rules
---------------

* Primary BRL-CAD build directory: `build/`, generated with Ninja.
* Python command: `python3.11`.
* Debugger: `lldb`.
* Obol source checkout: `obol/`.
* Preserve user and preexisting worktree changes; do not revert unrelated
  edits.
* Retire legacy BSG paths when they conflict with a clean Obol design.
* Keep new Obol/libbrlobol API boundaries narrow and explicit rather than
  accumulating one-off compatibility paths.
* Update this guide and the relevant `doc/notes` files when a design invariant,
  known risk, or verification baseline changes.

Current migration stance
------------------------

Obol/libbrlobol is the canonical scene, view, interaction, and rendering path
for migrated BRL-CAD interactive workflows.  Retained BSG/libdm code may remain
compiled for legacy or no-owned-scene compatibility, but new correctness work
should not preserve parallel BSG ownership when the Obol answer is clear.

The immediate hardening target is removing the remaining legacy drivers from
Obol-owned draw and realization.  Database-source realization and publication
must keep geometry reuse explicit, transforms unambiguous, and multiple views
free to choose different LoD/display levels for the same scene without changing
selection, edit, identity, or database semantics.

Core invariants
---------------

* Database-source primary geometry is source-local.
* `SoBRLDatabaseSource::drawMatrix` is local-to-scene placement metadata; it is
  not baked into primary point/index arrays.
* Realized BRL-CAD database leaves use local shared geometry plus explicit
  per-instance OpenInventor transforms built from tree-walk state.
* The visible leaf shape owns path identity, material/region state, selection,
  visibility, highlight, edit intent, and export metadata even when drawable
  arrays come from a shared local geometry node.
* LoD-capable mesh leaves keep a per-instance LoD wrapper so view-specific
  display/staged LoD state can differ between views while source-backed exact
  operations remain tied to stable database identity.
* External primary publication APIs accept source-local geometry.  Legacy
  transformed mesh producers must normalize points at the producer boundary
  before publishing to libbrlobol.
* Bounds and autoview use explicit transform application.  Autoview keeps the
  historical padded database-object envelope behavior separate from tight scene
  bounds.
* Source refresh caches are realization-local unless a future persistent cache
  has explicit content/revision keys and refcount ownership.

Current state
-------------

* The GED basic drawing test passes through Obol capture.  The latest repair
  moved database draw modes to direct Obol providers, removed the hand-coded
  ARB shaded mesh shortcut in favor of librt tessellation, and repaired the
  GED draw-scene regressions exposed by that migration.
* Autoview work was not lost.  `autoview2` still calls the Obol database
  autoview bounds bridge, and `draw_obol.cpp` exposes the libbrlobol scene
  bounds summary to GED autoview.
* libbrlobol database realization now refetches primitive geometry with an
  identity matrix on cache misses and shares local geometry between realized
  instances.
  Each `SoBRLRealizeAction` has a two-phase traversal: first seed the
  realization cache from already-current shared geometry in the scene, then
  realize stale database sources.  This lets separately synchronized
  transformed instances reuse the same local geometry node without making the
  cache persistent across refreshes.
* Direct database realization and external publication no longer rely on a
  source-level placement transform plus already transformed child geometry.
* For Obol-owned wire, shaded-BoT, shaded, and hidden-line draw modes, GED draw
  transactions expand requested roots with `db_walk_tree_leaf_instances` and
  realize the resulting full leaf paths as database sources.  Direct provider
  draws now also ensure an explicit Obol group for the requested root path so
  later group lookup is idempotent and does not create retained placeholders.
* Evaluated wire and evaluated sampled-points now use named Obol database-source
  provider publication for the requested path instead of retained evaluated
  shape refs.  The evaluated-wire producer boundary is now in libbrlobol:
  GED resolves runtime/source state, calls the libbrlobol line-set provider,
  and publishes through neutral GED database-source or shape-ref facades.
  The implementation behind that boundary is still the old Big-E algorithm,
  but it no longer lives in GED or depends on retained BSG shape-ref
  evaluation internals.  GED Obol shape refs now carry optional
  representation-mode identity, so multiple database sources for the same path
  (wire, evaluated wire, hidden-line, evaluated points, shaded) do not collapse
  to one path-only ref.  Evaluated shape-ref realization now enters the direct
  Obol publication scope for the ref's mode before calling the provider;
  retained evaluated wrappers are fallback only for true retained scene refs.
  The libbrlobol provider owns and cleans its per-evaluation librt
  `struct resource` instead of mutating global `rt_uniresource`.
* Successful direct Obol draw providers no longer invoke `_ged_drawtrees` as a
  retained BSG mirror.  `_ged_drawtrees` remains compiled for no-owned-scene
  fallback, unsupported legacy callers, and exceptional direct-provider
  failures only.
* Command-owned result visualizations are not passive decoration.  Existing
  Obol line-layer overlays already preserve Coin pick/export/snap/measure
  identity, and feature styles now carry `selectable` intent through GED and
  libbrlobol feature-store publication.  Treat nirt, rtcheck, gqa, and similar
  commands as interactive Obol/Coin scene participants with command-owned
  lifecycle, pick detail, selection/highlight state, and result metadata.
  Typed Obol feature records are the first migration rung, not the capability
  ceiling: the longer-term API must allow command and plugin authors to publish
  custom Coin-backed scene objects and behavior through an explicit owner,
  lifecycle, pick/selection, and teardown contract.
* The first GED command-scene publication context now exists.  It publishes
  command-owned line-layer results into the Obol feature store, preserves owner
  metadata on shared command-result records, supports owner-scoped prefix
  removal, stamps `CommandResult` overlay metadata, and carries selectable
  style through realization.  Command-scene features can now carry persistent
  key/value result metadata for detail-panel and command-specific lookup, and
  neutral GED view APIs can read that metadata without exposing libbrlobol
  internals.  Command-result features now also carry selected/highlighted
  primitive-index lists through the feature store into realized Coin VLIST
  fields, with neutral GED APIs for setting and reading those lists.  GED
  command-scene transactions can report synchronous command-result
  accepted/updated/removed/failed callbacks to their immediate producer without
  storing callback state in long-lived scene records.  The command-scene API
  now also has an initial custom Coin node provider hook: commands can publish
  an owner-scoped `CustomNode` feature backed by a provider-returned `SoNode`
  while preserving normal Obol replacement/removal, metadata, primitive state,
  overlay stamping, generation fencing, and transaction callbacks.  Its default
  scope is scene/shared, matching current nirt/rtcheck/gqa line-result
  behavior; view-local command results are opt-in.  Command-result features
  also support per-primitive key/value metadata through libbrlobol storage,
  command-scene mutation, and neutral GED readback.  This gives pick/detail
  consumers a stable primitive-index lookup substrate for overlap/ray/gap
  domain data without hard-coding command-specific schemas into the store.
  Child Coin VLIST picks on command line-layer children can now be resolved
  through the neutral GED API back to the parent shared command-result feature
  and parent primitive namespace, with optional selected/highlighted primitive
  updates.  qtcad Obol pick records now carry canonical resolved
  feature/primitive fields and per-primitive metadata, and qtcad point/box/ray
  selection filters apply selected/highlighted primitive state for resolved
  command-result and overlay feature picks instead of sending those feature
  names through database path selection.
* rtcheck's uplot overlap stream publishes through the command-scene helper as
  shared `rtcheck::` command-result line layers with owner-scoped
  replacement/removal.  NIRT/qray plot output uses the same model for the
  shared `query_ray` result family.  `check overlaps -o` now publishes shared
  `check::overlaps` line layers and `check::overlaps::summary` HUD labels
  through the same command-scene ownership model.  GQA line diagnostics publish
  shared `gqa::overlaps`, `gqa::gaps`, `gqa::adjacent-air`, and `gqa::exposed-air`
  command-result line layers owned by `gqa`, and GQA overlap summaries publish
  `gqa::overlaps::summary` as a command-scene HUD label backed by
  `SoBRLHUDLabelOverlay`.  GQA volume sampling plot streams now have an
  explicit opt-in scene policy: when `-p` requests the dense plot stream, the
  same volume sample segments publish as shared `gqa::volume-samples`
  command-result line layers while preserving the file plot.  The old qray
  display-list work-flag mutation path has been removed.  The GED `overlay`
  command now imports uplot files as shared `overlay::` command-result line
  layers owned by `overlay`, while preserving the lower-level anonymous uplot
  feature helper as compatibility plumbing.  `vdraw send` now publishes
  line-compatible, point-compatible, and indexed-face-compatible `_VDRW*`
  output as shared command-result features owned by `vdraw`.  Simple line-set
  command visualizations from `gdiff`, `lint`, `joint`, `bot plot`,
  `bot_fuse`, `bot check`, and preview eye-path output now use the shared
  command-scene line-set helper instead of direct view line replacement.
  Obol feature export exposes
  line-layer children as per-layer records so existing color-layer
  selection/export code
  sees stable line records instead of a flattened parent; builder-published
  line layers now retain their payloads in the feature store for
  export/readback.
* BREP debug line plots and NMG edge-use diagnostics now use the shared
  command-scene line-layer builder helper when an Obol view exists.  The
  diagnostic line-layer callback and direct view-context feature replacement
  are retained in one helper as fallback for non-command-scene consumers rather
  than duplicated in each producer.
* `ged_test_obol_draw_sync` now includes a regression for mesh publication
  under source placement: the direct database-source publisher stores
  source-local coordinates while preserving the source placement matrix.
  It also covers repeated comb/solid instances under different transforms,
  verifies one shared local geometry node is reused, checks transformed source
  and scene subtree bounds, verifies logical visibility/highlight transactions,
  exercises direct instance-key stale/redraw seeding from a current sibling,
  guards logical redraw against retained fallback state, covers shaded shared
  local mesh reuse, and runs autoview against the transformed envelope.
* Obol-owned GED draw transactions now apply highlight directly to matching
  database-source instances and scene groups, parallel to visibility, instead
  of leaving highlight synchronization to retained legacy draw state.
* Source comments in `include/brlobol/database_source.h` and
  `include/brlobol/scene_controller.h` now document the source-local external
  primary geometry contract.

Known risks
-----------

* A librt ARB import alias/free-pattern issue is still protected by a
  libbrlobol payload-magic guard.  Do not hide this by adding Obol/BSG sync
  compatibility; the next diagnostic should trace allocator ownership/free
  history for the aliased external buffer.
* Transformed legacy mesh producers now localize points explicitly in
  `bsg_ged_draw_source.c` before calling the Obol database-source publisher.
  Keep that boundary visible until those producers can generate source-local
  geometry without legacy transformed intermediates.
* Legacy `draw.c` and lower-level display-stream compatibility helpers still
  have retained, file/plot, or DM-facing concepts.  View-object deletion now
  routes through a neutral
  `ged_draw_view_context_object_remove` facade that centralizes feature,
  overlay, source-group, and transient shape-ref cleanup.  View-object draw
  visibility and update/realize now route through neutral object-level
  facades that centralize feature-vs-shape-ref dispatch.  The public GED view
  object command surface has moved off `view obj`, `view objs`, and
  `view gobjs`; the new Obol-oriented split is `view object` for lifecycle,
  info, visibility, style, and realization, `view annotation` for line, arrow,
  label, and axes objects, `view polygon` for polygon editing, and `view db`
  for database display/edit-proxy insertion.  Line annotations support
  multi-point `create`/`append`, zero-based point-range `remove`, and `clear`
  removal.  The remaining view-object work should continue consolidating
  internals behind typed object/capability APIs, not reintroduce compatibility
  aliases.  rtcheck, NIRT/qray, check overlap,
  BREP/NMG line diagnostics, GQA line/HUD diagnostics, `vdraw send`, preview
  eye-path output, and the simple line-set command visualizations from
  `gdiff`, `lint`, `joint`, and BOT helper commands are on the command-scene
  path.  Command-scene owners now
  carry an optional generation fence, and rtcheck supplies a run generation so stale
  subprocess output cannot replace a newer result.  The command-scene feature
  store now has generic key/value result metadata, and migrated rtcheck,
  NIRT/qray, check, GQA, BREP, NMG, overlay-command, vdraw command
  diagnostics, and simple line-set command results populate baseline
  owner/kind/format/count metadata for their real result records.  NIRT/qray
  stale result cleanup now uses the centralized command-scene prefix cleanup
  helper, with direct view-prefix removal retained only as unowned-view
  fallback inside the helper.  The feature
  store now preserves primitive
  selected/highlighted state for command-result VLISTs and can resolve
  line-layer child feature picks to the
  parent result primitive namespace.  qtcad Obol pick records and selection
  filters now route real Coin pick details through that resolver for command
  result line layers.  The remaining command visualization work is richer
  command-specific schemas using feature and per-primitive metadata,
  detail-panel consumption, richer interaction/manipulator contracts for
  custom Coin providers, persistent/custom-provider callback lifetime policy,
  and applying generation tokens to any new asynchronous result producers.
  Diagnostic callbacks remain as fallback for non-command-scene consumers and
  qtcad sync tests, not as the primary owned-scene path for migrated
  diagnostics.
  Treat these feature families as the next migration target through
  command-owned interactive Obol features, not as anonymous overlays; do not
  grow new correctness behavior behind `_ged_drawtrees` or BSG node identity.
* Evaluated wire is no longer transaction-retained and no longer implemented
  inside GED.  Mode-specific Obol refs preserve the correct evaluated source
  instance when shape-ref realization is used, and the current libbrlobol
  provider API is the boundary to keep.  The provider now uses an
  evaluator-owned librt `struct resource`, so the remaining cleanup is
  implementation modernization inside libbrlobol: replace or refactor the old
  Big-E internals and, if parallelized, use per-worker `struct resource` state
  with deterministic result merging.  `concurrentqueue.h` is available if a
  work queue is useful.
* Current shared-geometry reuse is bounded to realization-action scope, seeded
  by already-current realized sources in the traversed scene.  Persistent
  cross-refresh reuse still needs deliberate cache keys, reference ownership,
  invalidation, and edit/update behavior before implementation.
* PCA/canonical mesh matching from libbg may be useful later for detecting
  duplicate transformed-only meshes, but it should wait until legacy/BSG draw
  drivers are retired from Obol-owned paths and should not be part of the core
  correctness contract.

Next implementation steps
-------------------------

1. Finish hardening typed Obol view-object management behind the new command
   surface.  The old `view obj`, `view objs`, and `view gobjs` public syntax
   is retired rather than aliased.  Continue moving implementation internals
   toward one resolver/registry that returns a typed object handle with class,
   scope, owner, database target, draw mode, lifecycle, and capability
   metadata, then route style, info, selection, and pick metadata through
   object-level APIs.  Preserve shared-scene behavior by default unless a
   command explicitly requests view-local scope.
2. Convert lower-level display-stream compatibility helpers where they are
   still used as primary command behavior, and legacy direct draw/preview
   callers to command-owned interactive Obol feature providers.  Preview
   eye-path output now uses the shared command-scene line-set helper, and
   NIRT/qray stale result cleanup is centralized under the command-scene prefix
   cleanup helper.  Continue rtcheck, NIRT/qray, check overlap, BREP/NMG, and
   GQA command-scene diagnostics from line-layer/HUD publication to richer
   command-specific metadata schemas, detail-panel consumption, and richer
   Coin interaction.  qtcad point/box/ray picks now route command-result
   line-layer child hits through the primitive resolver; keep extending that
   resolved pick data into command-specific UI panels and tools.
3. Extend the GED/libbrlobol command-scene context beyond initial typed
   line/HUD/custom-node publication and primitive metadata storage:
   pick-result integration, detail-panel consumption, and richer custom Coin
   scene-object provider contracts.  Typed neutral records should cover common
   cases; custom providers should support complex command/plugin-authored
   manipulators and behaviors while preserving Obol ownership, structured
   metadata, primitive state, transaction callbacks, generation fencing for
   asynchronous results, teardown, selection, and database-edit invalidation
   semantics.
4. Continue modernizing the libbrlobol evaluated-wire provider internals behind
   the new `brlobol_evaluated_wire_*` API.  Preserve the direct, mode-aware
   Obol source publication contract, remove remaining old Big-E assumptions
   where possible, and consider internal parallel region/job evaluation with
   per-worker librt resources and deterministic output merging.
5. Extend the new multi-instance transform coverage into draw-mode state,
   selection, edit, and explicit database-change behavior for direct providers
   without retained mirror state.  The current gate already covers wire and
   shaded repeated-instance geometry reuse, logical visibility/highlight,
   direct source-key stale/redraw, logical redraw fallback avoidance, bounds,
   autoview, and erase cleanup.
6. Add LoD variants of the repeated-instance regression so mesh LoD staging
   remains view-aware while selection/edit identity stays scene-stable.
7. Define the persistent geometry cache strategy: key material, database
   revision inputs, usage counts, invalidation, and edit/update behavior.
8. Revisit PCA/canonical mesh matching only after the legacy-driver removal and
   deterministic cache policy are stable; treat it as optional duplicate
   detection, not a dependency of core scene correctness.
