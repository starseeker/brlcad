BRL-CAD Obol Legacy Dependency Inventory
========================================

Scope
-----

This note is the transitional allowlist for BSG, DM, and dm_plugins
dependencies while qged/qtcad, GED/TclCAD/mged, and lower-level utility
targets move to Obol.  It records direct build rows and phase ownership.  The
Obol pivot guard checks the guarded rows below against src/source_dirs.cmake;
when a dependency is removed or added, update this note in the same change.

Guarded Direct Dependency Rows
------------------------------

These rows are intentionally exact.  They document the current direct target
dependency graph relevant to the Obol pivot:

* libbrlobol: libwdb;librt;libimgstream;libbg;libbu
* libnmg: libbg;libbn;libbu
* libbrep: libbg;libbu
* libanalyze: librt;libbg;libbn;libbu
* libimgstream: libicv;libbn;libbu
* libdm: libbsg;librt;libicv;libbn;libpkg;libbu
* libged: libicv;libanalyze;libwdb;liboptical;libdm;libbsg;libbu
* libqtcad: libbrlobol;libged;libdm;libbsg;libbg;libbn;libbu
* libtclcad: libged;libdm;libbsg;libbn;libbu
* qged: libqtcad
* mged: libtclcad

The qged executable also has a direct CMake build dependency on dm_plugins:

* qged plugin dependency: dm_plugins

The qtcad Obol workflow test targets are guarded separately.  They may link
through transitional qtcad/GED libraries while the application is migrating,
but they must not directly link libdm, libbsg, or dm_plugins:

* qtcad Obol tests: no direct libdm/libbsg/dm_plugins link

Selected converter and simulation build targets that do not use BSG APIs are
guarded separately so stale build-only direct libbsg links do not return:

* selected converter and simulate build targets: no direct libbsg link

The QgSW swrast integration test exercises the retained qtcad/GED/libdm bridge
path, but it must not directly link libbsg when it uses only qtcad legacy-view
helpers:

* qtcad QgSW swrast integration test: no direct libbsg link

The GED selection semantics test exercises transitional RT pick/selection
adapters, but it must not directly link libbsg while its source avoids BSG
pick/selection headers and calls:

* ged selection semantics test: no direct libbsg link

The GED snap semantics test exercises transitional RT snap adapters, but it
must not directly link libbsg while its source avoids direct BSG snap/grid
headers and calls.  Generated link lines may still include libbsg through
retained librt transitives until the lower-level owner migrates:

* ged snap semantics test: no direct libbsg link

The GED measure semantics test exercises transitional RT measure adapters, but
it must not directly link libbsg while its source avoids direct BSG measure
headers and calls.  Generated link lines may still include libbsg through
retained librt transitives until the lower-level owner migrates:

* ged measure semantics test: no direct libbsg link

The GED independent-view test exercises transitional RT/GED independent-scope
adapters, but it must not directly link libbsg while its source avoids direct
BSG utility calls for independent-scope inspection.  Generated link lines may
still include libbsg through retained libged/librt transitives until those
owner libraries migrate:

* ged independent-view test: no direct libbsg link

The GED mged shaded-mode test exercises retained GED/DM shaded rendering and
swrast readback behavior, but it must not directly link libbsg while its
source avoids direct BSG defines/API use and routes view setup through
`rt/view_legacy_bsg.h`.  Generated link lines may still include libbsg through
retained libged/libdm transitives until those owner libraries migrate:

* ged mged shaded-mode test: no direct libbsg link

The GED quad-stability and rtwizard tests exercise retained GED/DM
BSG-backed scene behavior, but they must not directly link libbsg while their
source routes scene-anchor creation, attached checks, and shared-scene checks
through `rt/view_legacy_bsg.h`.  Generated link lines may still include
libbsg through retained libged/libdm/librt transitives until those owner
libraries migrate:

* ged quad-stability test: no direct libbsg link
* ged rtwizard test: no direct libbsg link

The GED view-command test still directly links libbsg for retained
backend-scene render/export coverage, but its snap, measure, and polygon
semantic utility checks are guarded at the source boundary.  Those checks must
use `rt/view_legacy_bsg.h` wrappers rather than direct BSG utility headers,
records, calls, or the broad `bsg/util.h` include until a larger
backend-neutral render/export surface can replace the remaining structural BSG
coverage:

* ged view-command semantic utility checks: no direct BSG utility API use

The GED mged BSG draw test still directly links libbsg for retained render
request/batch coverage, but its scene attachment and center-dot state checks
are guarded at the source boundary.  Those checks must use
`rt/view_legacy_bsg.h` wrappers and neutral `rt_view_other_state` records
rather than direct BSG utility/view-state headers, records, or calls until the
remaining render checks can move behind a backend-neutral surface:

* ged mged BSG utility view-state checks: no direct BSG utility/view-state API use

Guard Expansion Rules
---------------------

1. New Obol-canonical files must be added to brlobol_pivot_guard.cmake rather
   than relying on this inventory.
2. New qtcad Obol workflow tests must stay direct-libdm/libbsg/dm_plugins-free.
3. Any new direct libbsg, libdm, or dm_plugins dependency must add a phase owner
   and a removal condition here.
4. Removing a legacy dependency should shrink this inventory and the guard's
   exact dependency-row allowlist in the same patch.
5. Temporary adapters such as qtcad draw-transaction sync are allowed only while
   they bridge an existing legacy API to an Obol-owned state path.
