BRL-CAD Obol Realization Coverage Matrix
=========================================

Scope
-----

This table tracks the production database object coverage expected from the
Obol realization path.  The current libbrlobol path realizes BRL-CAD .g
hierarchies through SoBRLDatabaseSource and SoBRLSceneController, preserving
database path identity on Obol shape nodes.  Wire output is converted from
rt_obj_plot bg/rt_vlist data into SoBRLVListShape only at the realization
boundary.  Shaded output is represented by SoBRLMeshShape using direct mesh
importers where available and rt_obj_tess fallback otherwise.

The required hierarchy smoke models are:

* share/db/pinewood.g, root object pinewood
* share/db/havoc.g, root object havoc

The larger maturity candidate is share/db/faa/Generic_Twin.g.  It is the
largest in-tree example, includes valid and invalid BoTs, and mixes in
implicit solids.  It should become the final qtcad/Obol large-model gate once
staged LoD realization and large-BoT diagnostics are mature enough for the
extra runtime.

The focused CTest gates are libbrlobol_prototype and
test_qtcad_obol_draw_sync.  libbrlobol_prototype requires both staged models
to load through Obol hierarchy realization, gates shaded mesh export and
measure traversal on pinewood.g, and keeps havoc.g as the larger required
wire hierarchy traversal.  This avoids duplicating havoc.g's expensive shaded
realization in the prototype gate while retaining required shaded hierarchy
coverage.  Its wire hierarchy measure uses summary counts for coverage, and
default connected-angle measurement is covered by a sparse endpoint-bucket
regression instead of relying on a quadratic all-pairs wire scan.  Vlist
measure and snap traversal must stay linear over SoBRLVListShape command
arrays; indexed segment lookup rescans the command stream and made the
prototype hierarchy measure path scale poorly on pinewood.g and havoc.g.
Staged RT mesh LoD payload copying also owns optional active normals as a
provider-neutral triangle-corner array, so normal payloads do not leak the
underlying RT/BSG cache container into libbrlobol consumers.  The RT mesh-LoD
provider gate seeds a normal-bearing cached mesh and verifies that the copied
Obol payload receives the normals through the RT facade.  Generated mesh LoD
stores use the same triangle-corner normal contract, and rt_view_info verifies
those normals round-trip through active RT LoD data.
test_qtcad_obol_draw_sync
also verifies the real GED draw-observer path used by qged/qtcad: a
ged_exec_draw command updates a QgView Obol database source and the resulting
scene is visible through qtcad capture without requiring the test to construct
synthetic transactions by hand.  The same gate runs a real ged_exec_autoview,
pushes the resulting qtcad view refresh through the canvas, and verifies the
Obol camera/readback path follows the updated view.
libbrlobol_prototype also rebuilds a view controller over an existing realized
Obol scene, verifies that source and draw-intent state remain authoritative on
the scene nodes, and exercises partial refresh through the rebuilt controller.
test_qtcad_obol_real_models gates qtcad Obol draw/readback workflows against
pinewood.g, havoc.g, and the larger mixed-primitive m35.g sample.  The m35.g
case also exercises qtcad Obol pick, snap, and measurement overlay helpers on
real model geometry.  Generic_Twin.g is tracked as the larger FAA maturity
candidate rather than a default CTest case until the large-model path can
handle mixed valid/invalid BoTs, implicit solids, and staged LoD behavior
without making routine developer tests too expensive.  Developers can run the
current opt-in draw/readback maturity check by setting
BRLOBOL_QTCAD_GENERIC_TWIN=1 for test_qtcad_obol_real_models; the default
test remains limited to the smaller routine models.
test_qtcad_obol_controller verifies the qtcad GL/SW visible-content capture
path uses Obol readback for migrated scene content, consumes the Obol render
request, and leaves the legacy display manager unopened for that capture case.
It also verifies SW visible paint follows the same direct Obol readback path.
When an offscreen Qt GL context is available, the same controller gate calls
QgGL paint with its GL context current and verifies migrated Obol content
drains the paint-time Obol render request through BRLObolViewController
without opening the legacy display manager.
test_qtcad_obol_real_models applies the capture request-drain and legacy-DM
bypass checks to the required real `.g` model workflow cases.
The same controller gate verifies default qtcad key, wheel, and drag
navigation can update the Obol camera and request an Obol render before
legacy DM initialization.
test_qtcad_obol_pick verifies point, rectangle, and ray selection workflows
prefer Obol pick identity and leave the legacy display manager unopened when
selecting migrated content.  The qtcad selection filter API exposes the
resulting normalized paths directly for qged consumption instead of requiring
callers to inspect BSG pick or interaction records, and the qtcad pick record
preserves source-backed mesh face, vertex, nearest edge, and edit-intent
identity for exact picks through the shared BRLObolViewController
source-backed mesh exact-ray helper.  The same gate verifies qtcad explicit
ray picks reuse the controller-owned librt exact-pick cache through the shared
BRLObolViewController RT exact-ray helper, merge display/RT hits in
ray-distance order, and that QgSelectRayFilter tries the Obol ray helper
before its legacy BSG/RT fallback even when the filter's legacy `dbip` field
is unset.
test_qtcad_obol_measure and test_qtcad_obol_snap verify migrated-content
measurement overlays and database snap refinement run through Obol without
opening the legacy display manager.  The snap gate also verifies source-backed
exact snaps preserve face, vertex, and edge-nearest identity through the shared
BRLObolViewController source-backed snap helper.  The measurement gate also
verifies source-backed exact measurement preserves nearest face, vertex, edge,
and edit-intent identity through the shared controller measurement helper, and
asserts that the qtcad measurement filter publishes its guide/final segment as
Obol line overlays, with no BSG measurement feature, cached BSG measure-result
path, or BSG-pick/raytrace fallback for 3D measurement.  qtcad exact export
records likewise preserve source-backed edit-intent metadata through the shared
controller export helper, and qtcad exact export/measure/snap/pick tests verify
pending submitted source-detail work is surfaced separately from immediate
misses.  The pick gate also verifies the qtcad point, rectangle, and ray
selection filters skip legacy fallback selection while source-backed exact
pick detail is pending.
The LoD service gate verifies controller
source-backed exact reload submission resolves the matching database source in
multi-source views and consumes the corresponding database-scoped result.
The LoD service gate verifies active request-key tracking rejects duplicate
queued/running source reloads while allowing resubmission after completion.
It also verifies partially ready multi-request exact export and mesh-pick
helpers consume the ready source-backed result and submit the still-missing
source-backed request in the same pass.
It also verifies direct BoT source-backed snap/pick subset payloads are
budgeted after source-local scoped face reduction, that scoped misses do not
expand to whole-object payloads, and that mixed-kind, duplicate, malformed,
or non-source-local query metadata stays whole-object while measure query
hints remain whole-object until a bounded measurement provider exists.  The
same LoD gate also verifies source-backed request conversion replaces stale template
`source_query.*` params with current request metadata, and that non-forced
mesh LoD submissions use the same view-policy active level as a direct
`rt_mesh_lod_load_view` selection for the submitted `rt_view_info` while
rejecting duplicate queued/running view-policy requests through LoD service
active-request tracking.

Preserved Identity
------------------

Every realized drawable Obol node must preserve:

* full database path, including combination instances
* source revision and realized source/input/view revisions
* primitive name and type identity at shape level
* inherited region/material identity currently carried by db_tree_state:
  region id, air code, GIFT material id, LOS, material color, and shader
* face or line-segment primitive index for pick/export/snap/measure
* visibility, selectability, selection, highlight, ghost, hidden-line, edit
  emphasis, LoD policy, and color override fields

Standalone material-object identity, first mesh edge/vertex action identity,
and typed edit-preview intent identity across pick/snap/measure/export are now
covered.  SoBRLEditPreview can publish explicit edit-intent id/role metadata
separate from preview-node identity, while preserving the old preview-id
fallback.  Broader live edit-tool lifecycle/state semantics and stable
face/edge/vertex IDs for tessellated curved primitives are still migration
work.

Draw-Test Realization Findings
------------------------------

After separating polygon, text, and axes raster tolerances, the draw-mode
realization failures in `ged_test_drawing_basic` have been brought onto
first-class Obol/libbrlobol paths:

* v022, `draw -m3 all.g`: passes through direct evaluated-wire publication.
  GED draw mode 3 is represented as a mode-specific Obol database source
  (`REPRESENTATION_EVAL_WIRE`) and realizes via `draw_m3`/bigE output instead
  of falling back to ordinary primitive wireframe.
* v023, `draw -m4 all.bot`: passes through hidden-line mesh rendering.
  GED draw mode 4 is represented as `REPRESENTATION_HIDDEN_LINE`; libbrlobol
  realizes the database source as mesh and renders an invisible depth-fill pass
  followed by a polygon-offset line overlay so coplanar mesh edges survive
  without exposing occluded back edges.
* v024, `draw -m5 all.g`: passes through sampled-face-set publication.
  GED draw mode 5 is represented as `REPRESENTATION_EVAL_POINTS`; the Obol
  source receives the sampled indexed-face-set mesh and uses the published
  geometry bounds for autoview.  External mesh publication replaces any
  generic database-realization primary children so stale unevaluated mesh
  geometry cannot leak into the sampled/evaluated source.
* v026, `draw -m3 scene.g` on rook.g: passes after evaluated-wire external
  publication updates source bounds from the realized geometry and replaces
  generic primary VLIST children.  This avoids autoview framing against stale
  pre-evaluation database bounds and prevents Boolean tool-solid wireframes
  from rendering beside the evaluated result.

Mode 1 shaded BoT/polysolid, mode 2 unevaluated shaded, mixed
shaded/wireframe cases v020, v021, and v025, and the mode-specific v022-v024
and v026 cases now pass the current OSMesa-backed Obol image gate.  Future
changes should preserve the representation-mode split rather than collapsing
non-shaded database sources back to generic wireframe realization.
The evaluated-mode regression case to guard against is applying generic
display settings after creating a mode-specific source: the underlying
libbrlobol draw mode is still wireframe for evaluated wire and point modes,
but the exact `REPRESENTATION_EVAL_WIRE` or `REPRESENTATION_EVAL_POINTS`
state must remain authoritative.  GED display mutations that know an exact
GED draw mode must update the source representation explicitly, and
libbrlobol draw-mode-only mutations must not demote existing non-simple
representations.  Summary reads also need to use the selected database source
instance, not the first source sharing the same logical database path, because
wire/shaded/evaluated mode sources can coexist during a transaction.
External GED primary geometry publication has an additional hardening contract:
line, annotation, point, and indexed-face publishers clear existing primary
realized children on the target `SoBRLDatabaseSource` before installing the new
external payload, while preserving auxiliary VLIST/source children.  This is
covered by `SoBRLDatabaseSource::clearRealizedGeometry` in libbrlobol and by the
current `ged_test_draw` Obol image gate.

Near-Term Gates
---------------

1. Preserve the `GED_DRAW_MODE_EVAL_WIRE`, `GED_DRAW_MODE_HIDDEN_LINE`, and
   `GED_DRAW_MODE_EVAL_POINTS` representation paths in qged/qtcad integration
   work, including source bounds updates from external geometry publication.
2. Promote BREP and BSpline/NURB shaded rows from diagnostics to stable native
   or tessellated representation when the underlying converters are reliable.
3. Promote diagnostic/fallback rows such as BREP, legacy HF, annotation, and
   point-clouds to native Obol representations where that adds stable user
   value.
4. Complete broader live edit-tool lifecycle/state semantics and extend stable
   edge/vertex identity beyond the current indexed-mesh action coverage where
   native or tessellated curved nodes need to report those sub-entities.
5. Promote the controlled Generic_Twin.g opt-in workflow gate to a default
   gate after large-BoT staged LoD realization can publish diagnostics for
   invalid BoTs, preserve mixed implicit/mesh identity, and avoid blocking
   routine qtcad developer tests.
