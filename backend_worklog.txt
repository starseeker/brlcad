Obol/libbrlobol Backend Worklog
===============================

Purpose
-------

This file is the append/update log for the Obol/libbrlobol migration.  Keep
`backend_capabilities.txt` focused on current status and remaining work.  Use
this file for detailed completed-work notes, bridge retirements, test evidence,
and guard updates.


Update Rules
------------

* Keep entries structured and easy to append automatically.
* Add new entries under "Log Entries" using the template at the end of this
  file.
* Use UTC dates in `YYYY-MM-DD` form.
* Keep `id` stable, lowercase, and hyphenated.
* Keep `capability` as one of:
  `scene-source`, `feature-polygon`, `render-export`, `display-stream`,
  `qtcad-ownership`, `docs`, or `guard`.
* Prefer concise bullets over long prose.
* Put detailed file/test evidence in the entry where the work happened.
* Update `backend_capabilities.txt` only when current status or remaining work
  changes.


Current Baseline Snapshot
-------------------------

date: 2026-06-26
status: active
active_capability: scene-source

Capability 1 baseline:

* Obol/qtcad has staged scene, group, source, placement, display-state,
  revision, summary, and draw-sync coverage.
* GED public records and transaction paths increasingly use neutral summaries,
  source-state records, draw-state summaries, source snapshots, child
  iterators, and facade operations instead of direct BSG field access.
* The BSG-backed source adapter still owns the transitional retained scene
  implementation, geometry publication, source realization, LoD realization,
  child/source attachment, and remaining scene-ref mutation.
* `src/libged/bsg_ged_draw_private.h` still exposes transitional
  `bsg_scene_ref` handles while live GED internals need retained scene tokens.
* `misc/CMake/brlobol_pivot_guard.cmake` is the authoritative staged-boundary
  guard for this migration phase.

Capability 2 baseline:

* Feature and polygon behavior still needs a full Obol/libbrlobol-backed store
  behind neutral `rt_view_*` and `ged_draw_view_*` APIs.
* `src/librt/view_legacy_bsg.c` and `src/libged/bsg_ged_draw_view.c` remain
  transition points for feature/polygon behavior.

Capability 3 baseline:

* Obol export action has staged object-record support with stable ordering,
  identity fields, filters, geometry details, and full-detail request metadata.
* GED view-record wrappers route through a neutral backend-adapter producer.
* The temporary BSG export producer remains in the BSG-backed source adapter
  pending Obol query hookup.

Capability 4 baseline:

* The permanent Obol/libbrlobol display draw stream still needs implementation
  sufficient to feed qtcad directly and temporarily validate libdm consumers.
* `src/libdm/view.c` still must lose direct BSG render API dependency before
  the libdm/libbsg dependency row can retire.

Capability 5 baseline:

* qtcad Obol sync/export/pick/snap/measure/window-host work is staged, but
  normal qtcad/qged visible rendering is not yet fully Obol/libbrlobol-owned.
* `qged` direct `dm_plugins` dependency must remain until qtcad/Obol owns the
  normal display backend path.
