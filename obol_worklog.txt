BRL-CAD Obol Worklog
====================

Last compressed: 2026-07-04

Purpose
-------

This file is a compact historical log for the Obol migration.  Turn-by-turn
detail was intentionally collapsed because the root text files had become hard
to use as handoff documents.  Use git history for exact diffs and `doc/notes/`
for durable design contracts.

2026-07-04: Documentation reset
-------------------------------

The root handoff files were shortened to reflect the current migration state:
finish retiring old-style non-Obol drawing drivers first, while defining only
the minimal richer-behavior contracts needed to keep command-result and custom
Coin work on a stable path.  `obol_legacy_dependency_inventory.txt` was reduced
to guard-visible dependency rows, active owners, removal conditions, and
current blockers instead of historical prose.

2026-07-04: View-mechanics boundary pivot
-----------------------------------------

The BSG-removal plan was redirected away from growing native generic view
mechanics inside librt.  Generic non-scene view state, camera matrices,
autoview-bounds math, screen/model transforms, input/knob state, refresh and
settings values, and view-set bookkeeping should live in a new clean libbv.
The old mainline libbv in `/home/starseeker/brlcad_vanilla` is reference
material only; the new libbv uses the short `bv_*` prefix but is not required
to preserve the historical bview-era data model or full old API surface.
Scene objects, display lists, Tcl/display manager state, polygon stores,
snap/selection, LoD caches, and retained scene graph behavior are explicitly
outside the new libbv boundary.

2026-07-04: Initial clean libbv scaffold
----------------------------------------

The new libbv scaffold now builds as `libbv` with public `bv.h` and
`bv/view.h` headers, short `bv_*` API names, CMake/source-dir/pkg-config
wiring, and a `bv_basic` regression test.  The initial implementation covers
view state initialization/copying, camera matrices, autoview bounds,
screen/model transforms, plane extraction, mouse/view adjustment, knob state
processing, and view-set bookkeeping.  It deliberately does not carry forward
old bview scene-object/display-list/Tcl/display-manager responsibilities.

2026-07-04: Evaluated-wire default and havoc diagnosis
------------------------------------------------------

`rt_eval_wireframe` now defaults to the symbolic boolweave-backed evaluator.
The historical Big-E evaluator remains available with
`RT_EVAL_WIREFRAME_F_BIGE` for comparison and fallback.  The old
`BRLOBOL_EVAL_WIRE_BOOLWEAVE_USE` opt-in is no longer the method selector;
profiling and diagnostic toggles remain opt-in.  The GED basic drawing
evaluated-wire rook baseline (`v026_ctrl.png`) was updated to the boolweave
output.

`src/libbg/RTree.h` gained a vector-backed tolerant `Overlaps` overload, and
the librt evaluated-wire candidate stage uses it to enumerate overlapping NMG
face pairs.  The implementation profile now reports face-index, face-pair
collection, face-pair evaluation, and boolweave candidate-evaluation timings;
`RT_EVAL_WIREFRAME_PROFILE_PROGRESS=1` emits leaf-pair progress records for
large-case diagnosis.

The current debug-build profile for `Generic_Twin.g all` with boolweave is
practical: about 14s wall time with profiling enabled and about 585k output
segments.  `havoc.g havoc` remains impractical for this candidate model.  The
bounded run completed `r.nos1`, then spent the remaining time in the next
nose-skin region processing thousands of thin-shell leaf-pair overlaps; RTree
collection was cheap, while Eplot-style face geometry evaluation dominated.
Treat havoc as a pathological thin-surface stress case for the current
evaluated-wire candidate model, not as evidence that RTree traversal failed.
The focused post-baseline gate passed:
`ctest --test-dir build -R '^(ged_test_drawing_basic|ged_test_ged_draw_scene_core)$' --timeout 240 --output-on-failure`.

2026-07-04: Evaluated-wire internals hardened
---------------------------------------------

The evaluated-wire core moved from libbrlobol to librt as
`rt_eval_wireframe(vhead, vlfree, dbip, path, tol, ttol, opts)`.  The API uses
full path/name style input, emits RT vlist line commands, and deliberately does
not add a `dp` wrapper or a new segment container.  The options flags can force
the historical `RT_EVAL_WIREFRAME_F_BIGE` method or explicitly select the
symbolic `RT_EVAL_WIREFRAME_F_BOOLWEAVE` default without losing A/B comparison
or fallback.  libbrlobol now keeps only a
compatibility adapter that converts the librt vlist to the existing
source-local BG line-command arrays used by Obol/GED publication.

The libbrlobol evaluated-wire implementation now owns its call context with
C++ cleanup, local librt resource/vlist state, vector-backed typed line records,
centralized segment allocation/free helpers, and explicit ray-data seghead
cleanup.  Region evaluation now has an ordinal result seam with optional debug
region names and deterministic aggregation order.

The first dynamic per-region worker version was left gated off because it
changed the evaluated-wire image baseline.  Follow-up diagnostics forced two
worker contexts, serialized full region evaluation, and then evaluated regions
serially while alternating contexts.  Alternating contexts in region order
passed, while dynamic worker execution still failed, so the immediate hazard is
out-of-order/order-sensitive region evaluation rather than second `rt_i`
contexts being intrinsically different.  The next parallelization step should
follow bot exterior/libanalyze structure at a lower level: preserve region
order, use per-thread librt resources, feed isolated queued ray/classification
jobs, and merge outputs deterministically.

An opt-in candidate diagnostic now compares Big-E evaluated segments with
librt boolweave partitions built from the real prepared soltabs on the active
region.  `BRLOBOL_EVAL_WIRE_BOOLWEAVE_DIAG=1` enables the probe and
`BRLOBOL_EVAL_WIRE_BOOLWEAVE_DIAG_LIMIT` caps detailed output while summary
counters still cover the full run.  The probe now injects known source
surface intervals rather than asking librt to rediscover them with grazing
shots.  With that hybrid input, the simple evaluated-wire case matches Big-E
exactly: 1,568/1,568 candidates.  The rook case remains divergent:
5,900/13,301 candidates matched in the current run, with differences
concentrated in the subtraction-heavy CSG tree and surface candidates where
volume partitions alone cannot prove boundary status.

Timing from the same diagnostic is encouraging but not final.  The rook run
reported Big-E candidate work at about 0.128s and the unoptimized boolweave
probe at about 0.212s, but the actual boolweave shot/finalization sub-total
was about 0.074s.  The extra cost is mostly diagnostic overhead such as
per-candidate soltab collection and region-table save/restore, so an optimized
region-local implementation may be competitive or faster.  The best long-term
direction is not a globally scaled/bumped in-memory database; that changes CSG
semantics.  Use original candidate geometry, inject known source-boundary
facts, use boolweave for interval/CSG partitioning, and add local two-sided
boundary classification to decide whether candidate curve intervals are true
evaluated CSG boundaries.

2026-07-04: Preview tree redraw moved to transactions
-----------------------------------------------------

The `preview` command no longer redraws script-requested tree tops by calling
`_ged_drawtrees` directly.  Its frame-end redraw now builds a GED draw
transaction with explicit appearance settings, using normal wire mode by
default and evaluated-wire mode for `preview -v`.

Draw-scene core coverage now runs a semicolon-terminated RT preview script and
asserts that both preview modes publish database draw state through the Obol
draw transaction path.  The pivot guard rejects direct `_ged_drawtrees` calls in
`src/libged/draw/preview.cpp`.

2026-07-04: View object command surface replaced
------------------------------------------------

The public `view obj`, `view objs`, and `view gobjs` spellings were retired
instead of kept as aliases.  The replacement surface is split by responsibility:
`view object` handles lifecycle, info, visibility, style, and realization;
`view annotation` handles line, arrow, label, and axes objects; `view polygon`
handles polygon editing; and `view db` handles database display/edit-proxy
insertion.

Line annotations accept one or more point triples in `create` and `append`.
`view annotation line remove` removes a zero-based point range, and
`view annotation line clear` removes the line feature.

View-object lifecycle, visibility, style, and realization now route through
object-level GED draw facades.  Feature, database shape-ref, and Obol overlay
group style dispatch lives in the draw bridge, including color support for
`view db add --as` aliases and capability rejection for unsupported arrow
settings.

Line, label, and axes annotation command edits now route through
annotation-level GED draw facades.  The command files no longer rebuild those
objects with direct feature-store calls, so line point removal preserves
annotation overlay lifecycle metadata while retained fallback remains isolated
in the draw-view bridge.

Legacy TclCAD data-overlay syntax remains available for old callers, but
`data_lines` / `sdata_lines`, `data_arrows` / `sdata_arrows`,
`data_axes` / `sdata_axes`, `data_labels` / `sdata_labels`, and
`data_polygons` / `sdata_polygons` now route draw/style/points/label,
polygon-outline, movement, scaling, and pick/readback operations through typed
GED data-overlay facades.  The command parsers no longer call feature
visibility, style, point, label, arrow, axes, or polygon replacement helpers
directly.

2026-07-04: Multi-instance transform reuse hardened
---------------------------------------------------

libbrlobol database realization now carries an action-scoped shared-geometry
cache.  The action seeds from already-current realized shared geometry, then
realizes stale sources.  Repeated comb/solid instances can share source-local
geometry while retaining per-instance transforms and identity.

`ged_test_obol_draw_sync` covers repeated transformed instances, shared local
geometry reuse, source/subtree bounds, autoview on the transformed envelope,
visibility/highlight transactions, direct stale/redraw reuse from current
siblings, shaded shared mesh reuse, and erase cleanup.

2026-07-04: Evaluated-wire boundary moved to libbrlobol
-------------------------------------------------------

GED evaluated-wire realization became a thin adapter.  `wireframe_eval.c`
resolves GED runtime/source state, calls the public
`brlobol_evaluated_wire_*` line-set API, and publishes through neutral GED
shape-ref or database-source facades.  The legacy Big-E implementation now
lives behind `src/libbrlobol/evaluated_wire.cpp` and no longer depends on GED
or BSG scene-ref internals.

The provider no longer mutates global `rt_uniresource`; each call owns and
cleans a librt `struct resource`.  Remaining work is libbrlobol-internal
modernization, including optional deterministic parallel evaluation with
per-worker resources.

2026-07-04: Mode-aware evaluated source refs
--------------------------------------------

Obol database-source refs now preserve representation mode when multiple
sources share a database path.  Wire, evaluated wire, hidden-line, evaluated
points, and shaded refs no longer collapse to one path-only token.
Evaluated source realization enters the direct Obol publication scope for the
ref's mode before calling the provider; retained evaluated wrappers remain
fallback only for true retained scene refs.

2026-07-04: Command-scene result model expanded
-----------------------------------------------

The GED/libbrlobol command-scene API now publishes owner-scoped shared or
view-local features with replacement/removal, generation fencing, metadata,
primitive metadata, primitive selected/highlighted state, child line-layer pick
resolution, and transaction callbacks.

Typed feature kinds include line layers, line sets, point sets, indexed face
sets, HUD labels, and custom Coin nodes.  The custom-node hook lets commands
provide an opaque Coin node through a C-safe callback interpreted only by the
C++ Obol adapter, while preserving the same owner, scope, metadata, primitive
state, generation, replacement, and removal rules as typed features.

rtcheck, NIRT/qray, check overlap, GQA diagnostics, BREP/NMG debug lines,
BREP debug indexed-face output, overlay-command uplot import, `vdraw send`,
preview eye paths, and several simple command line-set visualizations now
publish through command-scene helpers instead of anonymous direct view-line
mutation.  BREP-specific extraction stays with the BREP command; the shared
indexed-face publication helper is part of the GED command-scene bridge.

The remaining private direct-uplot feature wrappers were retired.  Draw-scene
core coverage now verifies NIRT/qray command-scene uplot publication and
cleanup, overlay-command uplot import without framebuffer/display-manager
dependency, `vdraw send` line/point/face command results, and shared
line/indexed-face helper publication in one passing core shard.

Draw-tree/navigation semantics were tightened for explicit Obol trees.  Shape
contexts are no longer assumed to be leaf nodes, shape-ref-to-context
round-trips preserve the exact Obol token and draw mode, `group_ref_of_shape`
returns the top GED draw group while nested Obol subgroups remain explicit,
missing-target erase/highlight/visibility transactions stay no-ops, and source
rename reconciliation updates top owner groups.  The full
`ged_test_ged_draw_scene_*` shard family passes sequentially.

2026-07-04: qtcad command-result picks integrated
-------------------------------------------------

qtcad Obol pick records now carry resolved feature-store identity in addition
to raw Coin detail.  Real child line-layer picks can resolve back to the parent
command-result feature and primitive namespace, with primitive metadata copied
into the pick record.

qtcad point, box, and ray selection filters separate database picks from
resolved Obol feature picks.  Resolved command-result and overlay feature picks
update Obol selected/highlighted primitive state instead of being treated as
database selection paths.

2026-07-04: Database drawing and autoview stabilized
----------------------------------------------------

Normal database draw modes moved to direct Obol providers.  Wire, shaded-BoT,
shaded, and hidden-line draws expand requested roots to leaf database-source
instances and realize those sources in libbrlobol.  Successful direct providers
no longer mirror through `_ged_drawtrees`.

The GED basic drawing test passes through Obol capture.  Autoview was retained:
`autoview2` uses the Obol database autoview bridge, and GED can read
libbrlobol scene bounds for autoview.

2026-07-04: Source-local geometry contract hardened
---------------------------------------------------

External database-source publication and direct realization now require
source-local point/index arrays.  `SoBRLDatabaseSource::drawMatrix` remains
placement metadata.  Legacy transformed producers explicitly localize points
before publishing to libbrlobol.

An ARB import alias/free-pattern failure is guarded by refetching primitive
geometry with an identity matrix and validating payload magic before plotting
or tessellation.  The guard avoids building drawable geometry from poisoned
tree-walk callback internals; the underlying librt alias still needs root-cause
diagnosis if reproduced outside Obol.

2026-07-04: libbv native RT view context started
------------------------------------------------

A clean BSG-free libbv scaffold was added for common view mechanics: view
state, matrix updates, autoview-bounds math, screen/model transforms, generic
knobs, adjustment logic, and view-set bookkeeping.

librt now has a native/libbv-backed neutral `rt_view_context` implementation
in `view_context_native.c`.  Neutral constructors create native contexts and
explicit `_bsg` constructors remain retained fallback only.  Native dispatch
covers generic view mechanics, knobs, refresh/display state records, LoD
policy, snap setting scalars, zclip/framebuffer/cleared settings, and update
callbacks.

Scene/interaction operations are intentionally not implemented in libbv:
native contexts use installed scene/feature/polygon/selection adapters when
available and otherwise return neutral empty/no-op results instead of creating
or mutating retained BSG state.  The remaining cleanup is to inventory broader
caller-facing legacy dependencies, migrate each feature to native contexts plus
Obol/libbrlobol adapters, then move neutral dispatch out of
`view_legacy_bsg.c`.

2026-07-04: libdm retained-view proxy removed
---------------------------------------------

The libdm `dm_view_context_is_retained_legacy` helper was removed.  QtGL was
using retained BSG identity as a proxy for "this pointer is not a QWidget";
that became wrong once neutral RT contexts became native/libbv-backed.  The
new public `rt_view_context_is_valid` predicate identifies any RT view context,
native or retained, while `rt_view_context_is_retained` remains BSG-only.
QtGL now rejects opaque RT view-context pointers with the neutral predicate.

The retained Tcl overlay regression was retired instead of preserved.  GED's
default active view remains native/libbv-backed, and Tcl/data overlay lifecycle
coverage now belongs in Obol/native view-command, draw-scene, and draw-sync
tests rather than in standalone retained-BSG fixtures.

2026-07-05: Shared GED Obol scene plus per-view render roots
------------------------------------------------------------

Reworked attached Obol DMs from mirrored scene owners into render endpoints on
one GED-owned shared scene.  Each attached view controller now keeps a local
scene root, and its render root is rebound by view state: shared views render
the shared GED scene plus their local root, while independent views render only
their local root.  Database draw/clear transaction sync now updates the shared
scene for shared scope and the matching view endpoint for independent scope.

View-object lookup, removal, prefix removal, clear, and style application were
hardened so local records resolve through the attached view controller and
shared records resolve through the GED scene owner.  Scoped feature/polygon
store removal APIs were added for correct shared-vs-local clears.  Local
polygon lookup was fixed for the polygon store's `L::name` keys, annotation
lines now default to the historical red style, and shared line style changes
apply to the actual shared feature controller.

`ged_test_drawing_quad` now exercises Obol attach/capture for shared drawing,
independent drawing, local view objects, shared view objects, and mixed
shared/independent clears.  The only baseline adjustment was a narrow pdiff
tolerance bump for visually equivalent Obol/Coin polygon edge rasterization.

2026-07-05: View-local LoD bindings for shared Obol scenes
----------------------------------------------------------

Hardened the shared-scene/per-view-render-root model for LoD.  Controllers now
own `BRLObolViewLodState`, expose it to Coin traversal through
`SoBRLViewLodGroup`/`SoBRLViewLodElement`, and apply controller-drained LoD
results into view-local payloads instead of mutating shared mesh
`point`/`coordIndex` fields.  Render, display-level export, measure, snap, and
pick consume the bound view payload; exact paths skip it and use preserved
source geometry or source-backed full-detail requests.

Controller LoD submission and RT pick/source helpers now discover database
sources through the composed render root, so attached views see the GED shared
scene plus their local root.  GED draw transaction fanout clears attached view
LoD state on draw/erase/clear/source-change rebuilds.  Mesh residency budgeting
now accounts for view-local LoD payloads and can evict optional shared source
arrays while preserving source metrics.

The design is documented in `doc/notes/brl_obol_view_lod.txt`.

2026-07-05: LoD update action requires explicit view state
----------------------------------------------------------

Removed the remaining view-independent active-LoD escape hatch from
`SoBRLLodUpdateAction`.  Matched results with no `BRLObolViewLodState` now

detail, picking skips the view payload and falls back to resident shared
geometry.  LoD-backed meshes without resident full-detail geometry still require
the source-backed exact pick path.
